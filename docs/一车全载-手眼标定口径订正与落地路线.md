## 1 根因：为什么「必须重标」是伪冲突

### 1.1 X 是什么（概念双轨）

- **大白话**：相机骑在手腕上，它看到的「那个点」要换算成手臂该往哪伸；X 就是这把换算尺子。
- **规范定义**：eye-in-hand 手眼标定求解 `AX = XB`（Tsai-Lenz / Park-Martin，IEEE Trans. Robotics & Automation 1989）。
  `X ∈ SE(3)` 是**相机坐标系相对末端执行器（gripper）的刚体变换**；
  `A` 是基座↔末端两次运动间的变换，`B` 是相机↔标定目标两次观测间的变换。

**不变量**：只要相机与机械臂**刚性固连在同一车架**上，车体整体平移、转向都只是把
「基座坐标系」搬到新的世界位置，**相机↔末端的相对关系 X 在刚体意义下不变**。
会变的是 `W`：基座↔世界（棋盘 / 桌面平面 / `--plane-z`）的注册。

> 佐证：`docs/项目实施方案.md` 阶段 1 原文就是「臂固连底盘、眼在手相机装末端；做手眼标定(求解 X)」，
> 说明「上车 + X」在原规划里本就是同一阶段，不是互斥项。

### 1.2 但项目的 X 不是纯刚体不变量 —— 这点必须诚实

`handeye_X.json` 是**台架单点实标**的等效变换，已经混入台架几何假设：
12 组姿态、`tilt≈41°`、桌面 `z=0`、`--plane-z`、J2 下垂 `SAG_DZ=−3.88` / `TIP_BIAS_XY=(0.10,−0.95)`、
以及出口经验系数 `_EYE_RADIAL_K=1.091`。
`MEMORY.md` §4 明确写「**X 与 k 只在单次上电、同一姿态族、同一时段有效**」；
`docs/项目硬数据速查.md` §10 也写「换姿态 / 换棋盘 / 换相机安装 / 重标 X / tilt 离开 41° ⇒ 系数全部失效，必须重测」。

⇒ 所以**不能假定台架 X 在车上仍准**。但正确处置不是「重标 X 去凑精度」——
那是 §4 明令禁止的动作；正确处置是「**封存台架 X，车上另做一次适用性验证并单独记录**」。

### 1.3 精确结论

- **失效对象**：① 世界注册 `W`；② 车架振动 / 倾斜下的等效姿态与下垂量；③ 精度口径（数字不能外推）。
- **不失效对象**：X 的刚体定义（前提：车架刚度足够，见 §3.3）。
- **「车上视觉引导是坏的」的真实前提**：不是「没重标 X」，而是「没新增位姿注册 `W` 与停稳门控」。

## 2 四层分栏（核心表）

| 层 | 台架现状 ✅（封存） | 一车全载 📋（新配置） | 是否碰 §4 禁令 | 处置 |
|---|---|---|---|---|
| ① **X 手眼矩阵** | `samples_fkfix.json` resid **1.60mm**，`s=0.7549`，`\|t\|=16.67≈L3`，`handeye_X.json` | 刚性共架 ⇒ 理论不变；车架刚度不足才会漂 | ❌ 不碰 | **不重标**；只做刚度验证（§3.3），超范围则诚实降级 |
| ② **k 径向修正** | `_EYE_RADIAL_K=1.091`，台架单点经验值 | 台架 k **不迁移**；倾斜/振动下适用性未知 | ❌ 不碰 | 车上另存/另记实测值，**绝不覆盖台架值**，也不拿它「凑」1.4cm |
| ③ **世界注册 W** | 棋盘/桌面固定，`--plane-z=0`，隐含在定位链 | 每次停稳后**重建**：车相对目标/桌面的位姿 | ❌ 不碰 | **新增模块**（§3.1），属新配置必要初始化，非「精度实验」 |

一句话：**禁令管的是「台架那条已收口的精度链」，不是「永远禁止在任何新配置下做初始化」。**
两者对象不同，所以不是冲突。

## 3 三个新增模块与可验收判据（量化）

### 3.1 车体位姿注册 `W`（真正缺的东西）

- **为什么必须做，用现有硬数据算**（📌 11-16 订正：原文引「视野窗口 y∈[26.2,28.0] 宽 1.8cm」是**错误口径**，
  已作废——那是定位值/末端位置，不是视野窗口）：台架棋盘可摆 `y=26~36cm`（距 J1，纵向有 10cm 余量），
  真正紧的是**横向：余量仅 ±6°/25mm**（见 `排障记录-手眼标定.md` 末节「J1 扫幅被视野硬限制」）
  ⇒ 车体横向定位误差需 **≤ ±1.2cm**。
  而底盘现状是开环定时「走 X cm」误差 **20~40%**（走 30 cm 差 6~12 cm），麦轮打滑让轮式里程计累计漂移无界。
  **差一个数量级** ⇒ 纯里程计根本停不进窗口，必须闭环微调。
- **做法**：`VL53L1X` ToF「走到 25 cm 停」先闭环（呼应 §6 三条白捡）＋ `RC522` 地标做绝对位置复位，
  停稳后用 ToF 读数稳定度 + 目标是否入画共同确认 `W`。
- **判据**：`look.jpg` 里棋盘完整入画且位于窗口内；否则拒绝下发任何视觉引导指令（**只拒发，不补数**）。

### 3.2 停稳门控

- 车体速度归零 → 静置（台架 `--hover` 要求 ≥3 s，车上需实测重定）→ 倾斜角门限 → 才允许解算 `/api/ik/eye`。
- **IMU 库存表没有，需新增采购**（MEMORY.md §10 已记）；在 IMU 到位前，用「ToF 连续 N 帧方差 < 阈值」做替代门控，
  并在文档里如实标注这是替代方案。
- 门控失败 ⇒ `return 2` 拒发，沿用项目既有的三条入场闸门风格（不给 `--plane-z` 强制 0.0 / 非 C 姿态拒 / 成功提示回位）。

### 3.3 结构刚度验证（**先做这个，而不是先标定**）

- 这是让 X 是否仍成立的前置条件：玻纤板 + 铜柱 + 臂举起时重心高 ⇒ 车架可能弹性扭转，
  那相机↔基座就不再是理想刚体，X 才真的漂。这是**结构问题，不是标定问题**。
- 不上电阶段（沿用 §10 阶段①）：称重（日志估 **2.3~3.0 kg**）、倾斜测试、
  **推车前后各拍一张 `look.jpg` 对比棋盘像素位置**，位移超阈值先加固支架，不谈标定。

## 4 概念双轨速查

| 概念 | 大白话 | 规范定义 |
|---|---|---|
| 手眼矩阵 X | 把「相机看到的」换算成「手臂坐标」的尺子 | `AX=XB` 中 `X ∈ SE(3)`，相机↔末端刚体变换（Tsai-Lenz / Park-Martin） |
| 世界注册 W | 车停在哪、目标在车前方多远 | 基座坐标系↔世界坐标系的外参 `W ∈ SE(3)`，每次停车重新确定 |
| 刚体 / 不变量 | 两样东西焊死在一起，怎么搬相对位置都不变 | 刚体变换群 `SE(3)` 作用不改变两点间相对位姿 |
| 里程计 | 靠数轮子转了多少圈猜走了多远 | wheel odometry，由编码器脉冲积分估计位姿；打滑⇒无界漂移（无绝对观测） |
| 重力下垂 | 臂伸出去会微微往下掉一点 | 开环稳态误差 δ2=6.5° / δ3=2.2°；末端 C 姿态 dz −3.88 cm |
| 刚度 | 支架硬不硬，推一下会不会扭 | 结构抵抗弹性变形能力 `k = F/δ`；不足则破坏刚体假设 |
