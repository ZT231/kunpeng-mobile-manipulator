# 联调验收清单（串口协议 + 视觉判据）

> 本文合并原「串口联调测试清单」与「视觉识别测试清单」，分两部分：
> **第一部分（第 0~7 节）= 下位机 UART 协议联调，✅ 现行可照跑**，57 项，全部通过即为下位机「工程化」证据；
> **第二部分（第 8~11 节）= 视觉验收判据，⚠️ 仅保留判据与方法论**——旧版 `vision_old/` 程序已在工程精简时移除，相关命令**不可照跑**，现行视觉实现见 `kunpeng/vision/`（YOLOv8n + DaBai DCW + 眼在手标定）。
> 协议版本：v1　|　帧格式 `$CMD[,ARG]*CK<CR><LF>`，CK 为 `$` 与 `*` 之间字节的 XOR。

# 第一部分　串口协议联调（✅ 可照跑）

## 0 准备（5 分钟）

| 项 | 值 |
|---|---|
| STM32 串口 | USART1，PA9=TX / PA10=RX |
| 串口助手 | 任意（XCOM / SSCOM / 串口猎人均可），115200 / 8 / N / 1，无校验 |
| 换行 | 勾选「发送新行」或帧尾手动加 `\r\n`（协议以 `\r` 或 `\n` 结尾成帧） |
| 接线 | USB 转 TTL：**TX↔RX、RX↔TX**，共地（GND 相连） |
| 上电顺序 | 先 PC 供电，再机械臂供电；舵机必须独立供电且共地 |
| 恢复手动 | 每轮测试前发出 `$MANUAL*1A` 确保进手动态 |

> **初始位（上电 / `HOME` 命令的目标姿态）**：J1~J6 = `1580 / 1900 / 2400 / 700 / 1450 / 1500` µs，
> 定义在 `Core/Inc/main.h` 的 `SERVO_Jx_INIT`，是折叠收拢的安全姿态。
> ⚠️ 它**不是**各关节 0° 的标定零位（那个在 `kunpeng/robot/arm_params.json` 的 `map` 里）。
> 本清单测前会先发 `$MANUAL*1A`，所以第 1.2 项读到的是电位器实时值，不是初始位；
> 想核对初始位，请在上电后未发任何 MOVE 前直接读 `$STATE*57`。

⚠️ 常见坑：USB 转 TTL 的 TX/RX 接反、波特率不对、没共地 → 收不到任何响应。

## 1 基本指令（8 条，逐条测）

> 预期响应里 `*xx` 表示该校验值由板子自动计算，实际收到正确值即可，不用核对具体数字。
> 但 **PING 一定要看到 `$OK,PONG*xx`**，这是链路打通的标志。

| # | 发送 | 预期响应 | 通过 |
|---|------|----------|:---:|
| 1.1 | `$PING*10` | `$OK,PONG*xx`，且板子上应无动作 | ☐ |
| 1.2 | `$STATE*57` | `$OK,S,M,<6个当前脉宽>*xx`（初始 M=手动态） | ☐ |
| 1.3 | `$HOME*0F` | `$OK*xx`，六路平滑回初始位（折叠姿态） | ☐ |
| 1.4 | `$MOVE,0,1500*25` | `$OK*xx`，J1 平滑转至约 1500µs | ☐ |
| 1.5 | `$MOVE,3,1000*23` | `$OK*xx`，J4 转至约 1000µs | ☐ |
| 1.6 | `$JOINT,1500,1500,1500,1500,1500,1500*56` | `$OK*xx`，六路同到 1500µs（只测 JOINT 批量指令；1500 **不是**初始位） | ☐ |
| 1.7 | `$STATE*57` 再发一次 | 状态变为 `C`（指令态），脉宽与上一步一致 | ☐ |
| 1.8 | `$MANUAL*1A` | `$OK*xx`，回到手动态，电位器可接管 | ☐ |

|---|------|------|---------------|:---:|
| 2.1 | 复位/急停 | `$STOP*18` | `$OK*xx`，**所有输出立即冻结**，拧电位器无效 | ☐ |

## 3 软限位（安全边界）

> 软限位表来自 `main.h` 的 `SERVO_J?_MIN/MAX`。命令脉宽先 clamp 再执行，不会越界。
> 当前值：J1 800~2300、J2 750~2150、J3 520~2500、J4 500~1850、J5 500~2500、J6 900~2000（µs）。

| # | 发送 | 预期现象 | 通过 |
|---|------|----------|:---:|
| 3.1 | `$MOVE,0,0*11` | 返回 `$OK*xx`，但 J1 停在 `SERVO_J1_MIN`（800µs），**绝不会到 0** | ☐ |
| 3.2 | `$MOVE,0,3000*22` | 返回 `$OK*xx`，但 J1 停在 `SERVO_J1_MAX`（2300µs） | ☐ |
| 3.3 | `$MOVE,3,0*12`（J4 软限位 500~1850） | J4 停在 `SERVO_J4_MIN`（=500µs），**绝不会到 0** | ☐ |
| 3.4 | 前后对比 | 读 `$STATE*57`，确认脉宽确实被夹在 `[MIN, MAX]` 区间；**重点确认 J4 上限已被夹到 1850µs**（不再是 2500）、**J6 上限已被夹到 2000µs**（不再是 2100） | ☐ |

## 6 示教回放（S2）

> 目标：验证「手动示教 → 自动回放」全流程，以及轨迹管理、异常保护。
> 背景：记录态 `R`（电位器驱动 + 每 100ms 采样六路脉宽入 RAM），回放态 `P`（每 100ms 取点复现）。
> 前提：已通过第 1 节基本指令（尤其 1.2 / 1.8 能进出手动态）。

### 6.1 功能主流程（必测）

| # | 操作 | 发送 | 预期响应/现象 | 通过 |
|---|------|------|---------------|:---:|
| 6.1.1 | 开始记录 | `$REC*54` | `$OK*xx` | ☐ |
| 6.1.2 | 确认状态 | `$STATE*57` | 状态字为 `R`，脉宽=当前实际值 | ☐ |
| 6.1.3 | 手动走位 | 拧电位器 J1~J6 走一段约 5~10 秒的动作 | 舵机平滑跟随电位器 | ☐ |
| 6.1.4 | 查询点数 | `$TNUM*02` | `$OK,<n>*xx`，n>0（约 = 演示秒数/0.1s，但≤600） | ☐ |
| 6.1.5 | 结束记录 | `$RECEND*1B` | `$OK,<n>*xx`，返回同一 n | ☐ |
| 6.1.6 | 确认回手动 | `$STATE*57` | 状态字变回 `M` | ☐ |
| 6.1.7 | 手动乱动再回 HOME | `$HOME*0F` | 舵机回初始位，制造「偏离轨迹」起点 | ☐ |
| 6.1.8 | 开始回放 | `$PLAY*04` | `$OK*xx`，状态字变 `P` | ☐ |
| 6.1.9 | 观察回放 | 不做任何操作 | 舵机从 6.1.7 的位置平滑复现 6.1.3 轨迹 | ☐ |
| 6.1.10 | 回放结束 | 自动 | 状态自动回 `M`（可用 `$STATE*57` 确认） | ☐ |

### 6.2 轨迹管理

| # | 操作 | 发送 | 预期响应/现象 | 通过 |
|---|------|------|---------------|:---:|
| 6.2.1 | 空轨迹回放 | （复位后不录直接）`$PLAY*04` | `$ERR,3`（无轨迹可播） | ☐ |
| 6.2.2 | 查询空轨迹 | `$TNUM*02` | `$OK,0*xx` | ☐ |
| 6.2.3 | 清空 | 记录 2 秒后 `$MANUAL*1A` → `$CLEAR*59` | `$OK*xx` | ☐ |
| 6.2.4 | 清空后查询 | `$TNUM*02` | `$OK,0*xx` | ☐ |
| 6.2.5 | 重复性 | 同一段动作连续录/放两次 | 两次轨迹终点脉宽差≤30µs（可用 `$STATE*57` 对比） | ☐ |

### 6.3 异常与保护（重点安全项）

| # | 操作 | 发送 | 预期响应/现象 | 通过 |
|---|------|------|---------------|:---:|
| 6.3.1 | 记录中发 MOVE | `$REC*54` 后 `$MOVE,0,1500*25` | `$OK*xx`；`$STATE*57` 显示状态变 `C`，**记录自动停止** | ☐ |
| 6.3.2 | 回放中发 STOP | `$PLAY*04` 后 `$STOP*18` | `$OK*xx`；`$STATE*57` 显示 `E`，输出冻结，**回放自动停止** | ☐ |
| 6.3.3 | 急停解后回手动 | `$RESUME*19` | `$OK*xx`，状态回 `M`，电位器接管，无残留轨迹乱动 | ☐ |
| 6.3.4 | 记录中清空 | `$REC*54` 后 `$CLEAR*59` | `$ERR,4`（记录中禁止清空） | ☐ |
| 6.3.5 | 回放中清空 | `$REC`…`$RECEND`…`$PLAY*04` 后 `$CLEAR*59` | `$ERR,4`（回放中禁止清空） | ☐ |
| 6.3.6 | 缓冲上限 | 连续记录 >60 秒 | 到达 600 点后 `$STATE*57` 自动回 `M`，`$TNUM*02`=600 | ☐ |

> 设计说明（面试点）：6.3.1/6.3.2 展示「示教模块与状态机解耦」——任何外部接管（MOVE/急停）都会让 `Teach_Tick` 自动退出，防止残留半截轨迹继续乱动；6.2.5 的重复性检验「时间轴一致回放」的稳定性。

## 7 周期遥测开关（LOG）

> 目标：验证下位机周期打印（每 3 秒一条 `STATE | PULSE ...`）可由命令开关，不再一直刷屏。
> 背景：板子上电默认**关闭**周期打印，接收区只在每次命令应答时返回数据；需要观察实时脉宽时再 `$LOG,1` 打开。

| # | 操作 | 发送 | 预期响应/现象 | 通过 |
|---|------|------|---------------|:---:|
| 7.1 | 上电初始态 | 复位后等待 >5 秒 | 接收区**无**周期 `STATE` 刷屏（默认关闭） | ☐ |
| 7.2 | 开启遥测 | `$LOG,1*59` | `$OK*xx`；约 3 秒后开始每条 `STATE 0 \| PULSE ...` | ☐ |
| 7.3 | 确认持续输出 | 等待 10 秒 | 持续每 ~3 秒刷一条，脉宽随电位器变化 | ☐ |
| 7.4 | 关闭遥测 | `$LOG,0*58` | `$OK*xx`；约 3 秒内停止刷屏 | ☐ |
| 7.5 | 关闭后确认 | 等待 >5 秒 | 接收区**不再**出现 `STATE`，仅剩命令应答 | ☐ |
| 7.6 | 命令应答不受影响 | 关闭态发 `$PING*10` | 仍正常返回 `$OK,PONG*xx` | ☐ |
| 7.7 | 参数越界 | `$LOG,2*5A` | `$ERR,3*xx`（LOG 只接受 0/1） | ☐ |
| 7.8 | 缺参数 | `$LOG*44` | `$ERR,3*xx`（缺参数） | ☐ |

> 设计说明（面试点）：7.1/7.5 验证「默认关闭、命令控制」——避免周期打印淹没命令-应答，是嵌入式串口调试的良好抽象；7.7/7.8 与第 4 节一致，确保新命令同样走严格参数校验。

## 附：帧格式速查（写代码/做上位机时用）

```
请求: $CMD[,ARG1,ARG2...]*CK<CR><LF>
  CK = 对 "CMD[,ARG...]" 全部字节做 XOR，结果转 2 位大写十六进制
响应: $OK[,...数据]*CK<CR><LF>      成功
      $ERR,<code>*CK<CR><LF>        失败
        1=帧/校验错误  2=未知命令  3=格式/参数错误  4=状态禁止  5=设备故障(FAULT)
状态码: M=手动态  C=指令态  R=示教记录  P=示教回放  E=急停  F=故障
```

上位机（OrangePi / Python）示例计算 CK：

```python
def ck(payload: str) -> str:
    v = 0
    for b in payload.encode("ascii"):
        v ^= b
    return f"{v:02X}"
```

## 10 验收判据（原 36 项浓缩为判据表）

| # | 判据 | 通过标准 | 说明 |
|---|---|---|---|
| V1 | 环境自检 | Python ≥3.10；`import cv2` 打印版本号无报错 | 用 `python` 而非 `py`（后者可能是另一个未装 cv2 的解释器） |
| V2 | 合成图识别 | 程序生成的测试图能检出 6 个目标，颜色/形状标签正确，中心坐标与图形位置一致 | 先验证算法本身，排除摄像头因素 |
| V3 | 实时识别 | 积木块入画即被画框、标中心、标角度；移动时实时跟随 | 光照过暗/过亮会直接识别不到 |
| V4 | HSV 阈值标定 | 目标在掩膜中成实心白、背景尽量黑；回填配置后误识别明显减少 | 红色色相跨 0/180 两端，需两段区间 `[0,10]+[170,180]` |
| V5 | 单应性标定（四点法） | 按左上→右上→右下→左下点四角，`--width/height` 与标定物实际尺寸一致，生成单应矩阵文件 | 顺序点错 → 坐标整体错乱；尺寸填错 → 毫米数全错 |
| V6 | 坐标换算（核心验收） | 已知位置目标实测误差 **≤5mm**；中心点≈(148,105)mm、左上≈(30,30)mm、右下≈(270,180)mm（以 A4 210×297 为标定板时） | 误差大先查四点是否点准、摄像头是否接近正俯视 |
| V7 | 边界情况 | 多目标互不干扰；遮挡一半仍稳定；换光照稳定；目标移出再移回可重新识别 | 「识别范围 ≠ 坐标准确范围」：单应只在标定区域内准确，区域外坐标属外推 |

> 设计说明（面试点）：V4 说明为什么用 HSV 而非 RGB（色相 H 对亮度更鲁棒）；V6/V7 说明「测量系统可靠性优先于调参」；ROI 是可选优化，坐标需自动加回全图偏移。

## 11 标定口径警示（最容易弄错的一条）

- 旧流程用 **A4 纸**（297×210mm）当标定板，属「验证单应算法」的教学口径。
- 现行抓取流程按**工作区实际尺寸**标定（如 250×200mm），并配合 ROI 生成。
- **两者口径不同，不可混用**：拿 A4 标出的矩阵去算工作区坐标，毫米数会系统性偏。
