**📌 ESP32-S3 核心板电源/电容核查结论（基于 `D:\PCB\EDA\Projects\ESP32-S3.xlsx` BOM）**：
- 该板 BOM 用 **U2=AMS1117-3.3**（非 RT9193），输出 1A，远超乐鑫要求的 ≥500mA；3.3V 去耦为 22µF(C2) + 多颗 10µF/100nF，符合官方"每电源引脚 10µF + 0.1µF"建议。
- 之前担心的 **"3 处电容错误（VCAP 2.2µF / 20pF C0G）"是 STM32F407 板的问题**（VCAP 为 STM32 内部稳压器专用引脚，ESP32-S3 无此引脚），**不适用于本板**。
- **RT9193 LDO 跌落风险亦不适用**（本板未用 RT9193）。
- **结论：可放心焊接，无需改板/改 BOM。** 若仍担心 Wi-Fi 发射瞬时下坠，焊接时可在模组 3V3 引脚附近并一颗 10~22µF 作保险（非必须）。

**底盘复用件（既有循迹小车）**：TT 减速马达 + 轮子 + 编码器 + 电机驱动（L298N / TB6612FNG）+ 底盘板。阶段 1/2 直接复用，必要时升级编码器精度。
**机械臂复用件（既有视觉机械臂）**：六自由度舵机机械臂本体（复用），**执行器采用 4× 25kg 数字舵机（金属齿轮，PWM 开环，工作 6~8.4V）+ 2× MG996R（PWM 开环，4.8~7.2V）**，共 6 路标准 PWM（50Hz，脉宽 0.5~2.5ms 对应 0~180°）。STM32F407 用定时器 PWM 通道下发角度；**舵机内部自带位置伺服、MCU 不能读回真实角度（开环位置控制）**。驱动器见 `Core/Src/pca9685.c`；开发期也可先用订单已购的 **PCA9685 16 路 I2C PWM 板** 快速验证。重复定位受齿轮回差限制：25kg 数字舵机轴约 1~3mm、MG996R 轴约 3~5mm，**整体 cm 级（毫米级不可达；总线舵机毫米级升级路径见 `精度目标与硬件升级路径.md`）**。

## 四、视觉 — 双摄像头（A 档：2 个 USB UVC，全局视角 + 眼在手）

> ✅ **A 档范围锁定（2026-11-02）：只做纯软件视觉，不买深度相机、不买激光雷达**。
> 摄像头只需支撑「视觉追踪（颜色/质心/KCF）+ 场景理解（画面喂大模型）」，**2D 足够，不需要深度**。
> 订单已含 **USB 工业相机 GF100（720P/60fps UVC 免驱）×1**（装顶部作全局视角）。**眼在手第二颗暂延后采购**：先单相机跑通阶段 2 伪 3D + IK 抓取闭环，确认够用后再决定补 GF100（2D，¥66）还是短距深度相机（D405 / Aurora930）；届时若选深度相机，单颗即同时给 RGB + 深度，不必再买 GF100 眼在手。

| 位置 | 推荐型号 | 镜头 / 视角 | 接口 | A 档内作用 |
|---|---|---|---|---|
| **全局视角**（车体前方或顶部，看整个工作场景） | **GF100**（手上那颗若为 2.8mm 就放此位，否则再购） | **2.8mm / 90°**（0.5m 视野≈1.0m、1m 视野≈2.0m；不用 2.5mm/100°，边缘拉伸且目标过小） | USB2.0 UVC | 全局找目标、给机械臂指路、场景理解画面源 |
| **眼在手**（固连机械臂末端法兰，看抓取目标） | **GF100**（再购 1 个；若机械臂重复定位误差达 cm 级，可选 3.5mm/80° 留容错） | **3.6mm / 70°** 无畸变（0.3m 视野≈0.42m，目标占画面 1/5~1/4） | USB2.0 UVC | 末端近距离追踪目标、质心定位 |

**GF100 统一参数（已核实官方规格）**：
- 传感器 1/4" JRWT1319，像素 3μm×3μm；分辨率 1280×720@60fps
- 接口 USB2.0 High Speed，UVC 免驱（Linux 内核 uvcvideo 驱动，openEuler 直接出 `/dev/video*`）
- 电子卷帘快门（rolling shutter）；镜头可选 **2.5~16mm 共 9 档**，按位置选焦距：**全局 2.8mm/90°**、**眼在手 3.6mm/70°**；3.9mm 及以上（60°/50°/40°/30°/20°）视野过窄，近距目标抓取（臂伸展 0.3~0.5m）不适用
- ⚠️ 同店"颜色分类"为单选，买两个不同焦距需**分两单或下单后备注**两档规格
- 36×36mm 小体积、无畸变镜头（省标定）

> ⚠️ **GF100 三个短板（A 档要心里有数）**：
> 1. **卷帘快门** —— 机械臂快速运动时画面"果冻/拖影"，影响追踪精度；慢速/静态场景无影响。
> 2. **USB2.0 带宽** —— 720P60 原始 YUYV 超带宽，必须走 MJPEG 压缩；双摄同挂一个 USB 控制器会抢带宽（分插不同 USB 口）。
> 3. **1/4" 小靶面** —— 弱光/高动态差，光照一变就噪点/过曝（可补光缓解）。
>
> 若认真做眼在手追踪、要消除果冻：眼在手那颗可升级为 **全局快门微型 USB3.0 摄像头（如 OV9281 方案，约 150~300 元）**，但需上板实测 openEuler arm64 驱动；全局视角仍用 GF100 即可。

> 选型原则：**A 档先 2× GF100（0 元 / 66 元）跑通整条视觉链路**；CSI（树莓派 IMX219/IMX477）画质更好但 **KunPeng openEuler 下 CSI 驱动需实测、风险高**，作后期备选，不建议 A 档首发。

> ⚠️ **百元档"深度相机"要分两类看（2026-11-02 核实）**：① **¥2～¥138** 的"梅卡曼德/图漾/白牌双目"实为**定金 / 引流价 / 拆机裸板**（这些品牌工业正品是万元级），**别碰**；② **¥177 的 Astra Pro 是另一回事**——Astra Pro 已停产，二手行情本就 ¥80~150，¥177 含运费+开票属正常区间，**属于可买的二手真货**（店铺有销量/可开票/7 天无理由即可下单）。而 **¥177~¥499 的 D415 / D435i 才是定金**（正品 ≈ ¥1950）。判断法：**低于官方旗舰店 3 倍以上，先看型号是否已停产（停产老款二手价低是正常的），再看有无"定金 / 补差 / 专拍"字样、能否开票。**
>
> ⚠️ **深度相机不是抓取精度的瓶颈**：深度误差 δz ∝ z²/(f·b)，0.5m 处 1～3mm 已足够近距目标抓取；真正短板是**手眼标定（新手 5～20mm）和机械臂重复定位（舵机臂 1～5mm）**。精度链条上任何一环超过深度误差，换相机都白换——先把标定和机械臂做好。

> ⚠️ **Astra Pro 量程盲区（买二手前必看，2026-11-02 核实官方 datasheet）**：Astra Pro 量程 **0.6–8m**，近于 0.6m 深度图直接是黑洞；而**近距抓取末端到目标通常 0.3~0.5m，正好落在盲区**。短距型号是 **Astra S（0.4–2m，短距优化）**。所以二手 Astra Pro 适合「看整个工作台 / 学点云 / 讲原理」，**撑不起眼在手（相机装夹爪旁、末端到目标 0.3~0.5m）的近距离 3D 伺服**，别指望它替代深度主相机。

> 📌 **别被官方"抓取分拣"应用图误导（2026-11-03 对照官方规格图核实）**：官方资料里的「抓取分拣」是**相机固定在料箱上方 0.8~1.2m 俯视整箱**（即 **bin-picking / eye-to-hand 眼在外**），工作距离落在 0.6~8m 量程内，所以能做——官方没写错。本项目 A 档原设计是 **eye-in-hand 眼在手**（相机挂夹爪旁，末端到目标 0.3~0.5m），同一台相机换这个装法，深度全程无效。**准确结论是"不能眼在手近距用"，不是"Astra Pro 不能抓取"。**
>
> 另有一条比量程更硬的约束：**Astra Pro 净重 310g、外形 164.85×48.25×30mm 长条**，挂在 25kg 舵机臂末端（力臂约 25cm）仅静态力矩就 ≈7.8 kg·cm，再叠加夹爪与目标物，末端腕关节会超调/抖动/回差放大，精度直接崩。对比 **GF100 仅 36×36mm、几十克**——这就是眼在手必须用小模组的原因。
>
> **若仍想用这台 ¥177 二手件**：唯一合理用法是**固定在底盘顶部/侧面支架俯视工作区**（eye-to-hand），负责"大范围找目标 + 粗定位 + 避障"，精细抓取仍交给 GF100 眼在手。代价：openEuler arm64 需自编译 Orbbec SDK；固定俯视抓取依赖手眼标定残差；结构光怕强光与黑/反光面。

> ✅ **二手 Astra Pro 在 openEuler aarch64 上的可行路径（2026-11-02 核实）**：彩色是 UVC（`/dev/video*`，与 GF100 同路）；**深度必须 OpenNI2 + `liborbbec.so`**（私有协议）。官方出过 **`OpenNI-Linux-Arm64-2.3.0.66` 预编译包**，`ros_astra_camera` 仓库亦内置 `openni2_redist/arm64/` 的 arm64 库。**但网上教程几乎都是 ROS1 catkin 包，openEuler 装的是 ROS2 → 直接编不过**；最稳路线是绕开 ROS，用 **Python `openni2` 库**读深度图（`pip3 install openni2`，`export OPENNI2_REDIST=<解压目录>/Redist`）。风险：arm64 预编译库是 Ubuntu 编的，glibc 向下兼容一般 OK，但 `libusb`/`libudev` 版本需自行补（`dnf install libusb1-devel`）。另：深度相机瞬时电流大，**建议带供电 USB Hub**，别直插板载口。
>
> **到手三步验证（不通即退）**：① `lsusb | grep 2bc5` 应看到 **2bc5:0403（深度）+ 2bc5:0502（彩色）** 两个；② `v4l2-ctl --list-devices` 彩色出现 video 节点；③ 装 OpenNI2 跑 `NiViewer`/`SimpleViewer` 能出深度图。

> 🧭 **官方 17 项功能清单怎么读（2026-11-03 对照商家宣传图辨析）**：商家常列「2D 监控 / 颜色识别 / 二维码 / 巡线 / MediaPipe 交互 / 指尖轨迹 / 手关键点 / 肢体关键点」等——**这 8 项用几十块的 RGB 模组（如 GF100）+ OpenCV 就能做，跟深度无关**；真正需要深度的是「点云可视化 / AR 遮挡 / 背景分割 / 3D 物体检测 / 三维人脸 / 体感控制 / 姿态检测 / 建图导航」。两个坑：① **「三维建图导航」≠ 买了相机就能导航**，还需 SLAM（RTAB-Map 等）+ IMU 融合，鲲鹏 4 核 A72 跑 RTAB-Map 勉强；② **「垃圾分类」是结构光死穴**——黑袋吸红外、透明瓶穿透，深度图直接空洞。**这 17 项全是 cm~dm 级演示，无一项要求毫米级**，故「能演示」不能证明「能精确抓取」。

> 🔍 **竞品对照：幻尔 LanderPi 用的是 Aurora930 Pro，不是 Astra Pro（2026-11-03 核实官方 wiki 规格）**。这条决定「能不能复刻它的 3D 抓取」：
> - **Aurora930 Pro**：76.5×20.7×21.8mm、基线 40mm、**工作距离 15–300cm**、深度 3mm@0.5m / 7~8mm@1m、640×400@5~15fps、FOV H71°×V46°、USB2.0、<1.6W、支持 Linux/ARMv8/ROS/Win/Android。
> - 宣传页上 3D 抓取图标出的深度值是 **279 / 291 / 313 / 315mm**，正好落在 Aurora930 的舒适区，却是 **Astra Pro（60–800cm）的盲区**。
> - **结论**：¥177 二手 Astra Pro 复刻不了「在手边 30cm 做 3D 抓取」的演示；只能装车顶看 0.8m 以外做粗定位/点云入门。要近距 3D 需 0.2~0.3m 起效的型号（Aurora930 / Gemini 2），Astra S（0.4m 起）也只勉强。
> - 详见 `低预算能力清单（功能边界）.md` 第二节。

## 九、⚠️ 必读坑点（已核实，避免重踩）

1. **KunPeng Pro 是 4 核，不是 8 核** — 鲲鹏920，4× ARMv8-A @1.6GHz。面试被问"几核"答 4 核。
2. **NPU 不可用** — 昇腾 NPU 载板电流采样设计缺陷（power=0.0，全系列通病，RMA 同款无效），计算面废。CPU 完好，视觉跑 CPU、LLM 走云端。本项目不依赖 NPU。
3. **eMMC 是可选外接模块** — 未插则 `/dev/mmcblk0` 不存在是正常的，**不是板子坏**；当前 SD 卡启动完全 OK，无需购买 eMMC。
4. **KunPeng 供电两种方式（二选一）** — ① Type-C 20V PD 65W 适配器（随板附赠）；② 2pin 电池接口接 3 串锂电池（≈11.1V，官方支持快充），适合机器人移动场景。⚠️ 严禁把小车 5V 直接灌入 KunPeng 任何接口（电压不匹配会烧板）；走电池接口必须 3 串（≈11.1V），不是 5V。
5. **风扇必接** — 鲲鹏 920 发热大，无风扇会过热降频/关机。
6. **ESP32-S3 仅 BLE 5.0，无经典蓝牙** — 手机交互走 Wi-Fi 或 BLE，别写"蓝牙 4.2 经典"。
7. **ESP32-S3 核心板电源/电容已核对** — BOM 用 AMS1117-3.3 + 10µF/100nF 去耦（符合乐鑫指南），无 RT9193、无 VCAP 问题，回板可直接焊。
8. **STM32F407 核心板电容已核对** — 实际 BOM（stm32F407.xlsx）中 VCAP(C5/C6)=2.2µF、晶振负载(C16/C17)=20pF C0G、去耦(C1/C3/C7~C15)=100nF **均已正确**（VCAP 为 STM32 内部稳压器专用引脚、ESP32-S3 无），原"3 处错误"在最终 BOM 中不存在，回板可直接焊。
9. **USB-TTL / USB-CAN 适配器必选** — STM32 不直接联网，经适配器上 KunPeng 跑协议桥，否则架构悬空。
10. **摄像头优先 USB UVC** — 免驱即插即用，避开 CSI 在 openEuler 下的驱动不确定性。
11. **IoT 云端平台选阿里云 IoT / EMQX 桥接** — 不在 KunPeng 本地跑 ThingsBoard（其 CE 核心镜像主要 amd64，aarch64 需模拟、不稳）；EMQX/eKuiper/InfluxDB/Grafana 均有官方 arm64 镜像，可原生跑。
12. **鲲鹏920 无 GPU，NPU 又不可用** — 深度学习只能走"轻量 CPU 模型（YOLOv8n INT8 约 10~15FPS）+ 传统 CV 兜底 + 云端重模型"。⚠️ **绝不要说"本地跑深度学习自动驾驶"**，一问帧率就穿。
13. **激光雷达波特率必须对齐型号** — RPLIDAR A1=115200、A2M7=256000、C1=460800；配错的表现是"雷达通电、lsusb 看得到、但一个点都不出"。另需 `sudo usermod -aG dialout $USER` + udev 规则把串口固定成 `/dev/rplidar`（否则重启后 ttyUSB 编号会跳）。
14. **openEuler 有官方 ROS2 Humble 源（不用源码编译）** — `dnf install openeuler-ros` 再按需装 `ros-humble-ros-base`、`ros-humble-navigation2`、`ros-humble-slam-toolbox`、`ros-humble-cartographer-ros`、`ros-humble-rviz2` 等，均在 EPOL 仓库中。注意 SP1/SP2/SP3/SP4 的源路径不同，先 `cat /etc/os-release` 确认版本。
