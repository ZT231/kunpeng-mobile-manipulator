### 2.3 为什么这样选脚（被否掉的备选）

| 备选写法 | 为什么不采用 | 实际采用 |
| --- | --- | --- |
| PWM：PB6\~PB9 | PB6/PB7/PB8 是 NRF24L01 排座的 CE/CS/IRQ（本板无 24C02），整组被 NRF 排座占用 | **PD12\~PD15**（TIM4 四通道；不插 TFT 时可用） |
| DIR 模块 2：PC10\~PC13 | PC10\~PC12 是 SDIO_D2/D3/CK，PC13 属备份域弱驱动且部分板带 LED；驱动 TB6612 会与 SD 卡/LED 冲突 | **PB12\~PB15**（TFT 触摸 SPI2 排座，不插屏） |
| DIR 模块 2：PA4\~PA7 | PA5 要留给编码器 B（TIM2_CH1）；PA6/PA7 是板载 LED D2/D3，整组占用会破坏编码器 B、点亮 LED | **PB12\~PB15** |
| STBY：PB2 | PB2 是 **BOOT1** strap，部分核心板带下拉/跳线帽，不适合当普通输出 | **PE8**（TFT FSMC 排座，不插屏） |
| 编码器 B：PA15/PB3 | PA15 是 JTAG TDI（紧邻 SWD 的 PA13/PA14，SWD 后释放）；PB3 是 W25Q16 CLK 兼 NRF SCK | **PA5/PB3**（PA5 纯空闲、远离调试区；PB3 复用 W25Q16 CLK，CS(PB0) 常高） |
| 编码器：TIM3 CH1\~CH4 + TIM8 CH1\~CH4 | **不成立**：F4 每个定时器只有一个正交编码器接口，固定占 CH1/CH2（TI1/TI2）；CH3/CH4 不参与解码，这样接只能得到 2 路 | **TIM3 + TIM2 + TIM8 + TIM1 各一路** |

> 这条不是「换脚方便」，是硅片结构决定的：RM0090 的编码器模式只把 TI1/TI2
> 送进正交解码器，CH3/CH4 是独立的输入捕获 / 输出比较通道，不走计数器方向逻辑。

* **不要**把驱动板自带的 `5V` / `3.3V` 输出脚接到 STM32 的 3.3V 排针：

  两边都是「源」，会倒灌。驱动板的 5V/3.3V 输出可以空着，或只给编码器供电（先量电平）。

* 每块 TB6612 的 `VM-GND` 就近并 **100µF/25V 电解 + 0.1µF 陶瓷**；电解负极对 GND。

  四个电机同时换向时，母线会被拽出尖峰，这两个电容是给尖峰兜底的。

* 11.2\~12V 母线先串 **15A 保险**。四轮同时堵转 4×2.3A≈9.2A，15A 是「不误断但能保命」的档位。

* 台架第一次只带底盘，降压限流 **3A**；整车联调再按 8A 评估（舵机堵转叠加会更高）。

#### 3.2.1 电源输入端子：每块板有两个蓝端子，只接一处

每块板左侧（靠 `MOTOR-B`）和右侧（靠 `MOTOR-A`）各有一个 **2P 蓝色螺钉端子**，丝印不同：

| 端子 | 位置 | 实物丝印 | 针序 | 结论 |
| --- | --- | --- | --- | --- |
| **`VIN`** | 右侧，紧邻 `MOTOR-A` 与洋红色 220µF/25V 电解电容 | `−`（上）/ `+`（下）/ `VIN` | **上针 = 负，下针 = 正** | **主电源入口（VM）：12V 接这里** |
| `VIN1` | 左侧，紧邻 `MOTOR-B` | `VIN1`（上）/ `+` / `VIN2`（下） | 上针 = 正；下针极性未标注 | **未实测前保持悬空** |

⚠️ **`VIN` 端子是「上负下正」**——丝印 `−` 在上针、`+` 在下针。接反会直接烧驱动板，接前用万用表核对。

**为什么只接一处**：一块板只有一颗 TB6612、一个 VM 网络，两个端子是同一路电源的两个入口（用于多板级联时一进一出）。接一个就完成供电；两个都接等于把两根线并联，不增加任何电流能力，只多一个接反的机会。

**接线前用通断档确认三件事**（断电、不接电池组）：

1. 右侧 `VIN` 下针（+）↔ 左侧 `VIN1` 上针（+）→ **响** 说明两端子并联，接哪个都一样（仍建议接右侧 `VIN`，丝印最全）
2. 右侧 `VIN` 下针（+）↔ 220µF/25V 电解电容的 `+` 极 → **响** 说明确认是 VM 网络
3. 右侧 `VIN` 上针（−）↔ 控制排针 `GND` 针 → **响** 说明确认是公共地

若第 1 项**不响**，两个端子不是同一网络，**只能接右侧 `VIN`**，`VIN1` 永久悬空。

> `3.3V`（第 5 针）
>
>  是板载 3.3V **输出**（只接 VM 时对 GND 应约 3.3V），不要再外接 5V。
> **备用：若你用的是「裸 TB6612 + 螺钉端子」版（无 6P 座）**
> 电机红 / 白线直接进 
>
> `AO1/AO2`
>
> 、
>
> `BO1/BO2`
>
>  螺钉端子；编码器蓝→3.3V、黑→GND、
> 黄 (A)→CH1、绿 (B)→CH2 单独引线。接线逻辑与上面完全一致，只是少了 6P 座这一层。

### 3.5 麦轮装法



* 轮毂 6mm 孔配 6mm 金属联轴器，联轴器顶丝必须顶在电机 **D 形轴平面**上，不能顶在圆弧面。

* 80mm 麦轮有左右旋之分：**左前 + 右后** 一组，**右前 + 左后** 另一组。

  从车头看，四个轮的辊子轴线应指向车体中心（X 型）。装反了表现为：

  前进 / 后退正常，但横移变反或原地画圈。

* 轮子装好后先手转一圈，确认不刮底盘、联轴器不偏心；偏心会在 0.3m/s 以上引发整车共振。

## 4. 上电前检查清单（缺一不可）



* [ ] 12V 母线对 GND 不短路（万用表二极管档 / 电阻档）。

* [ ] 两块 TB6612 的 `VM` 都是 12V；控制排针的 `3V3` / `5V` 两针**全部悬空**（只量电压、不接线），杜绝倒灌。

* [ ] 4 根 PH2.0→XH2.54 转接线插到 4 个电机座；座内第 5 针 `3.3V` 是板载 3.3V **输出**（不外接，对 GND 应读 3.3V）、`GND` 共地；`C1`/`C2` 按编码盘丝印接（C1=A 相、C2=B 相），**不要按线色猜**。

* [ ] STBY（PE8）在**复位瞬间是低电平**（待机）；`CHS_Init` 成功后会拉高使能，

  但此时 PWM=0、DIR=0，轮子仍是 coast。若一上电就转，查 STBY 是否被板上拉 / 接错。

* [ ] 四个轮子悬空，联轴器顶丝拧紧。

* [ ] ST-Link 接的是 **SWD**（PA13/PA14），不是 JTAG，也**不要开 SWO**——
  PB3/PB4/PB5 与板载 W25Q16 的 CLK/MISO/MOSI 共用；固件已把 PB0(CS) 拉高，
  若调试器再开 JTAG/SWO，TIM2/TIM3 的计数仍会不正常。

* [ ] 12V 电源限流 3A，急停 / 断电开关在手边。

* [ ] 确认核心板排针确实引出 **PA5 / PB3 / PB5 / PB0 / PB12\~PB15 / PE8 / PE9 / PE11 / PD12\~PD15 / PC6 / PC7**；
  某个脚没引出就改 `chs_tb6612.h` 的宏或飞线。**PB0 只做 W25Q16 的 CS 输出，不接编码器**；
  PB12\~PB15 不要插 TFT 触摸屏，PD12\~PD15/PE8/PE9/PE11 不要插 3.5" TFT。

* [ ] **PB4 不在主排针上**（DevEBox F4VE 实测丝印确认）：PB4 只出现在 **6 针 JTAG/SWD 调试口**
  （丝印 `PB4/TRST`）与 **NRF24L01 排座的 MISO 针**，两处同属一个网络（`SPI1_MISO`）。
  编码器 A 的 `C1`（A 相）从 **NRF 座 MISO 针**引出（推荐，独立不占调试口），或从调试口 `PB4/TRST` 针引出；
  `C2`（B 相）仍用主排针 **`PB5`**（右排针 `PB5 PB3` 那一对的左针）。
  三个前提：**不插 NRF24L01 模块**（模块 MISO 会抢线）、**Keil 调试必须 Port = SW**
  （选 JTAG 会驱动 TRST = PB4，与编码器打架）、**PB0(FLASH CS) 常高**（固件已保证）。

## 6. 第一次上电（台架，四轮悬空）

### 6.1 看启动日志

复位后 USART1 应出现：



```
CHS: init OK (2xTB6612, TIM4 20kHz, 4xENC, JGB37-520 1:90)
```

若出现 `CHS: init FAIL (check TIM4 PD12~PD15 / TIM1,2,3,8 encoder pins)`，

说明某个 `HAL_TIM_*_Init/Start` 返回了非 HAL\_OK：先查时钟配置（SYSCLK 是否 168MHz）、

再查这四个定时器是否被 CubeMX 重复初始化。

### 6.2 逐轮点动（不开环跑整车）

发（校验和见第 7 节）：



```
$CAR,RAW,10,0,0,0*09     → 只有 A 左前转，10%
$CAR,STOP*64             → 请求 coast（下一拍 ≤20ms 生效）
$CAR,RAW,0,10,0,0*09     → 只有 B 右前转
$CAR,RAW,0,0,10,0*09     → 只有 C 左后转
$CAR,RAW,0,0,0,10*09     → 只有 D 右后转
```

看三件事：



1. **轮位对不对**（A/B/C/D 与表 2.1 一致）；

2. **物理转向对不对**：给正数时，该轮应把车往前推；反了就交换该电机的红 / 白线，

   不要改代码里的 `WDIR`（改线是物理事实，改宏只是软件兜底）；

3. **编码器有没有数**：转的时候发 `$CAR,ENC*34`，对应那一路应明显变化；

   不变化先查该座 `C1`/`C2` 与第 5 针 `3.3V`/`GND` 针。

### 6.3 自检（可选，但建议做一次）

把 `Core/Inc/chassis.h` 里：



```
#define CHS_SELFTEST_EN   0   →   1
```

重新编译、烧录、复位。四轮悬空，串口会逐轮 +20% / −20%，每方向 500ms：



```
[CHS] A(LF) fwd=... rev=... -> OK / CHECK WIRING/ENCODER
...
[CHS] self-test done, 4/4 passed
```

合格判据：`|fwd| > 20`、`|rev| > 20`，且 `fwd` 与 `rev` **符号相反**。

编码器 A/B 反接时 `fwd` 会是负的，但正交解码本身没问题，仍判 `OK`；按上表把该路

`EDIR` 改成 `-1` 即可，不要为了「让 fwd 变正」去改电机线。

通过后**务必改回 0** 再装车，否则每次上电车都会自己转 4 秒。

如果不通过，按这两条定位：



| 现象                      | 原因                  | 改法                                                   |
| ----------------------- | ------------------- | ---------------------------------------------------- |
| `fwd ≈ 0`、`rev ≈ 0`     | 电机没转或编码器没接          | 先 `$CAR,RAW,10,...` 看电机；再查该座 `C1`/`C2` 与第 5 针 `3.3V`/`GND` |
| `fwd > 0`、`rev > 0`（同号） | 编码器只接了一相 / C1-C2 短路 | 查 `C1`/`C2` 两针，别接混                                   |
| `fwd < 0`、`rev > 0`（反号） | 编码器 A/B 对调          | `CHS_EDIR_x` 改成 `-1`（只改这一路）                          |
| 电机转但车往后推                | 该轮电机线序与其它轮相反        | 交换该电机红 / 白线，`WDIR` 保持 +1                             |

> 为什么默认 
>
> `WDIR`
>
>  全 +1：四个轮子都按「raw + = 车前进」接线，麦轮逆解
> 「四轮同为正 = 前进」才成立。右轮镜像安装时 raw + 可能倒转，
>
> **换线**
>
> 即可，
> 不要用 
>
> `WDIR=-1`
>
>  去补 —— 那会让该轮的速度反馈符号和命令符号对不上。

### 6.4 编码器常数标定（3960 到底对不对）



1. 在 A 轮轮面画一条白线；

2. 发 `$CAR,ENC*34`，记下 A 的原始累计值；

3. 用手**慢慢**把 A 轮正好转一圈（对准白线）；

4. 再发 `$CAR,ENC*34`，差值应约 **3960**（± 几个计数是手转误差）。

差值对不上就改 `chassis.h`：



| 实测 / 圈 | 说明            | 改法                 |
| ------ | ------------- | ------------------ |
| ≈3960  | 11 线，正确       | 不改                 |
| ≈4680  | 13 线          | `CHS_ENC_LINES 13` |
| ≈3600  | 10 线          | `CHS_ENC_LINES 10` |
| ≈1980  | 只测到 2 倍频 / 单相 | 查 A/B 是否有一根没接      |

### 6.5 落地低速测试



1. 12V 限流 3A，车放地上，前方留 2m；

2. `$CAR,VEL,0.1,0,0,1000*0D`（1 秒 0.1m/s），看是否直线、有没有单轮拖后腿；

3. 再试 `$CAR,VEL,0,0.1,0,1000*0D`（右横移）和 `$CAR,VEL,0,0,0.5,1000*09`（逆时针自转）；

4. 方向不对，按这个顺序查：

* **vx 反**：某一轮电机线反了。四轮悬空，`$CAR,RAW` 逐轮看，哪轮反就换哪轮红 / 白；四个都正，vx 才对。

* **vx 对、vy 和 wz 都反**：四个麦轮的辊子对角线装成了另一种（O 型），把四个轮子绕垂直轴转 180°，或在上位机同时取反 vy/wz。

* **只有 wz 反**：先回头确认四轮 vx 是不是真的都往前（单轮装反会被 vx 的平均值掩盖）；四轮都对还反，检查左右轮是不是装错位置。

1. 都对了再上 0.2\~0.3m/s；**不要一上来就 0.45m/s**。

## 7. 协议命令

帧格式不变：`$<payload>*<XOR 两位大写 hex>\r\n`，XOR 覆盖 `$` 与 `*` 之间的全部字节。



| 命令                       | 作用                                                           | 示例（含校验）                  |
| ------------------------ | ------------------------------------------------------------ | ------------------------ |
| `$CAR,VEL,vx,vy,wz[,ms]` | 麦轮逆解速度，m/s、rad/s；500ms 心跳                                    | `$CAR,VEL,0.2,0,0*23`    |
| `$CAR,STOP`              | 请求 coast（下一拍 ≤20ms 生效）                                       | `$CAR,STOP*64`           |
| `$CAR,ODOM`              | 回 `ODOM,x_mm,y_mm,yaw_deg,online`                            | `$CAR,ODOM*75`           |
| `$CAR,RESET`             | 里程计清零                                                        | `$CAR,RESET*29`          |
| `$CAR,RAW,a,b,c,d`       | 开环 ±30%，原始占空比（不乘 WDIR）                                       | `$CAR,RAW,10,0,0,0*09`   |
| `$CAR,WHEEL`             | 回 12 个整数：四轮目标 / 实测 mm/s、占空比‰                                 | `$CAR,WHEEL*2F`          |
| `$CAR,ENC`               | 回四路原始累计计数                                                    | `$CAR,ENC*34`            |
| `$CAR,GAIN,kp,ki,kd`     | 在线改增益，不写 Flash                                               | `$CAR,GAIN,700,900,0*6F` |
| `$CAR,CLRFAULT`          | 清堵转故障；下一拍（≤20ms）由 ChassisTask 重新使能 STBY。无故障时回 `ERR,5`，不会顺手停车 | `$CAR,CLRFAULT*6B`       |

`$STOP` 只停底盘（调 `CHS_Stop` → coast）；无 `$RESUME`。

> `$CAR,STOP`
>
>  是「请求式」：ChassisTask 在下一拍（≤20ms）才真正把 H 桥 coast。
> **STOP 后至少等 20ms 再发新的 VEL/RAW**
>
> ；连续控制时按 10Hz 心跳重发，
> 不要指望 STOP 和 VEL 在同一毫秒内无缝衔接。
> 单轮线速度上限 
>
> **0.45m/s**
>
> ；
>
> `vx/vy/wz`
>
>  算出的任一轮超限时，四轮
>
> **等比缩放**
>
> ，
> 不逐轮裁剪（裁剪会把合力方向掰歪）。所以上位机给 1.0m/s 不会真的跑 1.0，
> 实际会被压到 0.45m/s 以内。
> 上表示例都已带校验；自己拼新 payload 时用下面脚本算，别手抄错。



```
def frame(payload: str) -> str:
    ck = 0
    for ch in payload:
        ck ^= ord(ch)
    return f"${payload}*{ck:02X}\r\n"

print(frame("CAR,VEL,0.1,0,0,1000"))
print(frame("CAR,RAW,0,10,0,0"))
```

`$CAR,WHEEL` 返回示例（单位 mm/s、‰）：



```
$WHEEL,200,198,430,200,205,425,200,190,440,200,210,420*5D
        tA  sA  dA  tB  sB  dB  ...
```



* `tA/sA` 差得大 → 该轮 PID 没跟上或机械阻力大；

* `dA` 长期顶到 ±1000 → 前馈不够 / 电压低 / 轮子卡；

* 四轮 `s` 都明显低于 `t` → 电池压降或 12V 限流触发。

## 8. PID 调参（先台架，后落地）

默认值（`chassis.h`）：`KP=700, KI=900, KD=0, FF=1800, 死区=70`。

这些只是**起点**，12V/11.2V、车重、轮子阻力不同都要重调。



1. `$CAR,GAIN,0,0,0*61` → 只剩前馈；

2. 发 `$CAR,VEL,0.2,0,0*23`，每 100ms 发 `$CAR,WHEEL*2F`，看 `sA` 是否接近 200mm/s；

* 明显低于 200 → 加大 `FF_GAIN`（1800→2000）；

* 明显高于 200 → 减小；

1. 加 KP：`$CAR,GAIN,300,0,0*62` → `$CAR,GAIN,600,0,0*67` → `$CAR,GAIN,900,0,0*68`，看超调和抖动；

* 轮速在目标附近 ±0.05m/s 抖 → KP 太大；

* 起步软、跟不上 → KP 太小；

1. 加 KI：`$CAR,GAIN,900,300,0*6B` → `$CAR,GAIN,900,600,0*6E` → `$CAR,GAIN,900,900,0*61`，消稳态误差；

* 积分大了会「低速爬行 — 突然窜」，先把 KI 减半；

1. KD 默认 0。编码器 20ms 测速噪声大，加 D 通常只会抖；除非有高频超调才试 20\~50；

2. 调好后把值写回 `CHS_PID_KP/KI/KD`，重新编译；`$CAR,GAIN` 不持久化。

**先调直行，再调横移，最后调自转**。自转时四轮目标相反，任何一轮方向错都会变成

「原地画圈 + 里程计航向飞掉」。

## 9. 故障处理

### 9.1 堵转锁死

现象：车突然停、`$CAR,ODOM` 的 `online=0`、串口打印：



```
[CHS] STALL wheel B: cmd=200 mm/s, spd=3 mm/s -> FAULT
```

处理：



1. 断电 / 架空前检查该轮是否被线束、联轴器、底盘卡住；

2. 手转该轮应顺畅；

3. 确认不是「目标太小 / 静摩擦大」造成的误判（`CHS_STALL_CMD_MS=0.08` 以下不判）；

4. 发 `$CAR,CLRFAULT*6B`；等 ≥20ms 让 ChassisTask 重新拉高 STBY，再重新 `$CAR,VEL`。

5. 连续多次堵转：查 12V 是否掉压、TB6612 是否过热、电机是否进灰。

### 9.2 不动 / 单轮不转



* 单轮不转：`$CAR,RAW,10,0,0,0` 点动；不转 → 查该路 PWM/DIR 线、TB6612 该通道、

  电机 M1/M2；转但 `$CAR,ENC` 不变 → 查编码器 `C1`/`C2`/第 5 针 `3.3V`/`GND`。

* 四轮都不转：STBY（PE8）是否为高；12V 是否到 VM；`online` 是否 0。

* 一转向就重启 / 复位：12V 尖峰 / 共地不良，查 100µF、星点地、电池限流。

### 9.3 速度上不去 / 电流大



* 12V 实际掉到 10V 以下 → 电池 / 降压限流；

* 联轴器打滑 → 顶丝没顶到 D 平面；

* 麦轮装反 → 横移阻力大；

* PID `d` 顶满但 `s` 低 → 机械阻力 / 轮子刮底盘。

## 10. 诚实边界



* **未实机**：本文引脚 / 定时器配置**尚未实机上电验证**；Rebuild 0 Error / 0 Warning（Code=24440），

  `KP/KI/FF` 是按 12V/110rpm 估的起点，必须按第 8 节实测重调。

* **没有电流环**：TB6612 没有电流反馈脚，代码只能靠「PWM 有、编码器不走」判堵转；

  轮子打滑空转（编码器仍在转）时不会保护，可能持续 2.3A 堵转电流（四轮 9.2A）。

* **TB6612 余量薄**：1.2A 连续 vs 电机 2.3A 停转（四轮 9.2A），任何长时间堵转 / 频繁正反转都要避免；

  台架限流 3A，落地限流按 8A 评估。

* **里程计会漂**：麦轮靠轮速积分，打滑、地面不平、轮径磨损都会累计误差；

  只能做短时相对定位，不能替代激光雷达 / 视觉。

* **实际 dt 会抖**：速度 / 里程计用 HAL tick 实测 dt，不再硬按 20ms；PID 的控制 dt

  夹到 100ms，任务被长时间阻塞时控制会变慢，但不会把速度算翻倍。

  `StartChassisTask` 另有「欠拍不补跑」保护，极端负载下仍应以实测为准。
