## 〇 一句话定位

板子**硬件主体健康、可放心用于本项目**；但有**两个出厂已知的"设计局限"**（NPU 不可用、eMMC 为外接插座），不是你弄坏的，但**必须在方案里写清、在面试里能答**。把这两个点讲清楚，反而证明你真上手摸过板子——比"一切正常"专业得多。

## 一、已知局限清单（均已实跑/查官方核实）

### 局限1：NPU（昇腾 8TOPS INT8）不可用 —— ⚠️ 板级硬件设计缺陷

- **现象**：加载 NPU 驱动/算子时报 `0xE3A203`（官方定义：node type=LPM, sensor type=Chip Hardware, event=obtaining current abnormal，即"取电流异常"）。
- **根因（已查社区证实）**：载板缺失电流检测电阻，是**硬件设计缺陷**，非驱动/配置/操作问题。同型号 RMA 大概率复现，属全系列通病。
- **对本项目影响**：**不构成阻塞**。架构里视觉推理走 KunPeng **CPU(OpenCV) + 云端 LLM**，NPU 支线已放弃。
- **规避**：算力三层——KunPeng CPU 跑视觉/边缘检测、云端 Ascend/LLM 跑重推理、ESP32 跑向量指令(语音)。若真要 NPU 算力，用云端 Ascend 实例或 Atlas 200I DK A2，不跟这块板的 NPU 死磕。

### 局限2：eMMC 为可选外接插座（非板载）

- **现象**：`/dev/mmcblk0` 不存在；自检脚本一度误报 FAIL（已修正为 INFO）。
- **根因**：官方设计 eMMC 是"可选外接模块需另购插入"，不是板载焊接。你未插模块属完全正常。
- **对本项目影响**：启动盘用 **TF 卡**（与拨码开关"TF 卡启动"吻合）。没用上"板载 eMMC 存储"能力，但不影响功能。
- **规避**：系统装 TF 卡；SD 卡偶发随机启动失败已用 `rootdelay` 规避；数据/大镜像放 NVMe(M.2) 或 USB 盘。

### 局限3：无板载 RTC

- **根因**：板子无电池供电 RTC 电路。
- **规避**：用 `chrony` / `ntpd` 联网校时，系统启动后从 NTP 同步。

### 局限4：SD 卡启动偶发随机失败

- **规避**：内核命令行加 `rootdelay=10`（等 TF 卡设备就绪再挂载根文件系统）。

### 局限5：i2c8 周期性 NAK（幽灵地址）

- **现象**：I2C 扫描 i2c8 偶发 NAK。
- **根因**：已知幽灵地址，与 NPU 缺陷无关，**非硬件故障**，可忽略。

### 供电/散热必读（非缺陷，是操作红线）

- **20V PD 供电**：随盒附赠 65W PD 电源 + 风扇，**风扇必接**（裸板高负载会过热降频/关机）。
- **移动供电**：板子有 2-pin 电池接口(2.54mm) 可接 3 串锂电(≈11.1V，支持快充)；小车不能拖 220V 线时走电池口。
- **严禁小车 5V 直灌 KunPeng**：KunPeng 用 20V PD 或电池口，与 STM32/ESP32 的 5V/3.3V 系统电源**必须隔离**。

## 二、面试应对话术（场景化，直接背）

**Q1：你用的什么板子？几核？**
> "OrangePi KunPeng Pro v1.1，香橙派出的鲲鹏920 开发板，4 核 ARMv8-A（华为自研 TaiShan v110 微架构）aarch64，16GB LPDDR4X，跑 openEuler 22.03。我选它是因为要原生跑 arm64 的 Docker 容器栈（EMQX/InfluxDB 那些），x86 板子反而要 qemu 模拟。"

**Q2：板子有什么坑/限制吗？**
> "两个出厂已知局限，我都实测 + 查社区确认过：① NPU（昇腾 8TOPS）是载板电流采样电阻缺失的硬件设计缺陷，全系列通病、RMA 也复现，所以视觉推理我没指望 NPU，改走 CPU+OpenCV 加云端 LLM；② eMMC 是外接插座得另购模块，我没插，系统跑在 TF 卡上。这些都提前规避了，没卡住项目。"

**Q3：那视觉识别 / AI 推理怎么跑？性能够吗？**
> "分层调度：轻量边缘检测/目标识别在 KunPeng 的 4 核 CPU 上用 OpenCV 实时跑；重推理（LLM 任务规划、复杂识别）走云端 API；语音唤醒在 ESP32 端侧离线跑。NPU 废了的板子，我用软件栈 + 云端补足，反而体现了异构算力的调度设计。"

**Q4：（追问）你确定 NPU 是板子问题不是你配置错？**
> "确定。错误码 0xE3A203 官方定义就是取电流异常，是硬件传感器层面的报错，不是驱动/算子问题。昇腾和鲲鹏社区都有同型号 RMA 复现的帖子，属于公认坑。"

**Q5：启动 / 存储怎么处理的？**
> "TF 卡启动（拨码开关设 TF 启动），SD 卡偶发启动慢我加了 rootdelay 等盘就绪；数据和大镜像放 M.2 NVMe；eMMC 没插不影响功能。"

## 三、可放心拍胸脯的点（已实跑验证，非嘴说）

- CPU 4 核 / 内存 15GiB 可用 ✅
- WiFi5（欧智通 6221BUUC）+ 蓝牙 4.2 ✅
- 千兆以太网口（RTL8211FW）✅
- USB3.0 ×2 + Type-C + MicroUSB ✅
- I2C eeprom / 显示 `/dev/dri` / CAN 总线 ✅
- 温度 60-62℃ 正常（满载前）✅

> **证据**：你 `sudo` 跑过硬件自检脚本，日志实测 **PASS=9 / FAIL=1 / WARN=1**，其中唯一 FAIL 的 eMMC 经核实是脚本误报（外接插座未插），已修正为 INFO。结论：板子主体完全健康。

## 四、面试 / 文档千万别踩的雷

- ❌ 写"8 核 A55"——实际 **4 核**（已查清，方案文档已改正）。
- ❌ 写/说"NPU 可用、用 NPU 跑推理"——会立刻被戳穿。
- ❌ 混淆 STM32 的 VCAP / RT9193 与 ESP32 板（ESP32 板用 AMS1117、无 VCAP、无 RT9193 风险，板已核对可焊）。
- ❌ 说"完全没问题"——NPU 缺陷客观存在，诚实说"有两个已知局限已规避"更专业、更显真实做过。
- ❌ 把"已购订单里的 ESP8266/HC-05/MFRC522"塞进本项目——ESP32-S3 仅 BLE5.0 无经典蓝牙，那些器件本项目不用。
