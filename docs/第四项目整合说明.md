### 2.2 A 项落地：`$CAR,FWD,800*3D`

沿用 `docs/机械臂小车+语音-可行性与落地路线.md` 第七节既定的阶段 A 定义：

> 发一帧 `$CAR,FWD,800`，车前进 0.8s 停；`$CAR,STOP` 立即停。工期 2~3 天，¥0。

- **800 = 毫秒**（不是厘米、不是 PWM）。底盘无编码器 / 里程计，是纯开环定时，长距误差 20~40%。
- 帧语法**与机械臂固件 `Core/Src/uart_protocol.c` 完全一致**：`$<CMD>[,<ARG>...]*<CK><CR><LF>`，
  CK = payload 逐字节 XOR、2 位大写 HEX，错误码 `1/2/3/4` 也沿用同一套。
  ⇒ 鲲鹏 / ESP32-S3 用**同一种句子**就能调度两个 MCU 节点，这才是「统一帧」。
- 固件侧有本地仲裁闸门（时长 ≤5000ms、PWM ≤999、MODE ≤2），越界 `$ERR,3` 且不动车。

### 什么情况下**才**需要改 CubeMX（本次不做）

如果将来想「车臂合体到**同一块** F407VE」，就得在 `RoboticArm_Kunpeng.ioc` 里：

1. 加 **TIM8** 四路 PWM → PC6/PC7/PC8/PC9（L9110S 的 IN1~IN4）；
2. 加 HC-SR04 的定时器输入捕获 + 外部中断、4 路循迹 GPIO、云台舵机 PWM；
3. 把小车串口从 **USART1（PA9/PA10）挪走** —— 它已被机械臂占用（PC 上位机通道），
   USART2（PD5/PD6 = HC-05）和 USART3（PB10/PB11 = ESP-01S）也都有主；
4. Generate Code 重新生成 → **重烧固件**。

🔴 代价：重烧会甩臂（项目既有铁律），而且会动到**已经实机验收通过**的机械臂链路
（眼在手全链、14 次重复性、三条闸门全在这块板上）。收益只是省一块 F407ZE，
风险远大于收益 ⇒ **不推荐，本次明确不做**。

### 概念补一句（大白话 + 规范定义）

- **CubeMX**：ST 官方图形化配置工具，点引脚 / 时钟 / 外设后自动生成 HAL 初始化代码，
  配置存在 `.ioc` 文本文件里（ST 官方：STM32CubeMX / STM32Cube HAL，FW_F4 V1.28.3）。
- **SPL（Standard Peripheral Library）**：CubeMX 之前的老寄存器封装，
  `GPIO_InitTypeDef` / `RCC_APB2PeriphClockCmd` 就是它的写法，工程文件是 Keil `.uvprojx`。
- 两套库**不能混编**：SPL 驱动直接塞进 HAL 工程会编译不过。所以「合并」按节点各自保留工程，
  靠**串口帧协议**在运行时统一 —— 这也是分布式嵌入式系统更常见的做法。
