# 阶段 0 · 视觉能力基线（双 GF100 诚实边界）

> **文档定位**：这是整个「移动操作机器人（机械臂装小车）」项目从 0 开始的**能力地基**。
> 所有后续阶段（通用物体识别 → 抓取 → 语音指挥 → IoT 可观测）都建立在这份视觉基线上。
> 先把「两颗 GF100 到底能干什么、不能干什么」钉死，后面的规划才不会飘。
> 本阶段**不写代码、不买硬件**，只把能力边界和误区定清楚（属于决策沉淀）。

---

## 0.1 两颗 GF100 到底是什么（先讲概念）

### 概念①：GF100 摄像头（大白话 + 规范定义）
- **大白话**：它就是一颗「普通 USB 摄像头」，插上电脑能出一张彩色平面照片；它**只知道画面里某个亮点在第几行第几列，不知道这个点到相机有多远**。
- **规范定义**：GF100 采用 1/4″ **JRWT1319** CMOS 传感器，输出 **720P@60fps**、**USB2.0 UVC 免驱**、**电子卷帘快门（rolling shutter）**，物理尺寸 36×36mm。它是一颗 **2D RGB 摄像头**，**不输出深度（depth）通道**。

### 概念②：eye-to-hand（眼在外）vs eye-in-hand（眼在手）
- **大白话**：相机装在**机械臂外面、看着整个工作区**，叫「眼在外」；相机装在**机械臂末端夹爪附近、跟着手臂一起动**，叫「眼在手」。
- **规范定义**：Robotic vision 中按相机位姿是否随机械臂运动分为 **eye-to-hand**（相机固定于世界坐标系，观测臂与工件）与 **eye-in-hand**（相机固连于末端执行器，随臂运动）。前者用于全局定位，后者用于精细对准与闭环伺服。

### 本项目双摄像头分工（已定稿）
| 摄像头 | 安装位置 | 镜头焦距 / 视场 | 角色 | 工作距离 |
|---|---|---|---|---|
| GF100-A | 小车顶部（朝前/下俯视工作区） | 2.8mm / 90° | **全局眼在外**：大范围找目标、粗定位 | 0.5~2m |
| GF100-B | 机械臂末端（夹爪旁） | 3.6mm / 70° | **眼在手**：精细对准、抓取确认 | 0.3~0.5m |

> ⚠️ 两颗是**不同尺度、不同用途的独立 2D 视图**，**不是一对立体相机**（见 0.5 节）。这个分工不冗余、有价值。

> 📌 **采购状态（2026-11-03 决策）**：GF100-A（车顶全局）已购；**GF100-B（眼在手）暂延后采购**。当前先只用 GF100-A + 机械臂本体，验证阶段 2 的「伪 3D 定位 + IK 逆解 + PWM 抓取」闭环——即车顶相机定位 + 底盘里程计移动逼近 + 机械臂按伪 3D 落点抓取，**暂不做眼在手精细确认**。待软件跑通、确认伪 3D / 视觉伺服够用后，再决定眼在手那颗买 **GF100（2D，¥66）** 还是 **短距深度相机（D405 7~50cm / Aurora930 30~300cm，真 RGB-D）**。延后期间，**手持 / 悬空物体的视觉伺服抓取（0.4.1）暂时做不到**，只能抓「已知高度承载面上的物体」（地面 / 桌面 / 台阶）——这是该决策的诚实后果，面试照实说。

## 0.2 能干的（2D 层面，真实可达 ✅）

| 能力 | 怎么实现 | 可靠性 | 说明 |
|---|---|---|---|
| **认出物体是什么** | YOLOv8 在 KunPeng 上推理（COCO 预训练含 cup/bottle/apple/orange/banana；tissue/egg 需自标 30~50 张微调） | 高 | 纯 2D 识别，GF100 完全够 |
| **小车全局搜索目标** | GF100-A 做颜色/轮廓/检测，没看到就转圈扫 + 小步前进 | 高 | 局部视觉搜索，不需地图 |
| **语音定向引导对准** | 「左前方」→ 底盘转向+前进，GF100-A 一看到目标就停 | 高 | 主模式，比自动搜索更稳 |
| **眼在手精细对准** | GF100-B 看目标质心是否居中、占画面比例是否够大 | 高 | 抓取前最后一道确认 |
| **估距离（伪 3D）** | 假设目标在**任意已知高度的水平承载面**上（地面 Z=0 / 台阶顶面 / 桌面），从检测框底边像素反推 | 中（误差 1~3cm） | 见 0.3 节，前提是「物体落在一个你知道高度的水平面」 |
| **算抓取点** | 机械臂关节角（正运动学）→ 末端位姿 + 伪 3D 坐标 → 逆解 IK | 中 | 依赖上面那条假设 |

**结论**：你那条「语音 → 小车找物 → 对准 → 眼在手确认 → 抓取 → 返回」的主链路，**靠双 GF100 + 机械臂正逆解 + 已知承载面高度（地面/台阶/桌面皆可），是能跑通演示的**。这是诚实可达的。

## 0.3 伪 3D 定位的原理与前提（必须讲清）

- **大白话**：相机不知道真实距离，但我们「提前知道物体脚下的那个面离地多高」——地面就是 0、台阶就是台阶高、桌面就是桌高——物体落在这个面上时，它在画面里的「底边位置」就唯一对应一个距离——像用影子长度估身高。注意：承载面**不必是桌子**，地面和台阶同样适用，关键是「高度已知」。
- **规范定义**：在相机内参已知、且物体支撑平面方程 $Z = Z_{plane}$（$Z_{plane}$ 为任意已知常数，地面取 0、台阶取台阶高、桌面取桌高）已知的前提下，检测框底边像素 $v_{bottom}$ 经针孔模型反投影可得物体到相机的水平距离 $d$。这是一种**单目深度估计的强先验特例**，误差来自像素量化 + 标定残差 + 承载面高度测量误差，典型 1~3cm。

**硬前提**：物体必须**乖乖放在一个你知道高度的平面上**。一旦不满足，下面 0.4 的硬边界就触发。

## 0.4 不能干的（硬边界 ❌，面试必说）

| 做不到的事 | 根因 | 后果 |
|---|---|---|
| **真 3D 距离/点云** | GF100 无深度通道 | 只能伪 3D，非真测距 |
| **物体悬空 / 手持 / 无承载面**（如你举着水瓶） | 伪 3D 先验失效（没有「已知高度的水平面」） | 距离估不准，但**抓取仍可靠「眼在手视觉伺服」完成**，见 0.4.1 |
| **透明玻璃杯 / 纯黑 / 强反光物体** | RGB 本身难认（透光/吸光），深度更无 | 识别漏检、抓取失败 |
| **任意未知物体通用抓取** | 无深度 → 抓握姿态（approach 方向、夹持宽度）难定 | 只能抓「已知类别+已知姿态」物体 |

> 这些是**物理/原理层面**的限制，不是「调参或换模型」能解决的。要突破必须加传感器或算法（见 0.6 / 0.7）。

### 0.4.1 特例：手持 / 悬空物体（如你举着水瓶）怎么抓

- **大白话**：伪 3D 那招要「物体底下有个你知道高度的平面」才能用；你手举着瓶子，瓶子底下是空气，没有平面，所以这招失效。但**抓瓶子根本不需要先知道它离地多高**——臂末端那颗眼在手相机只要一直盯着瓶子：瓶子偏左就往左挪、偏小就往前凑，等瓶子正好在画面正中、且占的画面大小刚好合适，夹爪一合就抓住了。这是一个「看着图像不断微调」的闭环，压根不依赖高度。
- **规范定义**：**视觉伺服（visual servoing，IBVS/PBVS）**——以图像特征（如目标质心像素坐标、检测框尺寸）作为反馈量，驱动机械臂直至特征达到期望值（质心居中 + 框尺寸达目标），无需已知物体绝对 3D 坐标。眼在手（eye-in-hand）配置下，相机随臂运动，特征误差直接映射为臂的修正动作。
- **结论**：手持/悬空物体 = 伪 3D 失效，但**抓取仍可达成**（依赖眼在手 GF100-B + 视觉伺服 + 末端 PWM 抓取）；真正缺的是「从远处精确测距 / 跨场景导航到它」的能力，那部分才需要深度相机或单目深度估计（0.6）。
- **透明瓶额外注意**：若水瓶是透明玻璃/塑料，RGB 本身难认（透光），YOLO 易漏检——这时伪 3D 和伺服都救不了，得换不透明瓶演示，或上深度相机（透明物对结构光也难，但对识别框至少不透光干扰小些）。

## 0.5 关键误区：两颗 RGB 摄像头 ≠ 自动有深度

**这是最容易想当然、也最该钉死的一点。**

真·立体视觉（stereo vision）成立需要**全部**满足：
1. 两路相机看**同一场景**、视场**重叠**；
2. 两相机间**基线（baseline）固定且已知**；
3. 采集**时间同步**；
4. 做**极线校正（epipolar rectification）+ 视差计算（disparity）**。

**你的布局不满足**：GF100-A 在车顶（全局、俯视），GF100-B 在臂末端（局部、随臂动）。两相机视场不重叠、基线随机械臂运动不断变化、没有同步采集——**它们构不成一个 stereo pair**，给不了深度。

> ✅ 正确认知：双 GF100 = 「全局找 + 局部对准」的**两级 2D 视图**；❌ 错误认知：双 GF100 = 「能算深度」。

（若真想要立体深度，得**另买两颗同规格相机固定成一组、基线锁死、视场重叠**专门做 stereo——这和当前「车+臂」分工是两套完全不同的装机方案，当前阶段不做。）

## 0.6 ¥0 补一半：单目深度估计（不买硬件也能做）

- **大白话**：用一颗 GF100 拍张照，喂给一个「会估深度」的神经网络，它吐一张粗糙的深度图——比「已知高度假设」鲁棒，至少能处理非标准高度的物体。
- **规范定义**：**单目深度估计（monocular depth estimation）** 用 CNN/ViT（如 MiDaS、Depth-Anything）从单张 RGB 回归相对深度图。KunPeng Pro（4 核 ARM / 16GB）可跑轻量版，**约 5~10fps、误差 cm~dm 级**。
- **价值**：零成本、能演示，且给你简历多一个「单目深度估计」亮点；**局限**：精度粗、是相对深度非绝对、算力吃紧。
- **定位**：这是「伪 3D 假设」和「真深度相机」之间的折中，演示够用，面试能讲清取舍。
