# 机械臂小车 + 语音：可行性与落地路线

> 定稿：2026-11-13。
> 对应底盘工程：`D:\简历\STM32项目\1.Smart car`（STM32F407ZE，Keil MDK，裸机大循环）。
> 对应机械臂工程：`RoboticArm_Kunpeng`（STM32F407VET6 + PCA9685 + KunPeng Pro）。
> 本文回答两个问题：① 能不能"说一句话就让它去把鸡蛋抓过来"；② 能不能像小智 AI 那样聊天。

---

## 一、先给结论（四条诉求，逐条判）

| 诉求 | 判定 | 真正卡在哪 | 工期 |
|---|---|---|---|
| 语音说"前进/后退/左转/右转/停"，车动 | ✅ **能** | 只要把蓝牙单字符协议换成统一帧 + 无线链路 | 2~3 天 |
| 语音说"抓取"，桌上机械臂去抓固定目标 | 🔶 **接近能** | 定位径向系统偏近 2.9cm（根因已定，修法未落地） | 3~5 天 |
| 语音说"正前方有鸡蛋，去抓过来放到指定位置" | ❌ **现在不能** | 底盘无编码器/无里程计 ⇒ "走过去"是开环定时（VL53L1X ToF 可兜住"接近"这一段，见 8.3）；软爪已有但**仍无任何力/位反馈** | 2~3 周 + 补 P0 硬件 |
| 语音聊天、自我介绍（小智 AI 那种） | ✅ **能，而且硬件正好** | 需要跑一个后端（ASR + LLM + TTS）；单麦无硬件回声消除 | 3~5 天 |

**一句话**：语音**控制**和语音**聊天**是两条技术路线，都能做；"鸡蛋"这个词里藏着一个**移动操作（mobile manipulation）**任务，那是另一量级的工程，现阶段的正确做法是**先把"固定位置抓取"做成，再谈"走过去抓"**。

## 二、底盘现状：读代码得出的硬事实

**先说概念。**
- **里程计（odometry）**：大白话——车自己"记账"，靠轮子转了多少圈推算自己走了多远、转到哪个方向；规范定义——通过对轮速积分递推位姿的航位推算方法（dead reckoning），误差随时间累积。
- **开环（open-loop）**：大白话——发完指令就不管结果，走没走够全靠"我猜"；规范定义——控制器不含被控量反馈的 control 结构，输出不受实际状态修正。

### 2.1 现在有什么

| 项 | 实现 | 位置 |
|---|---|---|
| 驱动 | L9110S 双 H 桥，TIM8 四通道 PWM，1kHz | `motor.c` |
| 运动 | 前进/后退/原地左转/原地右转/单轮转 | `motor.c` |
| 测距 | HC-SR04 超声波 + 舵机 45°/90°/135° 三向扫描 | `avoidance.c` |
| 避障 | 2 路红外（PE0/PE1）+ 超声阈值 25/35cm，7 态状态机 | `avoidance.c` |
| 循迹 | 4 路红外（PB8~PB11），阈值判黑/白 | `track.c` |
| 通信 | USART1 蓝牙 115200，**单字符协议** | `bluetooth.c` |
| 架构 | 裸机 `while(1)`，无 RTOS | `main.c` |

单字符协议就这几个：`1/2/3` 切模式，`4/5/6` 切速度，`F/B/L/R/S` 运动。

### 2.2 现在**没有**什么（这才是关键）

| 缺的东西 | 后果 |
|---|---|
| **编码器** | 不知道轮子转了多少 ⇒ 无里程计 |
| **IMU（陀螺仪/加速度计）** | 不知道车头朝向变了多少度 ⇒ 转弯角度不可控 |
| **PID 速度环** | PWM 占空比 = 指令，不是速度；电池掉压就跑偏 |
| **电流/堵转检测** | 撞到东西不知道，只能靠红外/超声看前面 |
| **任何位置反馈** | "走 50cm" 只能写 `delay(1200)`，实测误差 20~40% |

**这意味着**：底盘是一个**纯开环的平台**。它能做"看到障碍就绕"，但做不了"精确走到某个坐标"。这不是代码写得不好，是**没有传感器**。

> ⚠️ 另一个隐性瓶颈：L9110S 标称每通道 800mA 连续 / 1.5A 峰值，而你现在**每侧两个电机并联**。空载没事，一旦车体加重（装上机械臂），起步和爬坡会顶到上限。以后合体前要先量一下堵转电流。

### 2.3 两个 MCU 的关系

| | 底盘 | 机械臂 |
|---|---|---|
| 主控 | STM32F407**ZE** | STM32F407**VET6** |
| 执行器 | 4 个直流电机（L9110S） | 6 路舵机（PCA9685，I2C） |
| 系统 | 裸机大循环 | FreeRTOS 三任务 |
| 协议 | 单字符 | `$<CMD>[,ARGS]*<CK>\r\n` + XOR |

**建议不要合并固件。** 两块板各自干好自己的事，只把**帧协议统一**，由 ESP32 或鲲鹏当协调器。理由：机械臂固件里有 ORE 修复、软限位、斜坡，重烧有甩臂风险；底盘固件是另一套时序逻辑，混在一起会互相拖累。

## 三、把"鸡蛋任务"拆成 5 环，逐环判定

你原话："左前方有一枚鸡蛋，语音说正前方有一枚鸡蛋，去把它抓取过来并放在指定位置。"

这句话在机器人学里叫**移动操作（mobile manipulation）**，标准分解是 5 环。逐环看：

| # | 环节 | 现状 | 判定 | 说明 |
|---|---|---|---|---|
| 1 | **听懂句子** | `intent_parser` 已能抽 `action/target/qualifier` | 🔶 可做 | 但"左前方""正前方"是**相对车头**的空间指代，系统里没有"车头坐标系"，需要先定义 |
| 2 | **找到鸡蛋** | 眼在手相机视野 26cm 处约 **17×13cm** | ❌ 不够 | 这是"精定位相机"，不是"搜索相机"。要搜屋子得加车前广角相机 |
| 3 | **走过去** | 无编码器、无 IMU | ❌ 不能 | 只能定时前进，误差 20~40%，走 1 米可能差 30cm |
| 4 | **抓住** | J6 定角开合，无力反馈、无位置反馈 | ❌ 不能 | 见第四节 |
| 5 | **放到指定位置** | 臂在车上时基座随车移动 | 🔶 可做 | 每次移动后要重新定位目标（相机还在，能重看） |

**结论**：第 2、3、4 环是**硬件级缺口**，不是写代码能补的。所以"鸡蛋全流程"现在做不到，硬做只能演一次、失败率高。

### 3.1 但"视觉引导抓取"本身是可以的

如果把任务改成：**车停在固定位置，桌上放一个目标，语音说"抓取"→ 臂定位 → 抓 → 移到旁边指定格 → 松开**，那么 5 环里只剩第 4 环要解决，而第 4 环**换个对象就成立**。

| 目标物 | 可行性 | 原因 |
|---|---|---|
| 4cm 彩色积木 / 木块 | ✅ 好 | 平面、刚性、可夹、视觉好检 |
| 玩具彩蛋（硬塑料空心） | ✅ 好 | 球形但硬，夹不碎，摔了不心疼 |
| 海绵球 / 毛绒玩具 | ✅ 好 | 软的，夹紧力无所谓 |
| **真鸡蛋** | ❌ 差 | 见第四节 |

## 四、为什么"抓真鸡蛋"现在很难成功（三个硬数字，其中一条已按实物清单更正）

### 4.1 夹爪的力，天生不对

**概念（大白话）**：舵机"多大劲"是固定的，夹到东西时力有多大，取决于**夹爪摆臂多长**，跟东西软硬无关——它不会"感觉到疼就松手"。
**规范定义**：开环位置伺服驱动的平行夹爪，其夹持力由 `F = τ / r`（τ 为舵机堵转扭矩，r 为接触点到舵盘轴的力臂）决定，无 force feedback 时不具备力闭环。

J6 是 MG996R（约 10 kg·cm）。若接触点距轴 3cm：

```
F = 10 kg·cm / 3 cm ≈ 3.3 kgf
```

**蛋壳能承受的力就在几公斤这一档。** 也就是说：夹紧了碎，夹松了滑，而**中间没有任何传感器告诉你现在是哪一种**。

### 4.2 夹爪张口：⚠️ 本条已按实物清单更正

**更正（2026-11-13，核对 `已有硬件材料.xlsx`）**：原来按"两指平行爪、摆臂 3cm"算出最大张口 `2×3×sin45° ≈ 4.2cm`，与蛋短轴 4.2cm 正好相等 ⇒ 容错为零。**但库存里还有第二件末端：柔性软爪，张角 60mm、硅胶软指。** 换成它之后本条的结论要改：

| 末端 | 最大张口 | 对 4.2cm 短轴的余量 | 接触形式 |
|---|---|---|---|
| 平行两指爪（摆臂 3cm） | ≈4.2cm | **0** | 两点 |
| **柔性软爪（已有）** | **6.0cm** | **两侧各 9mm** | 面接触、可包络 |

软指会顺着蛋的曲面变形，把夹持力摊到一片面积上，而不是集中在两个点 ⇒ 单位面积的压强降一个量级，蛋壳不容易局部崩。

**所以"容错为零"这条不成立，撤回。** 但仍有两个限制：① 软指变形量有限，超行程照样硬顶；② 依旧**没有任何力反馈**，只能靠"目视 + 走一小段就停"控制。

### 4.3 定位的那 2.9cm，正好是"撞蛋"的距离

| 项 | 数值 |
|---|---|
| 定位链径向系统偏差 | **2.9cm**（三次独立测量，方向一致） |
| 蛋的半径 | 2.1~2.9cm |

爪尖会**正好落在蛋的侧面**，而不是上方。这不是"精度差一点"，是**会直接把蛋推倒**。

### 4.4 末端方案：按"已有"重排优先级（软爪先试，吸盘做 Plan B）

| 优先级 | 方案 | 成本 | 为什么有效 / 什么时候换 |
|---|---|---|---|
| **① 先试** | **柔性软爪（张角 60mm，已有）** | **¥0** | 面接触包络，把夹持力摊开；张口 6cm 对 4.2cm 蛋有两侧 9mm 余量 |
| ② 软爪不行就换 | 硅胶吸盘 + 微型真空泵 + 真空开关 | ~¥50 | 蛋表面光滑，吸盘天生适配；**真空开关给"吸住/没吸住"的二值反馈**，比力控简单一个量级 |
| ③ 不建议先做 | 加薄膜压力/ACS712 电流采样做力闭环 | ~¥30 | 仍是两点接触，蛋的曲面容易局部应力集中；且 ACS712 只有 5A 量程（见 8.3） |

**换判据（什么情况才值得买吸盘）**：软爪抓 5 次，**摔碎 ≥2 次或滑落 ≥2 次** ⇒ 直接上吸盘，别再调软爪。
**面试可讲**："我先用手上已有的柔性软爪，因为它的形变能包络曲面、把压强摊开；只有在实测失败率超过 40% 时才换真空吸盘——因为吸盘把'力控问题'降级成'真空通断'的二值判断，是更彻底的解法。"

## 五、语音聊天（小智 AI）：硬件正好，路是现成的

### 5.1 你的硬件 vs 小智 DIY 配置

| 小智需要 | 你有没有 | 说明 |
|---|---|---|
| ESP32-S3 + 8MB PSRAM | ✅ N16R8 成品板 | 完全够 |
| I2S 数字麦克风 | ✅ INMP441 | 小智 DIY 版用的就是它 |
| I2S 功放 + 喇叭 | ✅ MAX98357A + 3W | 一样 |
| Wi-Fi | ✅ | |
| **硬件回声消除（AEC）** | ❌ | 小智官方板用 ES8311+ES7210 做硬件 AEC；单麦只能软件 AEC，效果一般 |

**没有 AEC 的后果**：喇叭在放音时，麦克风会把自己的声音收进去 ⇒ 自己打断自己、或听不清你说话。

**解法（够演示）**：用**按住说话（push-to-talk）**或**按键唤醒**模式，播报时不采音。小智固件支持这种交互，这是最省事的绕过方式。

### 5.2 现成的两条路

| 路线 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A. 官方云** | 烧 `xiaozhi-esp32` 固件 → 连 `xiaozhi.me` 控制台配角色 | 半天能说话，不用自己搭后端 | 依赖公网；免费额度有限；演示时网络抖动就尴尬 |
| **B. 自建服务** | 烧同一份固件 → 连自建 `xiaozhi-esp32-server` | 全在自己手里，可接本地 ASR/TTS | 要跑 ASR（FunASR/SenseVoice）+ TTS（EdgeTTS）+ 一个 LLM Key |

**建议先 A 后 B**：先用官方云验证"能听能说"（半天），确认硬件链路没问题，再考虑自建。

### 5.3 关键：这条线和"控制"必须是**两条通道**

小智较新的版本支持 **MCP 工具调用**，理论上可以让 LLM 直接调"机器人前进"这类工具。但：

| 走云端 LLM 控制的三个风险 | 后果 |
|---|---|
| 延迟 1.5~3s | 说"停"，车还在走 |
| 断网 | 机器人直接瘫 |
| LLM 幻觉 | 可能生成超量程的关节指令 |

所以架构上必须**分开**，见下一节。

## 六、架构：快慢双通道 + 本地仲裁

```
                    ┌──────────────── ESP32-S3 ────────────────┐
                    │  INMP441 麦  →  音频缓冲  →  MAX98357A 喇叭 │
                    └───────┬───────────────────────▲──────────┘
            ①快通道（本地） │                       │ ②慢通道（云端）
              命令词识别     │                       │  Opus 流
              <300ms 离线    │                       │
                            ▼                       │
        ┌───────────────────────────────────────────────────────┐
        │              边缘协调器（KunPeng Pro）                 │
        │  ┌─────────────┐   ┌──────────────┐   ┌────────────┐  │
        │  │ 帧校验 XOR  │   │ 意图解析     │   │ 仲裁器     │  │
        │  │ 白名单      │──▶│ intent_parser│──▶│ 范围/净空  │  │
        │  └─────────────┘   └──────────────┘   │ 急停优先   │  │
        │        ▲                                └─────┬──────┘  │
        │        │  工具调用(仅"提议")                   │         │
        │  ┌─────┴──────┐                               │         │
        │  │ ASR→LLM→TTS│◀──────────────────────────────┘         │
        │  └────────────┘                                        │
        └───────────────────────┬───────────────────────────────┘
                                │ 统一帧 $<CMD>*<CK>
                 ┌──────────────┴──────────────┐
                 ▼                             ▼
        ┌─────────────────┐          ┌──────────────────┐
        │ 底盘 STM32F407ZE│          │ 机械臂 F407VET6  │
        │ 电机/超声/循迹  │          │ PCA9685 + 6 舵机 │
        └─────────────────┘          └──────────────────┘
```

### 为什么必须两条通道

| | 快通道（命令词） | 慢通道（聊天） |
|---|---|---|
| 时延 | <300ms | 1.5~3s |
| 依赖 | 全离线 | 要网、要 Key |
| 用途 | **所有会动的动作** | 闲聊、自我介绍、复杂指代 |
| 失败后果 | 可接受（没听懂就重说） | 无（说错话而已） |

**一句话原则：会动的东西走本地，会说话的东西走云端。LLM 只能"提议动作"，本地仲裁器才有"授权动作"的权力。**

这条原则是能写进简历的架构判断，比"我把语音接上了"值钱得多。

## 七、分阶段落地（每阶段都有硬验收）

> 顺序刻意如此：先把**不依赖新硬件**的部分做完，每一步都能独立演示。

| 阶段 | 做什么 | 验收判据 | 工期 | 要先花钱吗 |
|---|---|---|---|---|
| **A** | 底盘接统一帧：`$CAR,FWD,800*CK` 这类帧解析（替代单字符）；ESP32/鲲鹏通过 UART/WiFi 下发 | 发一帧 `$CAR,FWD,800`，车前进 0.8s 停；`$CAR,STOP` 立即停 | 2~3 天 | **¥0**（清单已够） |
| **B** | 语音命令词控车（前进/后退/左转/右转/停/抓取） | 说 20 次，成功 ≥17 次（85%）；10 分钟内误唤醒 ≤1 次 | 2~3 天 | **¥0** |
| **C** | **修定位径向 2.9cm**，桌上抓取替代物 | 4cm 积木：定位→抓→放到指定格，10 次成功 ≥7 次 | 3~5 天 | **¥0** |
| **D** | 小智聊天（独立固件先跑通） | 唤醒→问"你能干什么"→2 秒内开始说话；连续 5 轮不崩 | 3~5 天 | **¥0** |
| **E** | 把 D 的角色人设写成"机械臂小车助手"，支持一句自我介绍 | 语音问"你是什么"，回答里包含项目定位（视觉引导执行 + 语音入口 + 可观测性） | 0.5 天 | **¥0** |
| **F1** | 车臂合体第一步：舵机独立供电 + 铝板固定 + **ToF 接近闭环**（先不买编码器） | 车前进到距桌 25±3cm 自动停；臂在原位抓取不抖 | 3~5 天 | P1 ≈¥60（铝板 + 急停） |
| **F2** | 补 P0：37 编码电机 + 2×TB6612，做短距增量 + 麦轮四轮独立 | 直行 1m 横向偏差 ≤5cm；原地转 90° 误差 ≤5° | 1~2 周 | P0 ≈¥206 |
| **F3** | 📋 端到端：语音 → 走 → 抓 → 放到指定位置 | 10 次成功 ≥5 次（含蛋） | 视 F1/F2 | P2 ≈¥50~110 |

**注**：A~E 五阶段**一件新硬件都不用买**，全部可以用现有清单跑完。这也是建议的推进顺序——先拿到"能演示"，再决定要不要为 F 阶段掏钱。


**建议先做 A + B**：这两步做完，"语音指挥小车"就能演示了，而且完全不碰机械臂，风险最低。

**C 要排在 B 之后**：因为 C 的前置是修那 2.9cm，属于"精度活"，容易卡。

## 七·补、端到端具身智能目标场景与分期（2026-11-21 定稿）

> 本段是第七节"北星目标"的细化：用户口述了最终想要的完整场景，据此把路线

### 三条技术选型（2026-11-21 定）

1. **不采用 ESP-SR 命令词**：完整路线走云端 ASR（SenseVoice）+ LLM/VLM 规划器；
   ESP-SR 的本地 WakeNet/命令词与本路线重叠且价值低，砍掉（已 `add-dependency`
   写进构建副本的 manifest 作废，不影响仓库）。
2. **不采用 OpenVLA（端到端 VLA）**：它输出特定机械臂的连续末端增量，需 GPU 实时
   推理 + 遥操作数据微调，且与「离散原语 + 白名单 + 本地仲裁」的安全架构冲突。
   本项目采用业界主流的**「LLM/VLM 规划器 + 原语 + 仲裁」混合路线**。
3. **ACS712 由总线舵机负载反馈替代**：总线舵机（LX-224HV / HTS-35H / HTD-45H）
   协议自带负载/电流/电压/温度回读，限力夹持与重量估算改用该反馈，省一路 ADC
   接线。旧 ACS712-5A 限力夹持方案作废（5A 量程本就不适配舵机母线，见红线 6）。

### 8.3 库存里三条"白捡"的（不用另买）

1. **20A DC-DC 降压 = 舵机独立供电**。原清单第一条"6V / ≥10A UBEC"是硬门槛，这模块（1.2~35V 可调 / 20A）直接顶掉：7.4V 进 → 6.0V 出，压差 1.4V 余量足够。再并 3 只 2200µF（合计 6600µF）做母线储能，吸收六路同时启动的浪涌。
2. **200W 升压 = 鲲鹏 12V 供电**。鲲鹏要 12V，而 2S(7.4V)/3S(11.1V) 都不到 12V，必须升压；这模块 6~35V 输入、200W 输出，带 24W 的鲲鹏很轻松。
3. **VL53L1X ToF = 唯一的"接近"闭环**。4m 量程、I2C 直读，比超声准、比视觉快。**"走到桌前 25cm 停"这一步可以真闭环，完全不依赖编码器** —— 这是本次盘点最有价值的一条：它把"走过去"从"必须先买编码器"降级成"可以用 ToF 顶着先做，编码器后补"。

### 8.4 四条从清单里看出来的隐患

**① 麦克纳姆轮 + L9110S 是矛盾的。** 麦轮要横移必须四个轮子独立调速，而 L9110S 只有两路、左右各自并联 ⇒ 实际只能差速。要么接受"麦轮当普通轮用"（白买麦轮），要么按 8.2 换 2× TB6612 拿回四路独立。

**② TT 电机额定电压对不上电池。** 套件里的 TT 电机额定 3~6V，而 18650 组是 7.4V(2S) / 11.1V(3S)。直连 11.1V 会烧。所以电机轨要么单独降到 6V，要么只走 2S + PWM 限幅。

**③ 麦轮打滑会毁掉里程计。** 麦轮靠 45° 辊子侧向滚动，效率低、极易打滑，用它算里程的误差比普通轮大得多。所以正确策略是：**编码器只做"短距离增量"，绝对位置交给 ToF + RC522（地面/桌面贴标签）** —— RC522 那套正好能把"指定位置"变成"读到卡就停"，绕开里程计。

**④ 3.5" TFT 别装车。** 原子 3.5 寸电阻屏是 16 位 8080 并口（要 FSMC），会占掉 PB/PD/PE 一大片引脚，和电机 PWM、4 路红外、循迹直接冲突。留给台面调试，或改用 SPI 小屏。

### 8.5 建议的电源树

```
2S2P 18650（4×3000mAh 10C 两并两串，7.4V / 6000mAh / 30A 连续）
├─ 直供 L9110S / TB6612 → 4× 电机（PWM 限到 80%，等效 6V）
├─ 20A 降压 → 6.0V ─┬─ 舵机母线（4×25KG + 2×MG996R，堵转峰值 ≈15A）
│                   └─ 3×2200µF 并联就近去耦
├─ 200W 升压 → 12V → 鲲鹏 Pro（≈2A / 24W）
└─ LM2596 → 5V → STM32 / ESP32-S3 / 传感器
```

功率核对：舵机 15A×6V=90W（仅堵转瞬间）+ 电机 15W + 鲲鹏 24W + 逻辑 5W ≈ 134W ⇒ 7.4V 侧约 18A，留 40% 余量。**演示时避免六轴同时堵转**，否则会贴到 30A 上限。

## 十、红线

1. **不许把"语音控制"写成"语音理解"**。命令词识别是分类，不是听懂句子。
2. **LLM 不得直连执行器**。必须有本地校验（量程、净空、急停优先级），否则一次幻觉就是一次撞机。
3. **不许用"鸡蛋"当第一个验收对象**。先用 4cm 积木/玩具彩蛋把链路跑通；蛋是最后一步，末端先用已有的柔性软爪（60mm），摔碎/滑落 ≥2/5 次才换吸盘。
4. **合体前必须做电源改造**。舵机独立 6V（20A 降压 + 6600µF）+ 电机轨限压 6V，这是唯一会造成硬件损坏的一条。
5. **任何"走过去"的表述都要带条件**："固定起点 + 固定时长"或"ToF 到 25cm 停"，不许写"自动导航 / 自动建图"。
6. **ACS712 是 5A 量程**，不许串在舵机母线上（峰值 15A 会饱和甚至烧采样电阻），只能测单路或电机支路。
