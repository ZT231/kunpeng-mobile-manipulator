# 机械臂：总线舵机接线与 `$ARM` 命令

> 定稿 2026-11-26。对应固件 `Core/Src/servo_bus.c`（帧与舵机个体）+ `Core/Src/arm_robot.c`（整臂控制层），
> 已加入 `MDK-ARM/RoboticArm_Kunpeng.uvprojx` 的 `Application/User/Core` 分组，Rebuild 实测 **0 Error / 0 Warning**。

## 一、这套代码到底接在哪

| 项 | 值 |
|---|---|
| 主机串口 | **USART3：PB10 = TX、PB11 = RX**，AF7，**115200 8N1**，无流控 |
| 为什么是 USART3 | 2026-11-26 起把「预留第三控制源」取消（`wifi.c/h` 已删除）。USART6(PC6/PC7) 被编码器 C 占用；UART5(PC12/PD2) 是板载 SD 卡座的 SDIO_CK/CMD，排针未引出 |
| 转接板 | **Waveshare Bus Servo Adapter (A)**，拨到 **A 档（UART~SERVO）**，板内完成 UART↔单线总线的方向切换 |
| 方向脚 DE | **不需要**。`servo_bus.h` 里原 PB1 的 DE 预留已删除（PB1 与本板 TFT 背光 LCD_BL 同名） |
| 收发方式 | **阻塞式**（`HAL_UART_Transmit` / `HAL_UART_Receive`），**不注册中断、不进 uart_protocol.c** |

## 二、物理接线（先接线，再上电）

1. **断掉所有电源**（电池盒拔掉、USB 拔掉）。
2. 转接板拨码开关拨到 **A 位**（丝印 `UART~SERVO`）；拨错到 B 位就是 USB 模式，STM32 发什么都没反应。
3. 主机侧三根信号线（交叉接，丝印同名不是对接同名）：
   - STM32 **PB10（USART3_TX）** → 转接板 **RX**
   - STM32 **PB11（USART3_RX）** → 转接板 **TX**
   - STM32 **GND** → 转接板 **GND**（必须共地，否则帧全乱）
4. 舵机电源：**11.2V 母线**（4S 18650 经降压模块，限流 3A 起）接转接板的舵机电源输入，
   转接板 GND 与 STM32 GND 共用星点。**严禁**从 TB6612 的 5V/3.3V 针取电给舵机。
5. 舵机总线：六颗舵机 SIG 单线首尾级联，链首接转接板的 SERVO 口；每颗舵机 ID 已设 1~6
   （J1=1 HTS-35H / J2=2 HTD-45H / J3=3、J4=4、J6=6 LX-224HV / J5=5 HTS-20H）。
6. 上电顺序：**先 STM32（USB/ST-Link 供电）→ 再舵机 11.2V 母线**。断电相反。
   带电插拔总线会打火，容易打坏舵机通信口。

## 三、命令一览（走 USART1，与底盘 `$CAR,...` 同一套帧）

帧格式 `$ARM,<子命令>[,参数...]*<CK>\r\n`，CK = `$` 与 `*` 之间所有字节 XOR 的 2 位大写 HEX。
位置单位是**舵机原始位置 0~1000**（0~240°，1 单位 = 0.24°），不是角度；角度换算在鲲鹏侧 `arm_params.json`。

| 命令 | 作用 | 回帧 |
|---|---|---|
| `$ARM,READ` | 读六轴当前位置 | `$OK,POS,p1,p2,p3,p4,p5,p6` |
| `$ARM,POS,460,514,516,502,494,674` | 六轴同步移动（默认 800ms） | `$OK,ARM,POS,800` |
| `$ARM,POS,...,...,...,...,...,...,1500` | 同上，末位给运动时间 ms | `$OK,ARM,POS,1500` |
| `$ARM,J,6,300,600` | 单轴：J6 到 300（张开）用时 600ms | `$OK,ARM,J,6,600` |
| `$ARM,STOP` | 六轴原地停 + 撤销未执行作业 | `$OK,ARM,STOP` |
| `$ARM,RESUME` | 解除 STOP 的暂停 | `$OK,ARM,RESUME` |
| `$ARM,HOME` | 六轴回零位（460/514/516/502/494/674） | `$OK,ARM,HOME,1000` |
| `$ARM,TEMP` | 读六轴温度（阻塞 6 次查询，约 50ms） | `$OK,TEMP,t1,...,t6`（℃） |
| `$ARM,VIN` | 读六轴母线电压（同上；J6 用于堵转判握力） | `$OK,VIN,mv1,...,mv6`（mV） |
| `$ARM,CLRFAULT` | 清过温锁停 | `$OK,ARM,CLR` |

错误码沿用统一口径：`1` 帧/校验错、`2` 未知命令、`3` 参数错、**`4` 状态禁止（上一条运动还没走完）**、`5` 设备故障（舵机应答不上/过温锁停）。

## 四、两条设计约束（必须知道，否则会误判成 bug）

1. **运动是异步的**。`POS/J/HOME` 只把作业投进邮箱、立刻回 `OK`，真正下发由 `ArmTask`（10ms，优先级低于底盘）执行。
   所以：`OK` 只代表**已受理**，不代表已到位；到位要看 `$ARM,READ` 读数。
   同一时刻只受理一条运动：`ArmTask` 正在下发那一刻（毫秒级）再发运动命令会回 `$ERR,4`。
   ⚠️ **但排队窗口只有下发那几毫秒**：一旦 6 帧发完、`ArmTask` 已返回，舵机还在按 `ms` 自己爬坡，
   这时再发 `$ARM,POS`/`$ARM,J` 会被**接受并覆盖**在途斜坡（舵机从当前位置重新规划，不会跳变）。
   要真正中止在途运动，用 `$ARM,STOP`（给六轴发 MOVE_STOP 原地停）；接着发 `$ARM,RESUME`
   （MOVE_START）会从停下的位置继续走完剩余行程。上位机点动/滑杆连发就利用了这个“覆盖”特性。
2. **J5 慢**。J5（HTS-20H）实测背隙 3.6°（15 单位），`$ARM,J,5,...` 会走「越过目标 24 单位 → 停 150ms → 反向慢速逼近」两段式，
   耗时约等于 `时间参数 + 350ms`；六轴 `$ARM,POS` 不做背隙补偿（保证多轴同步），J5 要精确到位就单独发 J5 命令。

## 五、首次联调 checklist（按顺序做，每步都有判据）

1. **只接 PC、不接 STM32**：转接板拨 B 位插 USB，用 `D:\简历\STM32项目\4.ESP32-S3项目\工具\servo_acceptance\servo_check.py` 跑 `--cmd scan`，
   应看到 `ID 1~6 在线`。这一步验的是舵机和转接板本身，跟固件无关。
2. **改回 A 位、接好三根线**，STM32 烧录最新固件，USART1（115200 8N1）开串口助手。
3. 发 `$PING*10`，应回 `$OK,PONG*xx`（底盘链路先通）。
4. 发 `$ARM,READ`：六个数应接近 **460 / 514 / 516 / 502 / 494 / 674**（±10 以内）。
   回 `$ERR,5` = 有舵机没应答 → 查 A 位、TX/RX 是否交叉、GND 是否共地、波特率是否 115200。
5. 发 `$ARM,J,6,300,800`，夹爪应张开；再发 `$ARM,J,6,674,800`，应闭合。J6 软限位就是 300~674，越界自动钳住。
6. 发 `$ARM,HOME`，整臂应回到面朝正前、垂直桌面的姿态（就是定零位时的姿态）。
7. 发 `$ARM,STOP`，运动中应立刻停住。

## 六、与鲲鹏侧的对应关系

- 固件只认**原始位置**（0~1000）；`kunpeng/robot/arm_params.json` 里的 `pos_zero`（460/514/516/502/494/674）与 `dir`（J1~J6 = **+1/-1/+1/+1/-1/-1**）负责把「关节角」换算成这个原始位置。
- 改零位 = 同时改两处：`servo_bus.h` 的 `SB_HOME_POS_LIST` 与 `arm_params.json` 的 `joints[*].pos_zero`，否则上位机算出来的目标和固件认为的零位对不上。
- 夹爪按位置堵转判握力：先 `$ARM,J,6,<目标>,<较长时间>` 慢闭，再用 `$ARM,VIN` 看母线电压是否被拉低（堵转瞬间电压跌落）。
  这就是原来 ACS712 那套电流判握力的替代方案，总线舵机自带电压回读，不需要外挂传感器。

## 七、已知限制

- `$ARM,TEMP` / `$ARM,VIN` 是 6 次阻塞查询，最长约 50ms 占住协议任务；底盘 20ms 节拍会因为 dt 自测量而补偿，不会失控，但别把它当高频命令刷。
- 过温保护：≥80℃ 锁停，回落到 <55℃ 并保持 30s 才能 `$ARM,CLRFAULT`；`SB_T_WRITE_LIMIT=70` 是写进舵机内部的永久阈值，**不要随便改**。
- 软限位目前只做驱动层钳位（10~990，J6 另有 300~674），没有写进舵机内部 EEPROM；换成新结构后必须按实测重新收紧。
