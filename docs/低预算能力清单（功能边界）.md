# 低预算能力清单（功能边界）

> 用途：把「不花大价钱的前提下，这个项目到底能做到什么程度」定死。以后任何"这个功能能不能做"的问题，查这张表，不用反复纠结。
>
> 素材来源：幻尔 LanderPi 官方功能页 18 张（2026-11-03 用户提供截图）+ 幻尔官方 wiki 规格表（已联网核实）。

---

## 一、一句话结论

**这套宣传页里约 2/3 的功能，用手上已有的硬件 + 开源算法零成本就能做；剩下 1/3 卡在两件硬件上——"近距深度相机"和"激光雷达"，而后者是有意放弃的。**

真正的分水岭**不是"有没有 AI 大模型"**（那只是调 API，你已经有通道），而是：

> **相机能不能在 0.2~0.3m 给出有效深度数据。**

---

## 二、关键发现：幻尔那颗相机不是 Astra Pro（这条决定了一半结论）

用户之前考虑过 ¥177 的二手 Astra Pro。对照官方规格后可以明确：**幻尔配的是 Aurora930 Pro，跟 Astra Pro 完全不是一个量程段。**

| 参数 | 幻尔 **Aurora930 Pro** | Orbbec **Astra Pro** | 结论 |
|---|---|---|---|
| 工作距离 | **15 – 300 cm** | 60 – 800 cm | Aurora 覆盖近距 |
| 0.28m 处 | 正常出深度 | **盲区，深度图全黑** | 决定性差异 |
| 尺寸 / 重量 | 76.5×20.7×21.8 mm / 轻 | 164.85×48.25×30 mm / **310g** | Aurora 可上臂端 |
| 深度精度 | 3mm@0.5m、7~8mm@1m | 官方 ±1~3mm@1m | 同量级 |
| 深度分辨率/帧率 | 640×400 @ 5~15fps | 640×480 @ **30fps** | Astra 更流畅 |
| 视场角 | H71° × V46° | H58.4° × V45.5° | Aurora 更宽 |
| 接口 / 供电 | USB2.0 / 5V 1.5A、<1.6W | USB2.0 / <2.4W | 相当 |
| 支持系统 | Linux / ARMv8 / ROS / Win / Android | Ubuntu arm64 为主 | 未知，需核实 |

### 为什么这个差别是致命的

宣传页上那几张「3D 抓取」图，深度数值标的是 **279 / 291 / 313 / 315 mm**——全部落在 **0.28~0.32m**。

- 这正是 Aurora930 的**舒适区**（15cm 起）；
- 却是 Astra Pro 的**盲区**（60cm 起才有数据）。

**所以**：¥177 的二手 Astra Pro **复刻不了**图上那种"在手边 30cm 处做 3D 抓取"的演示。它只能装在车顶，看 **0.8m 以外**的工作区，做粗定位 / 点云入门 / 讲结构光原理——这个定位没变。

> 一句话：**同一句"这台能 3D 抓取"，取决于相机装多远。幻尔是"贴着物体看"，Astra Pro 是"隔着桌子看"。**

## 三、18 项宣传功能逐条对照

### 3.1 零成本可做（10 项）——已有硬件 + 开源算法

| 宣传功能 | 靠什么实现 | 现有基础 | 备注 |
|---|---|---|---|
| YOLOv8 识别水杯/苹果/绿植 | YOLOv8n（COCO 预训练） | 待写推理脚本 | **COCO 自带 cup/bottle/apple/orange/potted plant**，开箱可用 |
| KCF 目标追踪 | OpenCV `cv2.TrackerKCF` | `a_vision_demo.py` 已含 | 已实现，含降级保护 |
| MediaPipe 手势/骨架/人脸 | MediaPipe（pip 装） | 无 | 纯 RGB，KunPeng 上可跑 |
| 文本大模型问答 | 云端 LLM API | IoT 栈 + LLM 通道已有 | **幻尔也是"实时接入阿里云"**，同一条路 |
| 语音大模型对话 | ESP32-S3 小智固件 + 云端 ASR/TTS | 已有方案 | 端侧唤醒 + 云侧理解 |
| 视觉大模型场景理解 | VLM API（传图问话） | LLM 通道复用 | 慢（1~3s），适合"下指令前先看一眼" |
| 相机第一视角回传 | MJPEG 推流 / WebRTC | Web UI 可做 | 已有 IoT/Grafana 栈，加一路视频不难 |
| 手机 App / 网页控制 | Flask/FastAPI + 前端 | KunPeng 上做 Web UI | 零成本，比 App 更快出效果 |
| 逆解 IK 抓取（伪 3D） | 自写 IK + 已知承载面高度（地面 Z=0 / 台阶 / 桌面）反推距离 | `kunpeng/robot/arm_ik.py` | **A 档核心**，见第四节 |
| 色块分拣 | HSV 颜色分割 + 轮廓 | `kunpeng/vision/a_vision_demo.py` | 现状能力，cm 级 |

### 3.2 加钱可做（4 项）——卡在"近距深度"

| 宣传功能 | 硬性依赖 | 缺什么 | 成本 |
|---|---|---|---|
| 点云可视化 | 有效深度图 | 近距深度相机 | ¥177 起（但 Astra Pro 只到 0.6m 外） |

## 四、你真正想要的「抓水杯/纸巾/鸡蛋」——缺的不是相机

拆成三层看，每层卡的东西不一样：

### 第 1 层：认出它是什么 → 换检测引擎（¥0）

旧版 `detector.py`（已移除）是 **HSV 颜色 + 形状分类**，只认红/绿/蓝/黄的圆/方/三角积木，水杯/纸巾/鸡蛋全部失识别——不是相机不行，是方法不行；现状已换 `kunpeng/vision/stage1_yolov8.py` 的 YOLOv8n（COCO 预训练自带 cup/bottle/apple）。

换 **YOLOv8** 后：

| 目标物 | COCO 预训练直接有？ | 要做什么 |
|---|---|---|
| 水杯（马克杯/纸杯） | ✅ `cup` 类 | 直接用 |
| 瓶子/罐头 | ✅ `bottle` 类 | 直接用 |
| 苹果/橘子/香蕉 | ✅ `apple`/`orange`/`banana` | 直接用 |
| 盆栽（绿植） | ✅ `potted plant` | 直接用 |
| **纸巾 / 纸巾盒** | ❌ 没有该类 | **需自己标注 30~50 张微调** |
| **鸡蛋** | ❌ 没有该类 | **需自己标注微调**（且白色小目标，难度偏高） |

> 这就是"想要抓大部分物体"的真实成本：**不是买相机，是花半天标数据 + 训一次模型**（笔记本就能训，免费）。

### 第 2 层：知道它在哪 → 伪 3D 或深度（¥0 / 加钱）

- **伪 3D（¥0）**：假设目标落在一个**已知高度的水平承载面**上（地面 Z=0 / 台阶顶面 / 桌面皆可），用"检测框底边在画面里的像素高度"反推距离。对水杯/盒子这类**有明确底面**的物体够用，误差 1~3cm。注意：承载面不必是桌子，地面和台阶同样适用，关键是高度已知。
- **真深度（要钱）**：0.2~0.3m 有效才行，见 3.2。

### 第 3 层：抓得住不捏碎 → 夹爪才是瓶颈（¥0~几十）

**这一层最容易被忽略，但对"鸡蛋/纸巾"是决定性的。**

- 大白话：现在的 PWM 舵机夹爪只知道"合到第几度"，**不知道夹了多大劲**。就像你用两根手指夹鸡蛋还蒙着眼——角度到了就停，蛋早就碎了。
- 规范：舵机是**开环位置控制**，无电流/力矩反馈，无法实现 force control（力控）。抓取脆性物体需要**阻抗控制/力闭环**，或退一步用**被动柔顺**（软硅胶垫 + 限位 + 低速闭合）。
- 工程解法（不花钱）：
  1. 夹爪内侧贴 **2~3mm 硅胶/海绵垫**（分散压强）；
  2. **降速闭合**（PWM 分段逼近，最后 20% 用 50ms 小步）；
  3. **限位角**：按目标尺寸预设"合到还剩 5mm 就停"，靠摩擦提起而不是靠夹紧；
  4. 纸巾这种**别夹，改用"铲/拖"**（从底部插入再抬）；
  5. **电流检测（低成本力上限）**：在舵机动力电源串 **INA219**（¥10~30），F407 经 I2C 读电流；舵机夹到物体堵转时电流会"噌"地飙升，超过安全阈值即停下发——这是无需力传感器的"接触即停"，与硅胶垫+降速组合后，PWM 开环舵机也能做到"按物体调力度"。总线舵机方案（STS3215）则直接回读 load/current，力反馈等于白送（见 `精度目标与硬件升级路径.md` 方案 A）。

## 五、宣传页的 3 处水分（面试被追问时用得上）

1. **"毫秒级实时推理"**：YOLOv8n 在树莓派 5 上实测约 **10~20fps（50~100ms/帧）**。"毫秒级"字面没错（不是秒级），但别理解成 1ms；且多半是 640×400 输入 + 跳帧。
2. **"毫米级精度的动态手势交互"**：指的是**手指关键点在图像里的像素位置**精度，不是三维空间定位精度。说成"像素级"更诚实。
3. **"三维空间任意物品抓取"**：实际是"**已训练的几类物体 + 承载面高度已知（地面/台阶/桌面）**"。真"任意物体 + 任意高度"要通用抓取算法（6-DoF grasp detection，如 GraspNet），那是另一个量级的工程。
