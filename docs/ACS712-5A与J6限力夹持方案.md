## 一、概念先讲清（大白话 + 规范定义）

| 概念 | 大白话 | 规范定义 |
|---|---|---|
| ACS712 | 一根电线从它中间穿过去，它就能「感觉」流过多少电流，输出一个电压；电线和测量电路不直接连 | Allegro ACS712，基于**霍尔效应**的线性电流传感器；内置导体与信号侧 galvanic isolation（约 2.1 kV RMS），输出与电流成比例的模拟电压 |
| 5A 量程 | 这个型号最多能测 ±5A，超了就「顶到头」读不准 | ACS712**ELCTR-05B**：灵敏度 `185 mV/A`，量程 ±5 A，带宽 80 kHz |
| ADC | 把「电压」翻译成「数字」的翻译器，单片机只认数字 | STM32F407 逐次逼近型 12 位 ADC；`VREF+ = 3.3 V` ⇒ 1 LSB ≈ `3.3/4095 = 0.806 mV` |
| 规则通道 / 注入通道 | 规则通道是「排队一个个测」；注入通道是「插队，来了先测它」 | ADC regular group（可被 DMA 搬运，本项目 6 路电位器在用）vs injected group（优先级更高，独立结果寄存器 `JDRx`，可中断读） |
| 舵机 PWM | 不是给电机通断，而是每 20ms 发一个「去第几度」的脉冲 | MG996R：50 Hz、脉宽 500~2500 µs 对应角度；内部自带电位器做**位置闭环** |
| 堵转 | 舵机被东西卡住、转不动了，还拼命使劲 ⇒ 电流猛涨 | DC 电机稳态 `I ≈ τ/(K_t)`，堵转时反电动势为 0，电流升到 stall current（MG996R @6V 约 **2.5 A**） |
| 力控 vs 限力保护 | 「一直保持 1 牛顿」很难；「劲儿一大就松手」容易 | 前者 = force control / impedance control（需力传感器或力矩观测器）；后者 = current-threshold contact detection，本项目只能做到后者 |
| 滑动平均 | 把最近十几个读数取平均，把抖动抹平 | moving average filter，抑制零均值噪声；窗口越大越稳、反应越慢 |

## 二、硬件怎么接（🔴 唯一必须遵守的一条：只串 J6 单路）

### 2.1 红线

`docs/机械臂小车+语音-可行性与落地路线.md` **8.7 第 6 条**（原文）：
> **ACS712 是 5A 量程**，不许串在舵机母线上（峰值 15A 会饱和甚至烧采样电阻），只能测单路或电机支路。

六路舵机同时启动峰值可达 ~15 A。串母线 ⇒ 饱和 + 采样电阻过热 + 其他关节动作污染 J6 读数。**必须把 J6 的 6V 供电单独引一路。**

### 2.2 接线图

```
6V 舵机母线（20A 降压 1.2~35V → 6.0V，并 3×2200µF = 6600µF）
   │
   ├──────────────────────── J1~J5 舵机 VCC（直接接，不测）
   │
   └── ACS712 IP+ ──[ ACS712 模块 ]── IP- ────── J6 舵机 VCC   ← 只串这一路
                          │
                          ├── VCC  ← 5V（独立 5V 轨 / USB 5V，别从 3.3V 取）
                          ├── GND  ── 星型汇合到 6V 电源 GND（信号地）
                          └── OUT  ── 1kΩ ── PA6 (ADC1_IN6) ── 0.1µF ── GND
                                              └─ RC 低通，抗舵机 PWM 脉动

J6 PWM 信号：仍来自 PCA9685A 通道 5（I2C1 = PB6/PB7），一根线都不用改
J6 GND    ：直接回 6V 母线 GND
```

**四根线各管什么（别接错）**：
- `IP+ / IP-` 是**功率侧**端子，串在 J6 的 6V 正极里（电流方向 IP+→IP-，输出高于 2.5V）；
- `VCC / GND` 是**信号侧**供电与参考地，必须与 STM32 **共地**（项目老规矩：地星型汇合）；
- `OUT` 是模拟电压，进 MCU ADC；
- 🔴 ACS712 模块 **VCC 必须 5V**（datasheet 4.5~5.5 V），**不能接 3.3V**（不工作），而 OUT 的最高 3.425V 对 STM32 ADC 引脚是安全的（绝对最大 `VDDA+0.3 ≈ 3.6V`）。

### 2.3 为什么「只测 J6」时**不用分压**（量化核算）

ACS712-05B 输出：`Vout = 2.5 V + 0.185 V/A × I`（零电流 = VCC/2 = 2.5 V）

| 电流 | Vout | 3.3V ADC 能不能读 |
|---|---|---|
| 0 A（静止） | 2.500 V | ✅ 读数 ≈ 3102 |
| 0.8 A（接触阈值起点） | 2.648 V | ✅ |
| **2.5 A（MG996R 堵转）** | **2.963 V** | ✅ **在量程内** |
| 5 A（满量程） | 3.425 V | ⚠️ **削顶到 4095**（超 3.3V），但引脚不损坏 |

⇒ 只测 J6 单路（工作电流 ≤2.5 A）时，**OUT 可以直接进 PA6**，不必加电阻分压；加 `1kΩ + 0.1µF` 做 RC 滤波即可（若想留满 5A 余量，再并一个 2:1 分压，软件按分压比还原）。

**分辨率**：`0.806 mV / 185 mV/A ≈ 4.4 mA/LSB`（理论）；ACS712 输出噪声典型几十 mV ⇒ 实际有效分辨率约 **±0.1 A**，靠滑动平均压下去。

🔴 **零偏不能写死 2.5V**：ACS712 零偏有 ±20 mV 量级误差（折算 ±0.11 A），且随温度漂。上电、J6 不动时**实测 100 次取平均**当 `I_offset`，后面全部用 `I = (ADC − offset)` 相对量。

## 三、`.ioc` 现状与 A 方案为什么不用改它

`RoboticArm_Kunpeng.ioc` 里已经写死：

```
ADC1.NbrOfConversion=6                    # 六路电位器
ADC1.Channel-1~6 = ADC_CHANNEL_0~5        # PA0~PA5
ADC1.ContinuousConvMode=ENABLE
ADC1.DMAContinuousRequests=ENABLE
Dma.ADC1.0.Instance=DMA2_Stream0  (CIRCULAR)
ADC1.InjNumberOfConversion=0              # ← 注入通道「没配」，不是「不能用」
```

**A 方案做法**（纯用户代码，`Core/Src/` 里新增，不碰 CubeMX 生成段）：

1. `MX_GPIO_Init()` 之后把 **PA6** 配成 `GPIO_MODE_ANALOG`（PA0~PA5 已被生成代码配好，别动）；
2. 用 `HAL_ADCEx_InjectedConfigChannel(&hadc1, &sConfigInjected)` 把 **ADC_CHANNEL_6** 加进注入组；
3. 软件触发 `HAL_ADCEx_InjectedStart_IT(&hadc1)`，在 `HAL_ADCEx_InjectedConvCpltCallback()` 里 `HAL_ADCEx_InjectedGetValue()` 读值；
4. 规则组（6 路电位器 + DMA）**照常跑**，注入转换优先级更高、用独立 `JDR1` 寄存器，两者不抢。

✅ 不改 `.ioc`、不 Generate Code、**不重烧甩臂**、不影响已验收的电位器手动模式、¥0。
⚠️ 代价：`HAL_ADCEx_Injected*` 这套 API 比普通 `HAL_ADC_PollForConversion` 陌生，且要给新手讲清「插队」的概念（第一节已讲）。

**B 方案**（退路）：INA219 挂 I2C1，读 `bus voltage / shunt voltage` 两个寄存器算电流，代码量最小、数字量无噪声；但**要买件**，且 ACS712 闲置。这正是 `docs/低预算能力清单（功能边界）.md` 第 3 层原本写的方案。

**C 方案**（不推荐）：改 `.ioc` 加第 7 个规则通道 → 重新生成 → **重烧甩臂**。除非本来就要整体重烧，否则不做。

## 四、软件怎么做（新手风格，分步状态机）

### 4.1 状态机（把一件事拆成几个状态，每个状态只干自己的活）

```
IDLE ──($GRIP,CLAMP)──> CLOSING ──(I_smooth > I_contact 连续 3 次)──> HOLD ──($GRIP,OPEN)──> RELEASE
                          │                                                                      ↑
                          ├──(I_smooth > I_max 或 超时 3s)──> ABORT ──(回退 + $ERR,4)───────────┤
                          └──(脉宽到 1900 仍没接触)────────> NO_OBJ ──(上报)────────────────────┘
```

**`CLOSING` 每一步（每 50 ms 一次）**：
1. J6 脉宽 `+20 µs`（从 900 张开向 1900 闭合方向**小步推进**，别一步到位）；
2. 🔴 **屏蔽这一步后的 30~50 ms** —— 舵机刚动有启动冲击电流，这时候的高电流是「在转」不是「夹到了」，算进去必误判；
3. 读 `I_smooth`（8~16 点滑动平均）；
4. `I_smooth > I_contact` **连续 3 次** ⇒ 停推进、**回退 `Δµs` 卸载**、上报 `$FORCE,CONTACT` → `HOLD`；
5. `I_smooth > I_max` ⇒ 立即停 + 回退 + `$ERR,4` → `ABORT`（限流保护，防堵转烧舵机）；
6. 超时 3 s 或脉宽到 1900 仍无接触 ⇒ `NO_OBJ`（没夹到东西）。

### 4.2 阈值表（**起点值，必须实测标定**）

| 参数 | 起点 | 怎么定 |
|---|---|---|
| `I_offset` | 上电静止 100 次平均 | 禁止写死 2.5 V |
| `I_contact` | 0.8 A | 空抓（无物体）全程最大电流 × 1.3 |
| `I_max` | 2.0 A | 略低于 MG996R 堵转 2.5 A，留余量 |
| 连续次数 | 3 次 @100 Hz | 避开单次尖峰 |
| 转动屏蔽 | 30~50 ms | 舵机启动冲击 / 反电动势 |
| 每步脉宽 | +20 µs / 50 ms | 降速闭合（既有文档第 3 层第 2 条） |
| 超时 | 3 s | 防止一直推进 |

### 4.3 通信与遥测（复用既有资产，¥0）

- 新增统一帧命令字：`$GRIP,CLAMP` / `$GRIP,OPEN` / `$FORCE,?`（查询当前电流），沿用 `$<CMD>*CK\r\n` 语法与 `ERR,1~4` 语义；
- 遥测报文加一路 `j6_current_mA` → 现有 ✅ 链路（STM32 串口 → 鲲鹏 `telemetry_bridge.py` → MQTT → EMQX → eKuiper → InfluxDB → Grafana）**多一条曲线**；
- ⇒ 这块最能讲清的产出**不是「抓取成功」，而是「夹持过程可观测、可回溯、可限力保护」**，正好对上项目名「**可观测性闭环**」。

## 六、诚实边界（面试被追问时照这个说）

1. **电流 ≠ 力**。直流电机 `I ∝ τ` 只对电机轴成立；中间还隔着减速齿轮效率、摩擦、软爪形变、接触点力臂 ⇒ 电流只与夹持力**单调相关**，**不是线性等于力**。绝对力要挂砝码 / 推拉力计拟合 `F ≈ a·(I − I_offset) + b`。
2. **做不到恒定力抓取**。本项目是「接触即停 + 限流保护 + 可观测」，属于 threshold-based protection；真力控需要力传感器或总线舵机（STS3215 直接回读 load/current）。
3. **开环无位置反馈**（项目已知边界）：J6 脉宽 → 实际爪开度无回读；电流只告诉你「夹紧了」，不告诉你「夹到哪」。
4. **ADC 噪声与 PWM 脉动**：ACS712 输出几十 mV 噪声、舵机 50 Hz 电流脉动 ⇒ 必须 RC + 滑动平均 + 转动屏蔽，单样本判据不可用。
5. **档位**：📋 规划 / 无代码 / 未接线 / 未实机。本轮**未写任何 STM32 代码、未改 `.ioc`、未重烧**。

**能说**：「用霍尔电流传感器监测夹爪舵机电流，超阈值即停止闭合并回退，避免堵转与捏碎；电流曲线接入既有 IoT 看板，让夹持过程可观测。」
**不能说**：「实现力闭环控制 / 自动控制力度抓取 / 力控夹爪 / 自适应抓取 / 自动抓取」。

## 八、README 三行法

- **① 用了什么语法/技术**：`HAL_ADCEx_InjectedConfigChannel()` / `InjectedStart_IT()` + 转换完成回调（注入通道，避开已被 DMA 占用的规则组）；`enum` 状态机 + `switch`；滑动平均环形缓冲；`printf` 风格的统一帧 `$GRIP,...*CK`；遥测 JSON 加一个字段。
- **② 为什么这么设计**：`.ioc` 里 ADC1 规则组已被六路电位器占满且用 DMA 循环，硬加第 7 路要重新 Generate Code + **重烧甩臂** ⇒ 改用「插队」的注入通道，纯用户代码、零改动、零风险。电流只做**相对阈值**不做绝对力换算，因为齿轮/摩擦/软爪形变让 `I→F` 不是线性。
- **③ 不这么写会怎样**：串舵机母线 ⇒ 5A 量程饱和甚至烧采样电阻（8.7 第 6 条）；用单次采样判据 ⇒ 舵机启动冲击电流误触发、一夹就停；写死 2.5V 零偏 ⇒ 温度一漂阈值全错；只看「电流超了」不回退 ⇒ 舵机持续堵转烧齿轮；改 `.ioc` 重烧 ⇒ 甩臂、把已实机验收的眼在手链路弄坏。
