## 一、机械臂末端执行器-舵机标定与限力夹持

> 来源：`末端执行器-舵机标定与限力夹持.md`

> 本文档记录六路舵机的软限位上下限（多数为实测，J4 另行收窄）、安装方向与两个「基准姿态」，用于：
> 1. 防止过角度碰撞（软限位 clamp 的依据）；
> 2. 明确上电 / `HOME` 命令要回到的「初始位」；
> 3. 作为项目「标定」证据，供简历/答辩引用。
>
> 对应代码：
> - 软限位 / 初始位：`Core/Inc/main.h` 的 `SERVO_Jx_MIN/MAX/INIT`；
>   `Core/Src/arm_control.c` 的 `servo_min[] / servo_max[] / servo_init[]`。
> - 标定零位：`kunpeng/robot/arm_params.json` 的 `map` / `pulse_mid`，
>   被 `kunpeng/robot/arm_ik.py` 用于角度↔脉宽插值。
>
> ⚠️ **「初始位」与「标定零位」是两个不同概念，不要互相覆盖**（详见第一节下方说明）。

### 一、标定结果汇总（实测，非估计值）

| 关节 | 舵机型号 | 软限位 MIN (µs) | 软限位 MAX (µs) | 初始位 INIT (µs) | 标定零位 0° (µs) | 物理行程说明 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---|
| J1 基座 | 25KG 数字舵机 270° | 800 | 2300 | 1580 | 1580 | 左右各约 90° |
| J2 大臂 | 25KG 数字舵机 270° | 750 | 2150 | 1900 | 1470 | 前/后倾各约 90°，两端大臂约与平台平行 |
| J3 小臂 | 25KG 数字舵机 270° | 520 | 2500 | 2400 | 1500 | 实测 520(逆 110°)~2500(顺 130°) |
| J4 腕俯仰 | 25KG 数字舵机 270° | 500 | 1850 | 700 | 1500 | 物理实测 520(顺 100°)~2500(逆 130°)；软限位另行收窄，见第六节 |
| J5 腕旋转 | MG996R 180° | 500 | 2500 | 1450 | 1450 | MG996R，顺时针 70°，逆时针 82° |
| J6 夹爪 | MG996R 180° | 900 | 2000 | 1500 | 1500 | 900=张开极限；软限位 2000 为另行收窄（物理实测闭合端点 2100，见第六节） |

> **两个基准的区别（面试常问，先说清）**
> - **初始位 INIT**：大白话 = 上电那一瞬间、以及按「回初始位 / HOME」时，六个舵机各自
>   摆到的**安全折叠姿态**（重心靠近基座、不是一条直线）。规范定义 = `Arm_Init()` 直接
>   写入 PCA9685 的开环位置指令，也是 `Arm_CommandHome()` / `Arm_CommandResume()` 的
>   目标值；宏 `SERVO_Jx_INIT`。它是**人为选的安全姿态**，不是测出来的 0°，可按需调整。
> - **标定零位 0°**：大白话 = 把某个关节摆到「0 度」时量到的脉宽。规范定义 = 脉宽↔角度
>   分段线性标定表 `map` 的中间点，供逆运动学 `to_pulses()` 插值用；记录在
>   `arm_params.json`。它是**实测的物理基准**，改了逆解就全错。
> - 两者数值只在 J5/J6 恰好相同，J1~J4 都不同。⚠️ **改初始位时绝对不要动
>   `arm_params.json`**；网页 2D 姿态示意图的角度基准也用标定零位，不用初始位
>   （否则折叠姿态会被画成一条直线，正好是要避免的奇异位形示意）。
>
> 软限位多数来自实测，J4、J6 为另行收窄（见第六节）；命令脉宽先 clamp 再执行；初始位必须落在 `[MIN, MAX]` 内。

> ⚠️ 端点说明（**物理实测**）：J3/J4 的 **500µs 端点实测无效**（舵机不动/抖动），
> 故 J3 的 MIN 取 520µs；J4 现按需求把软限位设为 500~1850µs（见第六节），
> 但 500µs 端点历史上实测无效，实机首次下探到 500 前请小步复核舵机是否响应、有无堵转；
> J5 的 500µs 端点实测可用，保持 500~2500µs 不变。
> ⚠️ 初始位 J3=2400 距上限 2500 仅 **100µs**、J4=700 距下限 500 仅 **200µs**：
> 这两个方向余量很小，拖滑杆 / 下发 MOVE 时留意别直接怼到软限位。
> J4 上限已由 2500 收窄到 1850，初始位 700 到上限尚有 1150µs 余量，但反向大角度行程被限制；
> 逆解 / 示教若规划到 >1850µs 会被固件 clamp，详见第六节。

### 二、标定方法与步骤（可复现）

> 标定工具：串口助手通过 UART1 发送 `$MOVE,<ch>,<pulse>*<ck>` 微调，配合本机 `$STATE*57` 读取当前脉宽。协议见《联调验收清单》第一部分。

#### 通用流程（对每个关节重复）

1. **上电回初始位**：发送 `$HOME*0F`，确认机械臂回到折叠收拢的初始位。
   ⚠️ 上电前必须**手动**把臂摆到接近初始位——`Arm_Init()` 不走斜坡、开环无反馈，
   写任何值对舵机都是突变；J2/J3/J4 的初始位离标定零位很远，摆错会猛甩。
2. **切手动确认畅通**：发送 `$MANUAL*1A`，确保处于手动态。
3. **逐步逼近下限**：对目标关节，从小到大发送 `$MOVE,<ch>,pulse`，每次步进 20~50µs；
   观察机械臂，取「结构到位、再继续会碰撞/卡死」前一档为 **MIN**。
4. **逐步逼近上限**：同理从大到小逼近，取卡死前一档为 **MAX**。
5. **确认方向**：记录正方向对应的脉宽增减（如「脉宽增大→关节向左」），供上位机逆解/示教用。
6. **复核安全**：发送一次 `$MOVE,<ch>,MIN或MAX±50`，确认不越界、不抖动。

#### 单轴 MOVE 校验值速查（校验值已按协议 v1 算好，可直接复制）

**A. 标定用：到标定零位（0° 检查点，不是初始位）**

| 关节 | 到下限附近 | 到标定零位 0° | 到上限附近 |
|---|---|---|---|
| J1 | `$MOVE,0,800*19` | `$MOVE,0,1580*2D` | `$MOVE,0,2300*20` |
| J2 | `$MOVE,1,750*12` | `$MOVE,1,1470*22` | `$MOVE,1,2150*26` |
| J3 | `$MOVE,2,520*14` | `$MOVE,2,1500*27` | `$MOVE,2,2500*24` |
| J4 | `$MOVE,3,500*17` | `$MOVE,3,1500*26` | `$MOVE,3,1850*2E` |
| J5 | `$MOVE,4,500*10` | `$MOVE,4,1450*25` | `$MOVE,4,2500*22` |
| J6 | `$MOVE,5,900*1D` | `$MOVE,5,1500*20` | `$MOVE,5,2000*26` |

> 表中「到标定零位 0°」一列是**运动学 0° 基准**，用于核对 `arm_params.json` 的 `map`；
> 它不等于上电初始位。第三节 CSV 里的 `center` 同样指标定零位。

**B. 日常用：回初始位（上电 / HOME 目标姿态）**

### 四、如何把标定结果同步回代码

#### 1. 改初始位 / 软限位 → 只改 `Core/Inc/main.h`

```c
/* 每路舵机的软限位与「初始位」脉宽（us） */
#define SERVO_J1_MIN   800U
#define SERVO_J1_MAX  2300U
#define SERVO_J1_INIT  1580U
#define SERVO_J2_MIN   750U
#define SERVO_J2_MAX  2150U
#define SERVO_J2_INIT  1900U
#define SERVO_J3_MIN   520U
#define SERVO_J3_MAX  2500U
#define SERVO_J3_INIT  2400U
#define SERVO_J4_MIN   500U
#define SERVO_J4_MAX  1850U
#define SERVO_J4_INIT   700U
#define SERVO_J5_MIN   500U
#define SERVO_J5_MAX  2500U
#define SERVO_J5_INIT  1450U
#define SERVO_J6_MIN   900U
#define SERVO_J6_MAX  2000U
#define SERVO_J6_INIT  1500U
```

改后 `Core/Src/arm_control.c` 的 `servo_min[] / servo_max[] / servo_init[]` 自动跟随，
无需单独改；`kunpeng/web/web_control.py` 的 `PULSE_RANGES` 前两列 MIN/MAX 必须**逐路同步**
（第三列是初始位，别改错列），否则网页滑杆范围和「初始位」按钮会把臂送到一个和固件不一样的位置。
J4、J6 软限位收窄后与 `arm_params.json` 的标定端点不一致是有意为之，见第六节。
`HOME` 协议命令、函数名 `Arm_CommandHome()`、变量 `home_pulse[]` 保持不变
（它们是通信契约，全工程多处依赖，改名无收益）。

#### 2. 标定零位 → 只改 `kunpeng/robot/arm_params.json`

`map`（以及同值的 `pulse_mid`）是角度↔脉宽插值表，被 `arm_ik.py` 读取。
**初始位变更不要碰这个文件。**

#### 3. 2D 姿态示意图基准 → `web_control.py` 的 `CAL_ZERO_PULSE`

与 `arm_params.json` 的 `pulse_mid` 保持一致，用于把脉宽换算成画图的偏转量；
滑杆的 `data-init` 是初始位、`data-cal` 是标定零位，两者不要混用。

### 五、安全注意事项

- 标定时务必**舵机独立供电、与 STM32 共地**，避免电流冲击 MCU 或 PCA9685。
- 逼近限位时**步进要小（≤50µs）、有停顿观察**，堵转（stall 声/电流增大）立即回退，防止烧舵机。
- J3 的 500µs 端点实测无效，MIN 保持 520µs、不要下探；J4 软限位虽设为 500µs，但 500µs 端点历史上实测无效，首次实机下探前先小步复核、确认舵机响应且不堵转（见第六节）；J5 的 500µs 端点可用但**单次不宜长时间堵转**（MG996R 电流大）。
- 🔴 **改完初始位重新烧录后，第一次上电前必须手动把臂摆到接近「新初始位」（折叠姿态）**：
  `Arm_Init()` 直接写 PCA9685、不走斜坡、开环无位置反馈；若臂还停在旧姿态附近，
  六路会同时大幅猛甩（J2 +430µs、J3 +900µs、J4 −800µs），可能打到周围物件或堵转。
- 标定过程建议全程录像，副产品可直接用于答辩素材。

### 六、J4 / J6 软限位为何与标定端点不一致（变更说明）

> 大白话：**软限位 = 软件允许你摆到哪**，**标定端点 = 舵机物理上能转到哪**。
> 这次把 J4 上限从 2500 收到 1850、下限放到 500，是主动给腕部留安全余量，
> 不是舵机突然转不动了，所以 `arm_params.json` 里的实测角度数据不用跟着改。

**规范定义**：`Core/Inc/main.h` 的 `SERVO_Jx_MIN/MAX` 是 `clamp_pulse()` 的裁剪边界
（执行端安全限位）；`kunpeng/robot/arm_params.json` 的 `map` 是脉宽↔关节角度的
分段线性标定表，端点是实测物理角度基准，供 `arm_ik.py` 的 `to_pulses()` 插值使用。

**为什么 `arm_params.json` 不改**：想把 `map` 从 520~2500 截到 500~1850，必须先重新
实测「1850µs 对应多少度」；凭空截掉一段会让 `to_pulses()` 的插值失真，整套逆解抓取
位姿都会算错。所以本次只同步软限位引用点，J4 的 `pulse_min/pulse_max/map/pulse_mid`
**保留 520/2500/1500 不动**——这是有意为之，检查时别当成漏同步。

**要心里有数的后果**：逆解或示教若规划出 >1850µs 的 J4 脉宽，会被固件
`clamp_pulse()` 裁到 1850，属于预期的安全裁剪、不是 bug；以后若要让逆解精确匹配新限位，
补测 1850µs 处的实际角度再重标 J4 的 `map` 即可。第三节 CSV 里的
`J4,520 / J4,2500` 是历史实测采样点，同样保留原值。

**J6 同理（2026-11-06 追加）**：按需求把夹爪软限位上限由实测闭合端点 2100µs
收窄为 **2000µs**（另行设定的安全限位），`arm_params.json` 里 J6 的
`pulse_min=2100 / pulse_max=900 / pulse_mid=1500` **保留不动**——它是夹爪
开合角度↔脉宽的反向线性标定；J6 没有 `map`，`arm_ik.py` 的 `to_pulses()`
走 `pulse_min + ratio*(pulse_max-pulse_min)` 分支直接插值，凭空把 2100 改成
2000 会让整条插值曲线平移、抓取时的开合角全错。第三节 CSV 的
`J6,2100,gripper_closed` 同样是历史实测采样点，保留原值。
逆解若规划出 >2000µs 的 J6 脉宽，会被 `clamp_pulse()` 裁到 2000，属预期安全裁剪。

### 一、概念先讲清（大白话 + 规范定义）

| 概念 | 大白话 | 规范定义 |
|---|---|---|
| ACS712 | 一根电线从它中间穿过去，它就能「感觉」流过多少电流，输出一个电压；电线和测量电路不直接连 | Allegro ACS712，基于**霍尔效应**的线性电流传感器；内置导体与信号侧 galvanic isolation（约 2.1 kV RMS），输出与电流成比例的模拟电压 |
| 5A 量程 | 这个型号最多能测 ±5A，超了就「顶到头」读不准 | ACS712**ELCTR-05B**：灵敏度 `185 mV/A`，量程 ±5 A，带宽 80 kHz |
| ADC | 把「电压」翻译成「数字」的翻译器，单片机只认数字 | STM32F407 逐次逼近型 12 位 ADC；`VREF+ = 3.3 V` ⇒ 1 LSB ≈ `3.3/4095 = 0.806 mV` |
| 规则通道 / 注入通道 | 规则通道是「排队一个个测」；注入通道是「插队，来了先测它」 | ADC regular group（可被 DMA 搬运，本项目 6 路电位器在用）vs injected group（优先级更高，独立结果寄存器 `JDRx`，可中断读） |
| 舵机 PWM | 不是给电机通断，而是每 20ms 发一个「去第几度」的脉冲 | MG996R：50 Hz、脉宽 500~2500 µs 对应角度；内部自带电位器做**位置闭环** |
| 堵转 | 舵机被东西卡住、转不动了，还拼命使劲 ⇒ 电流猛涨 | DC 电机稳态 `I ≈ τ/(K_t)`，堵转时反电动势为 0，电流升到 stall current（MG996R @6V 约 **2.5 A**） |
| 力控 vs 限力保护 | 「一直保持 1 牛顿」很难；「劲儿一大就松手」容易 | 前者 = force control / impedance control（需力传感器或力矩观测器）；后者 = current-threshold contact detection，本项目只能做到后者 |
| 滑动平均 | 把最近十几个读数取平均，把抖动抹平 | moving average filter，抑制零均值噪声；窗口越大越稳、反应越慢 |

### 二、硬件怎么接（🔴 唯一必须遵守的一条：只串 J6 单路）

#### 2.1 红线

`docs/可行性与落地路线.md` **8.7 第 6 条**（原文）：
> **ACS712 是 5A 量程**，不许串在舵机母线上（峰值 15A 会饱和甚至烧采样电阻），只能测单路或电机支路。

六路舵机同时启动峰值可达 ~15 A。串母线 ⇒ 饱和 + 采样电阻过热 + 其他关节动作污染 J6 读数。**必须把 J6 的 6V 供电单独引一路。**

#### 2.2 接线图

```
6V 舵机母线（20A 降压 1.2~35V → 6.0V，并 3×2200µF = 6600µF）
   │
   ├──────────────────────── J1~J5 舵机 VCC（直接接，不测）
   │
   └── ACS712 IP+ ──[ ACS712 模块 ]── IP- ────── J6 舵机 VCC   ← 只串这一路
                          │
                          ├── VCC  ← 5V（独立 5V 轨 / USB 5V，别从 3.3V 取）
                          ├── GND  ── 星型汇合到 6V 电源 GND（信号地）
                          └── OUT  ── 1kΩ ── PA6 (ADC1_IN6) ── 0.1µF ── GND
                                              └─ RC 低通，抗舵机 PWM 脉动

J6 PWM 信号：仍来自 PCA9685A 通道 5（I2C1 = PB6/PB7），一根线都不用改
J6 GND    ：直接回 6V 母线 GND
```

**四根线各管什么（别接错）**：
- `IP+ / IP-` 是**功率侧**端子，串在 J6 的 6V 正极里（电流方向 IP+→IP-，输出高于 2.5V）；
- `VCC / GND` 是**信号侧**供电与参考地，必须与 STM32 **共地**（项目老规矩：地星型汇合）；
- `OUT` 是模拟电压，进 MCU ADC；
- 🔴 ACS712 模块 **VCC 必须 5V**（datasheet 4.5~5.5 V），**不能接 3.3V**（不工作），而 OUT 的最高 3.425V 对 STM32 ADC 引脚是安全的（绝对最大 `VDDA+0.3 ≈ 3.6V`）。

#### 2.3 为什么「只测 J6」时**不用分压**（量化核算）

ACS712-05B 输出：`Vout = 2.5 V + 0.185 V/A × I`（零电流 = VCC/2 = 2.5 V）

| 电流 | Vout | 3.3V ADC 能不能读 |
|---|---|---|
| 0 A（静止） | 2.500 V | ✅ 读数 ≈ 3102 |
| 0.8 A（接触阈值起点） | 2.648 V | ✅ |
| **2.5 A（MG996R 堵转）** | **2.963 V** | ✅ **在量程内** |
| 5 A（满量程） | 3.425 V | ⚠️ **削顶到 4095**（超 3.3V），但引脚不损坏 |

⇒ 只测 J6 单路（工作电流 ≤2.5 A）时，**OUT 可以直接进 PA6**，不必加电阻分压；加 `1kΩ + 0.1µF` 做 RC 滤波即可（若想留满 5A 余量，再并一个 2:1 分压，软件按分压比还原）。

**分辨率**：`0.806 mV / 185 mV/A ≈ 4.4 mA/LSB`（理论）；ACS712 输出噪声典型几十 mV ⇒ 实际有效分辨率约 **±0.1 A**，靠滑动平均压下去。

🔴 **零偏不能写死 2.5V**：ACS712 零偏有 ±20 mV 量级误差（折算 ±0.11 A），且随温度漂。上电、J6 不动时**实测 100 次取平均**当 `I_offset`，后面全部用 `I = (ADC − offset)` 相对量。

### 三、`.ioc` 现状与 A 方案为什么不用改它

`RoboticArm_Kunpeng.ioc` 里已经写死：

```
ADC1.NbrOfConversion=6                    # 六路电位器
ADC1.Channel-1~6 = ADC_CHANNEL_0~5        # PA0~PA5
ADC1.ContinuousConvMode=ENABLE
ADC1.DMAContinuousRequests=ENABLE
Dma.ADC1.0.Instance=DMA2_Stream0  (CIRCULAR)
ADC1.InjNumberOfConversion=0              # ← 注入通道「没配」，不是「不能用」
```

**A 方案做法**（纯用户代码，`Core/Src/` 里新增，不碰 CubeMX 生成段）：

1. `MX_GPIO_Init()` 之后把 **PA6** 配成 `GPIO_MODE_ANALOG`（PA0~PA5 已被生成代码配好，别动）；
2. 用 `HAL_ADCEx_InjectedConfigChannel(&hadc1, &sConfigInjected)` 把 **ADC_CHANNEL_6** 加进注入组；
3. 软件触发 `HAL_ADCEx_InjectedStart_IT(&hadc1)`，在 `HAL_ADCEx_InjectedConvCpltCallback()` 里 `HAL_ADCEx_InjectedGetValue()` 读值；
4. 规则组（6 路电位器 + DMA）**照常跑**，注入转换优先级更高、用独立 `JDR1` 寄存器，两者不抢。

✅ 不改 `.ioc`、不 Generate Code、**不重烧甩臂**、不影响已验收的电位器手动模式、¥0。
⚠️ 代价：`HAL_ADCEx_Injected*` 这套 API 比普通 `HAL_ADC_PollForConversion` 陌生，且要给新手讲清「插队」的概念（第一节已讲）。

**B 方案**（退路）：INA219 挂 I2C1，读 `bus voltage / shunt voltage` 两个寄存器算电流，代码量最小、数字量无噪声；但**要买件**，且 ACS712 闲置。这正是 `docs/能力边界与对标（幻尔LanderPi）.md` 第 3 层原本写的方案。

**C 方案**（不推荐）：改 `.ioc` 加第 7 个规则通道 → 重新生成 → **重烧甩臂**。除非本来就要整体重烧，否则不做。

### 四、软件怎么做（新手风格，分步状态机）

#### 4.1 状态机（把一件事拆成几个状态，每个状态只干自己的活）

```
IDLE ──($GRIP,CLAMP)──> CLOSING ──(I_smooth > I_contact 连续 3 次)──> HOLD ──($GRIP,OPEN)──> RELEASE
                          │                                                                      ↑
                          ├──(I_smooth > I_max 或 超时 3s)──> ABORT ──(回退 + $ERR,5)───────────┤
                          └──(脉宽到 1900 仍没接触)────────> NO_OBJ ──(上报)────────────────────┘
```

**`CLOSING` 每一步（每 50 ms 一次）**：
1. J6 脉宽 `+20 µs`（从 900 张开向 1900 闭合方向**小步推进**，别一步到位）；
2. 🔴 **屏蔽这一步后的 30~50 ms** —— 舵机刚动有启动冲击电流，这时候的高电流是「在转」不是「夹到了」，算进去必误判；
3. 读 `I_smooth`（8~16 点滑动平均）；
4. `I_smooth > I_contact` **连续 3 次** ⇒ 停推进、**回退 `Δµs` 卸载**、上报 `$FORCE,CONTACT` → `HOLD`；
5. `I_smooth > I_max` ⇒ 立即停 + 回退 + `$ERR,5` → `ABORT`（限流保护，防堵转烧舵机）；
6. 超时 3 s 或脉宽到 1900 仍无接触 ⇒ `NO_OBJ`（没夹到东西）。

#### 4.2 阈值表（**起点值，必须实测标定**）

| 参数 | 起点 | 怎么定 |
|---|---|---|
| `I_offset` | 上电静止 100 次平均 | 禁止写死 2.5 V |
| `I_contact` | 0.8 A | 空抓（无物体）全程最大电流 × 1.3 |
| `I_max` | 2.0 A | 略低于 MG996R 堵转 2.5 A，留余量 |
| 连续次数 | 3 次 @100 Hz | 避开单次尖峰 |
| 转动屏蔽 | 30~50 ms | 舵机启动冲击 / 反电动势 |
| 每步脉宽 | +20 µs / 50 ms | 降速闭合（既有文档第 3 层第 2 条） |
| 超时 | 3 s | 防止一直推进 |

#### 4.3 通信与遥测（复用既有资产，¥0）

- 新增统一帧命令字：`$GRIP,CLAMP` / `$GRIP,OPEN` / `$FORCE,?`（查询当前电流），沿用 `$<CMD>*CK\r\n` 语法与 `ERR,1~4` 语义；
- 遥测报文加一路 `j6_current_mA` → 现有 ✅ 链路（STM32 串口 → 鲲鹏 `telemetry_bridge.py` → MQTT → EMQX → eKuiper → InfluxDB → Grafana）**多一条曲线**；
- ⇒ 这块最能讲清的产出**不是「抓取成功」，而是「夹持过程可观测、可回溯、可限力保护」**，正好对上项目名「**可观测性闭环**」。

### 六、诚实边界（面试被追问时照这个说）

1. **电流 ≠ 力**。直流电机 `I ∝ τ` 只对电机轴成立；中间还隔着减速齿轮效率、摩擦、软爪形变、接触点力臂 ⇒ 电流只与夹持力**单调相关**，**不是线性等于力**。绝对力要挂砝码 / 推拉力计拟合 `F ≈ a·(I − I_offset) + b`。
2. **做不到恒定力抓取**。本项目是「接触即停 + 限流保护 + 可观测」，属于 threshold-based protection；真力控需要力传感器或总线舵机（STS3215 直接回读 load/current）。
3. **开环无位置反馈**（项目已知边界）：J6 脉宽 → 实际爪开度无回读；电流只告诉你「夹紧了」，不告诉你「夹到哪」。
4. **ADC 噪声与 PWM 脉动**：ACS712 输出几十 mV 噪声、舵机 50 Hz 电流脉动 ⇒ 必须 RC + 滑动平均 + 转动屏蔽，单样本判据不可用。
5. **档位**：📋 规划 / 无代码 / 未接线 / 未实机。本轮**未写任何 STM32 代码、未改 `.ioc`、未重烧**。

**能说**：「用霍尔电流传感器监测夹爪舵机电流，超阈值即停止闭合并回退，避免堵转与捏碎；电流曲线接入既有 IoT 看板，让夹持过程可观测。」
**不能说**：「实现力闭环控制 / 自动控制力度抓取 / 力控夹爪 / 自适应抓取 / 自动抓取」。

### 八、README 三行法

- **① 用了什么语法/技术**：`HAL_ADCEx_InjectedConfigChannel()` / `InjectedStart_IT()` + 转换完成回调（注入通道，避开已被 DMA 占用的规则组）；`enum` 状态机 + `switch`；滑动平均环形缓冲；`printf` 风格的统一帧 `$GRIP,...*CK`；遥测 JSON 加一个字段。
- **② 为什么这么设计**：`.ioc` 里 ADC1 规则组已被六路电位器占满且用 DMA 循环，硬加第 7 路要重新 Generate Code + **重烧甩臂** ⇒ 改用「插队」的注入通道，纯用户代码、零改动、零风险。电流只做**相对阈值**不做绝对力换算，因为齿轮/摩擦/软爪形变让 `I→F` 不是线性。
- **③ 不这么写会怎样**：串舵机母线 ⇒ 5A 量程饱和甚至烧采样电阻（8.7 第 6 条）；用单次采样判据 ⇒ 舵机启动冲击电流误触发、一夹就停；写死 2.5V 零偏 ⇒ 温度一漂阈值全错；只看「电流超了」不回退 ⇒ 舵机持续堵转烧齿轮；改 `.ioc` 重烧 ⇒ 甩臂、把已实机验收的眼在手链路弄坏。
