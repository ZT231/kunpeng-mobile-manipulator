## 〇、核心概念速查（概念（大白话） + 规范定义）

> 规矩：凡出现的技术概念，既要能讲得让外行听懂，也要能说出标准术语与出处。

| 概念 | 概念（大白话） | 规范定义 |
|---|---|---|
| FreeRTOS 任务 | 「同时干几件事」拆成几个各自循环的小程序，系统按优先级切换 | CMSIS-RTOS v2 `osThreadNew()` 创建的独立执行流，各有栈与优先级，抢占式调度。本项目 `StartServoTask`(High/20ms) / `StartProtocolTask`(Normal/5ms) / `StartPrintTask`(Low/3s) |
| 互斥量 | 一把钥匙，谁拿谁进，避免两个人同时改同一份数据 | CMSIS-RTOS v2 `osMutex`，带优先级继承的二值信号量。本项目 `arm_lock`（臂状态）、`print_lock`（串口输出），**从不同时持有**以防死锁 |
| 中断 / ISR | 硬件「拍一下」CPU，CPU 暂停手头活去处理，处理完回来 | `stm32f4xx_it.c` 的 IRQHandler。ISR 里只能调 `*FromISR` 后缀的 RTOS API；优先级受 `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY=5` 约束。本项目 ISR **只收单字节**，解析放任务上下文 |
| 串口帧 / XOR 校验 | 一句话两头加 `$` 和 `*校验码`，收方自己算一遍，对不上就丢 | 自定义协议 `$<CMD>[,<ARG>...]*<CK>\r\n`，`CK` = `$` 与 `*` 之间 payload 逐字节异或，2 位大写十六进制。响应 `$OK[,...]` / `$ERR,<code>`（1 帧/校验错误 / 2 未知命令 / 3 格式参数错 / 4 状态禁止 / 5 设备故障） |
| I2C | 两根线（时钟 + 数据）串起一堆芯片，靠地址点名 | Philips/NXP I2C-bus 规范，SCL/SDA 开漏 + 上拉、7/10 位地址。本项目 I2C1 = PB6(SCL)/PB7(SDA)，`GPIO_MODE_AF_OD` + `GPIO_NOPULL`，`PCA9685_ADDR=(0x40<<1)=0x80`，依赖模块自带 4.7k 上拉 |
| PWM / PCA9685 量化 | 用「高电平占多久」表示角度；只能一格一格跳，跳不了一半格 | 12-bit / 50Hz（周期 20000µs），`pulse_count = pulse_us × 4096 / 20000`，**1 LSB ≈ 4.88µs**。MG996R 死区约 5µs，与量化同量级 |
| 斜坡（ramp） | 不让舵机一步蹦到目标，每 20ms 挪一小步 | `Arm_Update()` 逐拍逼近；`SERVO_STEP_US=25µs`。`bf860d8` 改比例减速 `step_of()`（`ARM_STEP_DIV=4`）+ `ARM_STEP_MIN_US=12`，小步一拍到位 |
| 软限位 clamp | 不管上位机发多离谱的数，写舵机前先夹到安全区间 | `clamp_pulse()` 把脉宽裁到 `[SERVO_Jx_MIN, SERVO_Jx_MAX]`，在写 PCA9685 **之前**执行，属软件安全边界 |
| 初始位 INIT ≠ 标定零位 0° | 一个是「开机摆什么造型」，一个是「0° 对应多少脉宽」，两码事 | INIT = 上电 / `HOME` 目标姿态（人为选的折叠安全姿态），定义在 `main.h` `SERVO_Jx_INIT`；标定零位 = `arm_params.json` 的 `map` 中点 / `pulse_mid`，供 `arm_ik.py` 角度↔脉宽插值。**改 INIT 绝不能动 `arm_params.json`** |
| Flask 常驻进程 | 服务一启动就把页面模板记在脑子里，之后改磁盘文件它不知道 | `app.run()` 后模块级 `PAGE` / `PULSE_RANGES` 常驻内存，Python 不热加载；改 `.py` 必须 Ctrl+C 重启进程，Ctrl+F5 只清浏览器缓存 |
| 轮询 / 节流 | 每秒问一次状态；拖滑杆太密就每 60ms 才发一条 | 前端 `setInterval(...,1000)` 拉 `/api/state`；`drag()` 60ms 节流（约 16~17 次/秒）；`endDrag()` 清定时器同时复位 `dragBusy[i]`，`DRAG_HOLD_MS=800` 避免 STATE 回填弹回 |
| MJPEG | 一个长连接里不停塞 JPEG 图片，浏览器 `<img>` 当动画放 | `multipart/x-mixed-replace; boundary=frame`。`<img>` 跨域加载不受 CORS 限制；`/api/detections` 走 Flask 同源代理，检测框靠 `frame.w/h` 真实帧尺寸换算百分比 |
| logging.Filter | 给喇叭加个筛子，只筛掉某一类话 | `logging.Filter.filter(record)` 收单条 `LogRecord` 返回 bool，**消息级**过滤；`Logger.level` 是 logger 级全局阈值，`isEnabledFor()` 判 False 直接丢整条。Werkzeug 的启动提示 / dev-server WARNING / `Press CTRL+C` / 访问日志全走 `_log("info", ...)` |
| 逆运动学插值 | 把「角度」按实测标定表换成「脉宽」 | `arm_ik.py::to_pulses()` 用 `arm_params.json` 的 `map` 分段线性插值；无 `map` 时 `pulse_min + ratio×(pulse_max−pulse_min)`（J6 是反向标定：`pulse_min=2100 / pulse_max=900`） |
| Git fast-forward | 远程还停在我上一步，直接把指针往前挪就行 | 远程 HEAD 是本地 HEAD 的祖先，push 只移动引用，无需 force。`bf860d8..cc196bf` 即此情形 |

## 一、模块 README 三行法

> 三行 = ① 用了什么语法 / 技术　② 为什么这么设计　③ 不这么写会出什么问题。
> 只列**已实机跑通或已静态验证**的模块；P2 规划中的 `esp32/` 不列，免得面试被追问露馅。

### 端侧固件（C / STM32HAL / FreeRTOS）

**`Core/Src/uart_protocol.c` — 自定义串口协议栈**
- ① 用 C 的**状态机（`switch` 按字节流转）+ 函数指针命令表 + 双缓冲**，帧格式 `$CMD*CK\r\n`，XOR 逐字节校验，四通道（USART1/2/3 + BT/WiFi/RFID）路由到同一套 dispatch。
- ② ISR 只收单字节、解析与执行放任务上下文；双缓冲（活动槽 + 备用槽）+ `__disable_irq()` 临界区保证连发命令的应答不丢。
- ③ 若把解析塞进 ISR，会违反 `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY` 且长帧阻塞中断；若不做帧白名单过滤，`printf` 重定向到 huart1 的 banner / 遥测裸文本会被当成命令误解析（本项目真实踩过）。

**`Core/Src/arm_control.c` — 六路舵机运动控制**
- ① 用**数组 + 宏常量表**（`servo_min[]/max[]/init[]` 只引用 `main.h` 宏）、`clamp_pulse()` 裁剪、逐拍斜坡 `Arm_Update()`、`step_of()` 比例减速。
- ② 软限位在写 PCA9685 之前统一裁剪；值未变跳过 I2C；只有 `HAL_OK` 才更新 `last_sent[]`；`ARM_USE_PROPORTIONAL_RAMP` 宏可一键回滚旧算法。
- ③ 固定 25µs 步长 ≈ 5.1 LSB，微调台阶粗；`ARM_STEP_MIN_US=5` 与 4.88µs 量化不整除 + 模拟舵机粘滑会**更抖**（真实踩过，已改 12）。若一次 I2C NACK 就更新 `last_sent[]`，之后永久停更。

**`Core/Src/pca9685.c` — I2C PWM 驱动**
- ① 用 HAL `HAL_I2C_Mem_Write` 写寄存器、`(uint32_t)pulse_us × 4096 / 20000` 定点换算、`500~2500µs` 硬裁剪。
- ② 12-bit / 50Hz 是舵机标准；量化误差 4.88µs 与舵机死区同量级，提 PWM 频率收益会被死区吞掉。
- ③ 不做裁剪会写出超范围脉宽导致堵转发热；把引脚写进这个文件是错的——引脚在 `.ioc` / `i2c.c`，`pca9685.h` 只有设备地址。

**`Core/Src/freertos.c` — 三任务架构**
- ① `osThreadNew()` 三任务 + 两把 `osMutex` + `osDelay()`，按实时性分级（20ms / 5ms / 3s）。
- ② 舵机刷新最紧给 High，协议解析给 Normal，打印给 Low；两把锁从不同时持有避免死锁。
- ③ 若把 6 路 I2C 写入塞进 10ms 周期，High 优先级会吃掉大量 CPU；若两把锁交叉持有会死锁。

**`Core/Src/teach.c` — 示教录制 / 回放状态机**
- ① `enum` 五态（M/C/R/P/E）+ RAM 环形点表（100ms 采样、≤600 点）+ `Teach_Tick()`。
- ② 任何外部接管（MOVE / STOP）都让 `Teach_Tick` 自动退出，示教模块与状态机解耦。
- ③ 不做这个解耦，急停或手动插入命令后会残留半截轨迹继续乱动。

**`Core/Src/adc.c` + `potentiometer.c` — 6 路电位器采集**
- ① ADC1 六通道 + DMA2_Stream0 循环搬运 + 滑动平均 + 回滞死区。
- ② DMA 让 CPU 不参与搬运；回滞死区抑制电位器抖动导致的舵机微动。
- ③ 只轮询不滤波会让舵机在临界值附近反复抖动；不做死区等于把噪声直接送到输出侧。

**`Core/Inc/main.h` — 参数单一来源**
- ① 18 个 `#define`：`SERVO_Jx_MIN/MAX/INIT` + `SERVO_STEP_US`。
- ② 固件、网页 `PULSE_RANGES`、`docs/舵机标定记录.md` 三方同步；`arm_control.c` 只引用宏不写死数字。
- ③ 数值分散在多个文件，改一处漏一处 → 「回初始位」按钮与 2D 图基准全偏（本项目真实踩过）。

### 边侧上位机（Python）

**`kunpeng/web/web_control.py` — Flask 网页控制台**
- ① Flask `render_template_string` 内嵌 `PAGE`、pyserial `SerialHost`、`Threading` 读帧线程、9 条路由、`<img>` MJPEG、SVG 2D 姿态、前端节流状态机。
- ② 视频优先级 `--video-url` > `--camera`（摄像头独占，不跟鲲鹏 `detector_service.py` 抢 `/dev/video0`）；`/api/detections` 同源代理避免跨域与手机端 `127.0.0.1` 指错设备；三处 `_rx_loop` 只收 `$` 开头帧。
- ③ 不重启进程改内嵌模板不会生效（真实踩过）；`setLevel(ERROR)` 会连带屏蔽 `Running on`（真实踩过）；`dragBusy[i]` 不复位会让滑杆永久锁死（真实踩过）。

**`kunpeng/vision/detector_service.py` — 常驻识别服务**
- ① 标准库 `ThreadingHTTPServer` + 后台 `cv2.VideoCapture` 线程、`threading.Lock` 保护 `_jpeg` 与 `_latest`、`cv2.imencode` + `multipart/x-mixed-replace`。
- ② JPEG 编码必须在 `draw_and_report()` **之前**（后者会 `cv2.rectangle` 改原帧）；画面与检测结果用同一把锁更新保证同帧；`/detections` 上报真实 `frame.w/h`，前端才能把 bbox 像素换算成百分比。
- ③ 不上报帧尺寸，1280×720 的框会被按 640×480 算，位置全错；不同锁会让画面和框错帧。

**`kunpeng/robot/arm_ik.py` + `arm_params.json` — 逆解与标定表**
- ① 分段线性插值（有 `map`）与线性映射（无 `map`）、`clamp_pulse` 裁剪；JSON 存 6 轴实测 `pulse_min/max/mid/map`。
- ② 标定映射是**物理实测数据**，与软件安全限位分开；J6 用 `pulse_min=2100 / pulse_max=900` 表达反向标定（900=张开）。
- ③ 把软限位收窄值（J4 1850 / J6 2000）写进 `arm_params.json` 会让整条插值曲线平移，抓取开合角全错——**这个文件一个字都不能动**（真实决策）。

**`kunpeng/robot/arm_host.py` — 上位机发帧**
- ① 封装 `make_frame()` / `send()` / `fire()`，XOR 自动计算（`$PING*10`）。
- ② `MOVE` 走 `fire()` 只写不等（拖动要跟手），`resp=""` 是设计如此；只有 PING/STATE 空才是故障。
- ③ 手算校验码容易错（曾导致 `$ERR,1`）；把「不等应答」误判成故障会白排查半天。

**`kunpeng/robot/handeye_calib.py` — 手眼标定（11-11 已实标，resid 1.60mm）**

## 二、排障记录（现象 → 排查过程 → 根因 → 解决 → 一句话面试说辞）

> 只记重要 / 关键 / 面试官关心的问题，鸡毛蒜皮不记。

### 1. 舵机小幅度微调时抖动（S3 最核心，已实机闭环）
- **现象**：拖滑杆做 ±20µs 微调时舵机肉眼可见抖动，大幅移动正常。
- **排查过程**：先排除硬件（50Hz / 12bit 量化 4.88µs / MG996R 死区约 5µs 三者同量级），再看 `Arm_Update()` 斜坡；第一版改成比例减速但 `ARM_STEP_MIN_US=5`，实机**更抖**；仿真 `±20` 与 `+1500` 两种工况定位到量化不整除。
- **根因**：固定 25µs 步长 ≈ 5.1 LSB 台阶粗；5µs 最小步长与 4.88µs 不能整除，叠加模拟舵机粘滑（stiction）产生反复微动。**问题在输出侧运动规划，不在输入信号噪声**。
- **解决**：`step_of()` 比例减速（`ARM_STEP_DIV=4`）、`ARM_STEP_MIN_US=12`、`d <= SERVO_STEP_US` 时一拍到位、值未变跳过 I2C、只在 `HAL_OK` 时更新 `last_sent[]`；提交 `bf860d8`，2026-11-06 PC 实机确认不抖、拖滑杆无新 warning。
- **一句话面试说辞**：「滤波不等于丝滑：先分清输入侧滤波和输出侧运动规划，抖动根因是固定步长与硬件量化不整除，改比例减速 + 最小步长夹限后实机消失。」

### 2. PCA9685 初始化失败，不出 banner、不响应 PING
- **现象**：串口反复打印 `PCA9685 init failed`，板子 `Error_Handler()` 关中断死循环，PING 无应答；每重复一行等于芯片完整复位一次。
- **排查过程**：核对 `.ioc` L149-152 与 `i2c.c` L74-79 引脚 PB6/PB7（`AF_OD` + `NOPULL`）、地址 `0x80`、时钟全部正确；用「只测 PING」最小系统把链路切到最小，逐段查接线。
- **根因**：**杜邦线接触不良导致 I2C 无 ACK**，是物理断路，不是固件 / CubeMX / 协议栈问题。初始化失败即死循环的设计让现象看起来像固件挂了，容易误判。
- **解决**：换线固定 + 彻底断电重启；仅测 PING 也必须接 PB6/PB7 并供逻辑电（VCC 必接，V+ 舵机电可不接）。接触不良是间歇性的，晃动线束会复现。
- **一句话面试说辞**：「先切最小系统定位物理层：I2C 无 ACK 时先量接线，别急着改驱动；初始化失败直接死循环会让硬件问题伪装成固件问题。」

### 3. 网页把 printf 裸文本当协议帧解析
- **现象**：串口接上后上位机偶发解析异常。
- **排查过程**：发现 `fputc` 重定向到 `huart1`，与协议帧共口；banner、遥测、AT 回显都是不带 `$` 的裸文本。
- **根因**：一个物理串口上混了「协议帧」与「调试文本」两种数据契约。
- **解决**：`web_control.py` 三处 `_rx_loop` 只接收 `startswith("$")` 的帧并剥 `*CK`，串口版清空 `line` 防粘连；`LOG,0` 关不掉 banner，所以过滤是必需兜底。
- **一句话面试说辞**：「同一通道混多种数据格式时，接收端必须做白名单式帧过滤，不能指望发送端不打印调试信息。」

### 4. 「改中位」差点破坏逆运动学（架构决策）
- **现象**：要把上电姿态改成折叠收拢，直觉上应同步改 `arm_params.json` 的 6 个 `pulse_mid`。
- **排查过程**：Grep 全工程发现 `map` 被 `arm_ik.py::to_pulses()` 读取做角度↔脉宽插值；改 `pulse_mid` 会和 `map` 自相矛盾，改 `map` 直接破坏逆解。上一轮「只是记录副本、建议同步」的结论**作废**。
- **根因**：工程里混着两个不同概念——**初始位 INIT**（上电姿态）与**标定零位 0°**（IK 基准）。
- **解决**：只改 `main.h` `SERVO_Jx_INIT` / `arm_control.c` `servo_init[]` / 网页 `PULSE_RANGES` 第三列 / 标定文档；`arm_params.json` 一字不动；网页 2D 图另立 `CAL_ZERO_PULSE` 用标定零位作画图基准；中文文案统一「初始位」，协议命令 `HOME` 保留为通信契约。
- **一句话面试说辞**：「改配置前先查谁在读它——同一个数字在不同模块可能代表完全不同的物理含义，动手前把数据流向画清楚。」

### 5. J6 滑杆「有时拖不动」
- **现象**：夹爪滑杆偶发完全无响应，刷新页面才恢复；同时感觉滑块会被「弹回去」。
- **排查过程**：前端节流状态机的 `dragBusy[i]` 只在 60ms 定时器回调里复位；`onchange` 里 `clearTimeout()` 取消定时器后标志永久为 `true`，之后 `drag()` 全被 `if(dragBusy[i]) return` 吞掉。叠加 1s `STATE` 回填覆盖 `s.value`。
- **根因**：**定时器被取消不等于状态被复位**；再叠加周期状态回填与用户输入的竞态。
- **解决**：新增 `endDrag()` 清定时器同时复位 `dragBusy/dragNext` 并发最终值；`dragAt[i]` + `DRAG_HOLD_MS=800` 让拖动后 800ms 内跳过该路 STATE 回填。
- **一句话面试说辞**：「前端节流要按完整状态机设计，别只管定时器；还要处理服务端周期回填与用户输入的竞态。」

### 6. 改了 Python 模板不生效 / 日志降噪误伤启动提示
- **现象**：磁盘上 J6 已是 2000、夹爪已是 V 形，浏览器仍显示 2100 和一根直线；终端缺 `* Running on http://127.0.0.1:5000`。
- **排查过程**：Grep + 现场 `render_template_string` 证明磁盘代码正确；Glob 确认全工程只有一份 `web_control.py`、无 `__pycache__`；查 Werkzeug `serving.py::log_startup()` 与 `_internal.py::_log()`，确认启动提示 / dev-server WARNING / `Press CTRL+C` / 访问日志**全是 `_log("info", ...)`**。
- **根因**：① Flask 常驻进程的内存快照不随磁盘文件更新，Ctrl+F5 只拿到服务端用旧 `PAGE` 重渲染的 HTML；② `setLevel(ERROR)` 是 logger 级全局阈值，把同 logger 下的启动 INFO 连带屏蔽。
- **解决**：① Ctrl+C 停进程再启动，必要时 `?v=2` 换缓存键；② 降噪改模块级 `_NoAccessLog(logging.Filter)` 按 `" - - ["` 内容过滤，保留启动提示 / WARNING / ERROR。
- **一句话面试说辞**：「先确认改动是否真的进了运行中的进程；日志降噪要按消息内容过滤，不要抬 logger 的全局阈值。」

### 7. push 报 TLS 握手失败（排障方法论）
- **现象**：`schannel: failed to receive handshake`；去掉代理直连则 `Recv failure: Connection was reset`。
- **排查过程**：确认 `cc196bf` 已 commit、`status` 干净；`git config --show-origin` 查代理与 SSL 后端；只读 `ls-remote` 做 9 种组合控制变量；Python socket 对 7897 做协议识别（HTTP CONNECT 回 `200`、SOCKS5 回 `\x05\x00`）与站点对照（`www.baidu.com` TLS OK，`github.com` / `api.github.com` / `www.google.com` 全 EOF）。
- **根因**：7897 是 Clash 混合端口、进程活着，但**上游节点 / 规则对境外站点不转发**；`CONNECT 200` 只代表代理接受隧道请求，不代表上游已连通。**不是 Git 配置、不是 TLS 后端、不是证书**。
- **解决**：修 Clash 上游（选可用节点 / 切 Global / 更新订阅）后**原样** `git push origin main`（不带任何 `-c`、不 `--unset`、不关 `sslVerify`）→ `bf860d8..cc196bf main -> main`。已撤回的错误结论：「换 openssl/HTTP1.1 能修」「直连反而通（工具环境假象）」「去掉代理」。
- **一句话面试说辞**：「用控制变量把问题钉在代理上游；诊断环境的网络路径未必等于用户终端，结论必须回到用户侧复现才算数。」
