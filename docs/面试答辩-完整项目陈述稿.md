## 0. 30 秒电梯版（先背下来）

我做的是一个**视觉引导的移动操作平台**。在鲲鹏开发板上跑一个网页，我在画面里点一下桌面目标，系统用手眼标定把像素坐标换算成机械臂基座坐标，逆运动学解出六路舵机脉宽，经串口下发给 STM32F407，让爪尖悬停到目标正上方；同时六路脉宽、帧号、检测数经 MQTT 进板内四容器，在 Grafana 上画成六条曲线。从 PCB、固件、上位机到时序看板都是我自己搭的。三根支柱是：视觉引导执行、ESP32-S3 语音入口、IoT 可观测性闭环。

## 1. 完整陈述正文（约 6~8 分钟，照念）

### 1.1 定位与要解决的问题（40 秒）

这个项目想解决的是**「嵌入式 Linux 上位机 + 单片机执行端」怎么协作完成一次带视觉的定位，并且整个过程能被观测」**。

我不是买一套成品套件跑 demo，而是把链路自己搭起来：自己画了 STM32F407 和 ESP32-S3 的核心板，机械臂固件用 CubeMX + HAL + FreeRTOS，底盘是另一颗 F407 用 Keil + 标准外设库，上位机是鲲鹏板上的 Python/Flask，中间用自定义的统一串口帧把四端串起来。

- **逆运动学**（大白话：告诉手臂"爪子去这个坐标"，反算六个关节各转多少度；规范定义：由末端位姿反解关节变量）——这是机械臂运动的基础。
- **手眼标定**（大白话：算出"相机看到的点"和"手臂基座坐标"之间的换算关系；规范定义：求解 AX=XB 中的手眼矩阵 X）——这是视觉引导的前提。
- **统一帧协议**（规范：`$<CMD>[,<ARG>...]*<CK><CR><LF>`，CK 为 payload 逐 UTF-8 字节 XOR 取 2 位大写十六进制）——这是四端互相听得懂的约定。

### 1.2 硬件架构：四端、两套库、一条帧（50 秒）

系统有四个计算节点：

| 节点 | 芯片 / 系统 | 职责 |
|---|---|---|
| 上位机 | OrangePi KunPeng Pro（openEuler / aarch64 / 嵌入式 Linux） | 视觉、Web UI、Flask 接口、IoT 栈 |
| 机械臂执行端 | STM32F407VE，CubeMX + HAL + FreeRTOS | 收帧、PCA9685 输出六路 PWM、六自由度总线舵机 |
| 移动底盘 | STM32F407ZE，裸机 + Keil + SPL | L9110S + TIM8 驱动电机、HC-SR04 三向测距、蓝牙 |
| 语音入口 | ESP32-S3-WROOM-1 N16R8，ESP-IDF v5.5.5 | Wi-Fi 上行、本地帧自检、命令词接入（🔶 未上板） |

🔴 这里有个必须讲清的工程决定：**两套 STM32 用的是两套互不兼容的库**（HAL+FreeRTOS vs 裸机 SPL），我没有强行合并成一个工程、也没有动 `.ioc`，而是让两颗 MCU 各跑各的，靠统一串口帧通信。改 `.ioc` 会牵动整套 CubeMX 生成代码，风险远大于收益；用帧解耦后，小车那个工程只改了一个 `demo.uvprojx`，原 `1.Smart car` 目录一行没动。

外围细节也是实测出来的：USB 转串口只接 TX/RX/GND、5V 必须断开；相机走 USB3.0、串口走 USB2.0；地线星型汇合；串口号不写死 `/dev/ttyUSB0`，改成开机按 `by-id` → `/sys` 认 `1a86:7523` → 兜底 `ttyUSB*` 自动探测，启动时就 open + PING。

### 1.3 软件架构与数据流（40 秒）

分层是「感知 → 决策 → 执行 → 可观测」：

1. **感知**：USB 摄像头 8080 推流，YOLO 出检测框与 `det_count`；棋盘/目标点由网页点选给出像素 `(u,v)`。
2. **决策**：`/api/ik/eye/solve` 拿像素 + 当前六路真实脉宽 → 内参反投影 → 当前 FK 相机位姿 → 手眼矩阵 X → 与 `z = plane_z` 平面求交 → 工作台坐标 `(x,y,z)` → `ArmIK.solve()` → `to_pulses()` 六路脉宽。
3. **执行**：`/api/cmd` 把逗号分隔的 payload 写进串口帧 → STM32 → PCA9685 → 舵机。
4. **可观测**：`telemetry_bridge.py` 只读 `/api/config`、`/api/detections`、`/api/state` 三个接口 → MQTT `device/kunpeng_01/telemetry` → EMQX → eKuiper → InfluxDB → Grafana。

架构上我坚持**不改主链路**：遥测桥和语音网关都是独立进程，只读 5000 端口已有接口、只经 HTTP `/api/cmd` 下发，一行 `web_control.py` 都不动。因为改主链路就要 scp + 重启 Flask，重启会把 `_IK_MAP` 标定值清回默认、打断实机现场。

### 1.4 支柱① 视觉引导执行（重点，90 秒）

这是全项目**已实机**的主成果，链路是：眼在手实标 → 点选定位 → 悬停到位。

**手眼标定**：用 AX=XB 求解，实测残差 **1.60 mm**，尺度 `s = 0.7549`，平移模长 `|t| = 16.67` 与连杆 L3 = 17.0 cm 吻合，`axis_cond = 0.519`。我先量化了误差下限：PCA9685 一个 LSB 是 **0.659°，折算末端 2.9 mm**；总线误差 0.40 mm；齿隙 0.75° 折算 3.3 mm。也就是说 1.60 mm 的标定残差已经贴着硬件分辨率了。

**验收结果**：垂直方向 **0.8 mm**；网页点选 J1 三档 **0.42 cm**；14 次重复性 x 0.10 mm / y 0.70 mm，回位 1.10 mm，上电→摆 C 姿态→测 1.17 mm。`--hover` 让爪尖到棋盘中心正上方，垂直 0.8 mm 是实测的。

**三条入场闸门**（实机全绿）：① 平面模式不给 `--plane-z` 就强制 0.0；② 非 C 姿态直接 `return 2` 拒发；③ hover 成功后强制提示回位。加闸门是因为开环舵机没有位置反馈，误发一次就要重新摆姿态。

### 1.5 支柱② ESP32-S3 语音入口（50 秒）

这条我做成**快慢双通道**：命令词只管会动的动作，闲聊走对话链；**LLM 只提议，本地仲裁器（量程 / 净空 / 急停优先）才授权**。缺 AEC 所以用 push-to-talk 绕过。语音走**端侧命令词**（ESP-SR WakeNet + MultiNet，全离线、不需要 Key，N16R8 的 8 MB PSRAM 够），不用云 ASR。

已实机的是**阶段 2 的鲲鹏侧网关链路**：`voice_gateway.py` 是独立 TCP server，收帧 → CK 校验 → 急停快速通道 → 意图解析 → 白名单仲裁 → HTTP `/api/cmd`。白名单只授权 `HOME / STOP / RESUME` 三个固件原生**无参数命令字**，`PICK / PLACE / MOVE` 一律拒 `ERR,3`。只选这三个，是因为下发 `$JOINT` 会一步踩进 `to_pulses()` 符号、软限位静默夹紧、`SAG_DZ` 净空折算四个已定案雷区。

四层硬判据全绿：八进制帧 `$ASR,回初始位*61` → `$OK,HOME*27`；网关日志 `payload=HOME / sent:true / apply:true`；`/api/state` 脉宽从 C 姿态 `[1636,1470,2177,1106,1450,1567]` 变回初始位 `[1580,1900,2400,700,1450,1500]`；肉眼确认臂从 C 姿态收回初始位。

🔴 诚实边界：`source` 恒 `mock`，喂的是**假帧**；没接云端大模型 / ASR / ESP32。ESP32-S3 固件的 Wi-Fi STA、TCP 上行、中文帧八进制字节串都已写完并在 PC 上整机 build 通过（`kunpeng_voice.bin` 803760 B），**未烧录、未上板、未联调**，档位 🔶。

### 1.6 支柱③ IoT 可观测性闭环（50 秒）

板内四容器 **EMQX → eKuiper 2.1.0 → InfluxDB 2.x → Grafana** 已端到端实机：真实串口遥测 → MQTT → 六路脉宽曲线，15 秒内 `records_in` 涨而 `exceptions_total` 不涨，是稳态写入不是瞬时侥幸。

- **MQTT**（大白话：设备把消息贴到"主题公告栏"，订阅的人就收到；规范：MQTT 3.1.1/5.0，基于 TCP 的发布-订阅协议，主题 `/` 分层、`+` 单层通配）。
- **eKuiper**（大白话：在板子本地用一句 SQL 把流过的数据筛一遍再转发，断网也能自治；规范：面向无界流的连续查询引擎）。
- **InfluxDB 2.x**（规范：按 measurement + field + tag + timestamp 组织；field 只允许 float / integer / unsignedInteger / string / boolean 五种标量，**每个 measurement+field 的类型首次写入即锁定**）。

这条约束直接决定了我的一个设计：串口断连时六路脉宽会变 `null`，eKuiper influx2 sink 不会跳过 nil、会把它写成 **string**，撞上历史 float 触发 `partial write: field type conflict`、整批写不出去。所以我在**发布端**加了 `is_publishable()`，六路必须全是真数字（显式排除 `bool`，因为 Python 里 `bool` 是 `int` 子类），不完整就跳过本次发布。进程不崩不等于数据无害。

🔴 欠账两笔，按真实状态说：ESP32 节点自身遥测（RSSI / 剩余堆 / 唤醒次数）和 eKuiper 阈值告警规则还没进板内栈；我已写好 `esp32_telemetry.py` 契约层 + `esp32_rules.json`（2 流 3 规则、token 全 `${INFLUX_TOKEN}` 占位符）+ 27 项单测，属**提前草案**，未部署、未联调。

### 1.7 四个硬骨头与我的解法（90 秒，这段最能体现深度）

**① 重力下垂 = 唯一精度瓶颈。** 定位成开环稳态误差，**不是结构柔性、不是齿隙**：J2 偏 6.5°、J3 偏 2.2°，末端位移 dx +0.10 / dy −0.95 / dz −3.88 cm。我试过按姿态前馈补偿（A→B 125%、B→C 25%），实测作废，所以**禁止按姿态补脉宽**；唯一可用的是 C 姿态常值偏置 `TIP_BIAS_XY=(0.10,−0.95)`、`SAG_DZ=−3.88`，而且**只许执行侧用，绝不进标定链**。`do_hover` 里有净空闸门 `sag_used = max(|SAG_DZ|, |SAG_DZ|·r_w/14.97)`，`r_w = r − 11.15`，净空 <0.5 cm 拒发。

**② 定位径向偏近 2.9 cm 的自洽解释。** 相机骑在腕上，FK 不知道 J2 下垂，视线偏了 6.5°；执行侧补了偏置、定位侧没补，于是「垂直 0.8 mm ✅ / 水平 3 cm 🔴」同时成立，不是两个独立 bug。修法放在 `/api/ik/eye/solve` 的**出口**：`_EYE_RADIAL_K = 1.091`，只按 `hypot` 缩放半径、**不改方位角**，返回 `x_raw/y_raw/radial_k/radial_shift` 便于对照；**不进 localize / 标定链**。旧系数 1.116 已作废，且这是单点经验值，换棋盘 / 换相机 / 重标 X / tilt 离开 41° 必须重测。

**③ 跨时段系统偏差定案。** 真值 (−2.46, 30) 半径 30.10 cm，三个时点测得 30.32 / 28.87 / 28.70，结论是**偏近 1.40 cm、横向约 1.2 cm**；方位角 −2.7° 指向手眼矩阵旋转或 J1 map，横向分量尚未解。我把它定成**已知边界**：手眼 X 与系数 k 只在「单次上电、同一姿态族、同一时段」有效；0.30 cm 是单点实测，不能外推成稳定精度。组内重复性极稳 ≠ 跨时段准确度，这两件事我分开报。

**④ 协议与鲁棒性。** 统一帧 CK 用 payload 逐 UTF-8 字节 XOR；中文帧在 C 里写成八进制字节串 `\345\233...`，与板端 `printf`、Python `.encode("utf-8")` 三者逐字节对齐，CK 固定 `0x61`。串口 ORE 溢出已在 `uart_protocol.c` 修好并烧录。网关层踩过并修掉的真问题：ASCII stdout 下中文日志抛 `UnicodeEncodeError` 导致服务退出（改为 `_configure_stdout()` / `_emit()` locale 无关输出）；日志打印排在回帧之前会**吞掉应答**（改为先 `write(reply)` 再打日志）；「解除急停」含裸词「急停」被反向判成急停（抽出 `_match_resume()` / `_match_estop()`，恢复词优先）。

### 1.9 工程与排障（40 秒）

我给每个项目都维护**排障记录**，固定五段式「现象 → 排查过程 → 根因 → 解决 → 一句话说辞」，只记关键问题。举两个能体现排查方法的：

- 串口三种超时对应三种病：`600 ms 未收到任何字节` 是只缺回程；`节点已重建或消失` 是真重枚举；`读取线程异常退出` 是 read 抛错。不混为一谈才不会瞎调参。
- Grafana `No data` 按层排查：先看遥测桥有没有在跑、再 `curl /rules/to_influx/status` 看 `records_in` 增量与 `exceptions_total`、再查 Flux 的 `range()` 是否用 `v.timeRangeStart/Stop`（写死 `-5m` 时 UI 调到 24 小时也取不到历史点）、最后 `nft list ruleset` 排容器间 REJECT。四个错误假设（hosts 陈旧 / eKuiper veth 专属 / iptables FORWARD 拦截 / 改 sink 网关绕行）逐个证伪后才定位到 firewalld nftables 的兜底 reject。

**验证纪律**：先本机可验证、后上板。C 侧 `gcc -std=c99 -Wall -Wextra -Werror` 零警告；主机单测 14/14；C++ 协议引擎 11 项 CTest 100% 通过；Python 侧网关 38 项、意图层 44 项、IoT 草案 27 项 unittest 全绿；跨语言帧语义实证 `PASS=24 FAIL=0`；ESP-IDF 整机 `idf.py build` `BUILD_RC=0`。编译和单测通过只证明本机逻辑，我从不把它写成实机。

### 1.10 系统的已知边界（40 秒，正面陈述，不是找借口）

我把边界当成系统的一部分，主动量化、主动定案：

1. **执行端是开环的**：`/api/state` 回读的是**指令脉宽**，不是舵机实际转角；六路总线舵机没有编码器、没有位置反馈。所以系统里不存在闭环控制，也不做视觉伺服；我用的是「C 姿态族内的常值偏置 + 明确的拒发闸门」。
2. **感知是单目 RGB**：相机是眼在手、骑在腕上的普通 USB 摄像头，没有结构光、没有 ToF、没有深度图。所以没有点云、没有体积测算、没有三维重建；定位靠「已知平面 + 手眼矩阵 + 平面求交」，把三维问题降成二维平面求交。
3. **底盘无里程计**：F407ZE 底盘没有编码器 / IMU / PID，纯开环，「走 X cm」只能用定时实现，误差 20~40%。所以没有建图、没有导航、没有全局重定位。语音走过去抓东西这类需求，对这个硬件是缺口，我不会把它写成已实现。
4. **语音入口尚未闭环**：`source` 恒 `mock`，ESP32 未烧录，急停只在网关层冻结并转发 `STOP`，开环无位置反馈。

### 1.11 演进路线（20 秒）

按优先级排好的后续：先烧 ESP32-S3 跑四层硬判据 → ESP32 真发帧钉死语义对齐 → ESP-SR 端侧命令词 → IoT 补 ESP32 节点遥测 + eKuiper 告警 → ACS712 串 J6 做接触即停与限流保护（**不是力控**）→ 最后才做底盘烧录、四条实机判据与第二路 USB-TTL 统一调度。再往后是 ROS / 双相机 6D / 导航 / OTA，目前是 📋 规划。

这个项目对我最大的价值不是某个精度数字，而是**能把一条从 PCB、固件、串口协议、嵌入式 Linux 上位机到时序看板的链路完整搭起来，并且把每一个"不准"都量化到毫米、追到根因、定成边界**。我习惯先本机验证再上板、每一步都留可复跑的证据，这也是我做完四个项目后最想带到岗位上的工作方式。

## 2. 可展开的技术纵深（每个结论能下钻到哪一层）

- **手眼 AX=XB**：为什么用 `|t| ≈ L3` 和 `axis_cond` 做合理性判据；`ArmIK.forward()` 不是绝对 FK（C 姿态算出 r=1.8~2.4 cm 而真值 26 cm），所以不能拿绝对半径判棋盘位置。
- **`to_angles()` 与 `solve()`**：前者是相对角、后者是绝对角；J3/J5 的 map 反向、J3/J4 存的是相对角，改脉宽前必须 `to_pulses()` 反解校验；`solve()` 成功不代表舵机能到，软限位会静默夹紧，判据是角度差 > 5°。
- **`plane_z` 语义分裂**：`/api/ik/eye` 返回的 `plane_z:2.0` 来自 `arm_params.json` 的抓握高度默认，不是桌面基准；桌面必须 `--plane-z 0`，手机屏 1.1 cm 才用 1.1。
- **坐标约定**：x 是横向，y 是 J1 正前方 / 径向；基准点写「+方向+格数」。
- **重力下垂闸门**：`r_w = r − L3·sin(tilt)` 的力矩臂折算、`r > 27` 必须重测不能外推、X 只在 C 姿态族精确。
- **eKuiper 两个坑**：schemaless 建流必须写空括号 `()`；`tags` 用 `{{.deviceId}}` 模板会报 `can't evaluate field deviceId`（2.1.0 模板上下文是 `[]map[string]interface{}` 切片），改静态 map。
- **心跳超时**：不能用 eKuiper 窗口检测 —— 窗口由「收到消息」驱动，设备彻底离线时一条消息都没有，SQL 窗口不会触发；离线检测必须放板侧看门狗。
- **InfluxDB 字段隔离**：两套设备共用 `device/+/telemetry` 通配时，必须按 `deviceId` 分流 + 独立 measurement，否则 field 类型冲突。
- **两套 STM32 库**：为什么不能混编、为什么不动 `.ioc`、统一帧 CK 的计算与中文 UTF-8 字节转义为何要与三种语言逐字节对齐。

## 3. 概念双轨速查（大白话 / 规范定义）

| 概念 | 大白话 | 规范定义 |
|---|---|---|
| 逆运动学 IK | 告诉爪子去哪，反算六个关节转多少 | 由末端位姿反解关节变量 |
| 手眼标定 | 算「相机看到的」到「手臂坐标」的换算 | 求解 AX=XB 中的手眼矩阵 X |
| 开环 / 闭环 | 只发指令不检查到没到 / 边走边测边修 | 控制系统有无反馈环节，输出是否回灌影响输入 |
| PWM 脉宽 | 用高电平持续时间长短表示"转到哪" | 脉宽调制，舵机以 500~2500 µs 映射角度 |
| 里程计 | 靠轮子转了几圈推算走了多远 | odometry，由轮速/编码器积分估计位姿 |
| 点云 | 几万个带距离的点把物体"摸"出立体形状 | 三维坐标系中点的集合，来自 RGB-D / 结构光 / ToF |
| MQTT | 消息贴到主题公告栏，订阅的人收到 | MQTT 3.1.1/5.0，基于 TCP 的发布-订阅协议 |
| 边缘规则引擎 | 板子本地一句 SQL 筛完再转发，不上云 | 面向无界流的连续查询引擎（eKuiper） |
| 时序库 field 类型锁定 | 一格第一次装小数，以后只能装小数 | InfluxDB 2.x 每个 measurement+field 类型首次写入即锁定 |
| 统一帧 CK | 给每帧算个校验码，收方验一下有没有传错 | payload 逐 UTF-8 字节 XOR，取 2 位大写十六进制 |

## 4. 用词规范（写简历、讲项目都按这个）

**可以说**：视觉引导执行、眼在手手眼标定、爪尖悬停、板内可观测性闭环、统一帧协议跨四端、开环稳态误差量化、跨时段系统偏差定案、四容器遥测、阶段 2 网关链路实机打通。

**不可以说**：具身智能、自动抓取、闭环控制、视觉伺服、NPU、语音控制已实现、语音→动作闭环、已接 ESP32、自然语言控制机械臂、定位 ±1 cm、机械松动 / J2 舵盘滑移（已撤回的旧结论）。

**三档别混**：编译通过 / 单测全绿 ≠ 实机；核心地位 ≠ 已完成。ESP32-S3 与 IoT 是核心支柱，但档位该是 🔶 就是 🔶。
