## 2 一句话结论

**幻尔宣传页上的功能，约 2/3 用现有硬件 + 开源算法零成本就能做；剩下 1/3 里，「近距深度」这一档已被 DaBai DCW 补上，「激光雷达 SLAM」是有意放弃的。**

真正的分水岭已经不是「有没有 AI 大模型」（那只是调 API），也不是「有没有深度相机」，而是：

> **夹爪能不能感知夹持力、整条链能不能把重复定位稳定在毫米级。**

前者对应 ACS712 限力方案（接触即停，尚未闭环），后者对应手眼标定 + 舵机回差（当前重复性 ≤1.1mm、横向仍有约 1.4cm 系统偏差未解）。

## 3 选型留痕：为什么最后是 DaBai DCW

当初在「二手 Astra Pro / 幻尔 Aurora930 Pro / 不买」之间比较，核心判据是**工作距离**而不是型号：

| 参数 | 幻尔 Aurora930 Pro | 二手 Astra Pro | **DaBai DCW（现用）** |
|---|---|---|---|
| 工作距离 | 15~300cm | 60~800cm | 实测 0.299~2.258m |
| 0.3m 处 | 正常出深度 | **盲区，深度图全黑** | 正常，噪声 1.49~3.42mm |
| 0.3~0.6m 抓取区 | 可用 | 不可用（盲区） | **可用，mm 级** |
| 接口/系统 | USB2.0 / Linux arm64 | USB2.0 / Ubuntu arm64 为主 | USB2.0 / openEuler aarch64 已跑通 |
| 结论 | 参数最匹配但需询价 | 只能车顶 0.8m 外粗定位 | **已到手并完成全功能测试，作为主视觉** |

> 一句话：**同一句「这台能 3D 抓取」，取决于相机装多远。** 幻尔是「贴着物体看」，Astra Pro 是「隔着桌子看」，DaBai DCW 覆盖了近距这一段。

## 5 抓取「水杯/纸巾/鸡蛋」缺的是什么

拆三层看，每层卡的东西不同：

### 第 1 层：认出它是什么 → 换检测引擎（¥0）

旧版 `detector.py`（已移除）是 HSV 颜色 + 形状分类，只认红/绿/蓝/黄的圆/方/三角积木；水杯/纸巾/鸡蛋全部失识别——不是相机不行，是方法不行。现已换 `kunpeng/vision/stage1_yolov8.py`（YOLOv8n，COCO 预训练自带 cup/bottle/apple）。

| 目标物 | COCO 预训练直接有？ | 要做什么 |
|---|---|---|
| 水杯（马克杯/纸杯） | ✅ `cup` 类 | 直接用 |
| 瓶子/罐头 | ✅ `bottle` 类 | 直接用 |
| 苹果/橘子/香蕉 | ✅ `apple`/`orange`/`banana` | 直接用 |
| 盆栽（绿植） | ✅ `potted plant` | 直接用 |
| 纸巾 / 纸巾盒 | ❌ 没有该类 | 需自己标注 30~50 张微调 |
| 鸡蛋 | ❌ 没有该类 | 需标注微调（白色小目标，难度偏高） |

> 想要抓大部分物体的真实成本：**不是买相机，是花半天标数据 + 训一次模型**（笔记本就能训，免费）。

### 第 2 层：知道它在哪 → 真深度已到位

- **真深度（已具备）**：DaBai DCW 在 0.3~0.6m 给出 mm 级深度；中央 20% 有效像素 99%，标定/目标必须放画面中央。
- **必须知道的限制**：深度是量化输出，台阶 ≈ `1.1e-5 · z²`（0.3m 约 1mm、1m 约 11mm、2m 约 44mm）；黑色/高反光物体无回波；640×480 下无 D2C 对齐、不报内参，**固定 640×360@30**。
- **伪 3D（仍可用）**：假设目标落在已知高度的水平承载面上，用检测框底边反推距离，误差 1~3cm；作为深度缺失时的兜底。

### 第 3 层：抓得住不捏碎 → 夹爪才是瓶颈

- 大白话：现在的 PWM 舵机夹爪只知道「合到第几度」，**不知道夹了多大劲**。就像蒙着眼用两根手指夹鸡蛋——角度到了就停，蛋早就碎了。
- 规范：舵机是**开环位置控制**，无电流/力矩反馈，无法实现力控。抓脆性物体需要阻抗控制/力闭环，或退一步用**被动柔顺**。
- 工程解法（已落地一半）：
  1. 夹爪内侧贴 **2~3mm 硅胶/海绵垫**（分散压强）；
  2. **降速闭合**（PWM 分段逼近，最后 20% 用 50ms 小步）；
  3. **限位角**：按目标尺寸预设「合到还剩 5mm 就停」，靠摩擦提起；
  4. 纸巾这类**别夹，改用「铲/拖」**；
  5. **电流检测（低成本力上限）**：ACS712 5A 已接 PA6、零点 2462mV、跨 PWM 周期采样噪声极差 21mA；3.8cm 瓶实测 1400→−10mA / 1550→+151mA（台阶 ≈160mA，信噪比 ≈7.7）。**判停闭环逻辑尚未写成代码**，当前只做「接触即停 + 限流保护」，不是恒力/力控。

## 6 宣传页的 3 处水分（面试被追问时用）

1. **「毫秒级实时推理」**：YOLOv8n 在树莓派 5 上实测约 **10~20fps（50~100ms/帧）**。「毫秒级」字面没错（不是秒级），但别理解成 1ms；且多半是 640×400 输入 + 跳帧。
2. **「毫米级精度的动态手势交互」**：指的是**手指关键点在图像里的像素位置**精度，不是三维空间定位精度。说成「像素级」更诚实。
3. **「三维空间任意物品抓取」**：实际是「**已训练的几类物体 + 承载面高度已知**」。真「任意物体 + 任意高度」要通用抓取算法（6-DoF grasp detection，如 GraspNet），是另一个量级的工程。

## 7 17 格功能对照（ROS 8 项 + AI 大模型 9 项）

### 7.1 三个硬约束（决定可行性）

1. **openEuler 有官方 ROS2 源**：22.03 EPOL 仓库有 `ros-humble-*` 全套 rpm，`dnf install` 即可，不用源码编译。常用包：`ros-humble-ros-base`、`navigation2`、`slam-toolbox`、`cartographer`、`rviz2`、`v4l2-camera`、`octomap-*`。⚠️ SP 版本不同源路径会变，先 `cat /etc/os-release`。
2. **鲲鹏 920 无 GPU、NPU 不可用**：纯 4 核 CPU。实测参照（同类 4 核 ARM，无加速单元跑 YOLOv8n 640×640）：树莓派 4B FP32 约 2FPS、INT8 约 4.7FPS；鲲鹏估 10~15FPS（本项目实际用 320 输入 + 降帧）。策略：传统 CV 为主 / 轻量模型降帧 / 重模型上云端。
3. **硬件缺口已收敛**：深度相机 ✅ 已到位；激光雷达 ❌ 主动不做；第二颗 RGB 摄像头 ❌ 不买。

## 11 干脆买一台幻尔 LanderPi？（2026-11-03 评估，结论仍成立）

商品页实况：LanderPi（树莓派 5 机械臂 · 深度视觉 · SLAM 导航 · AI 大模型 ROS2 小车），标价 ¥2199；分轮式/阿克曼/履带 × 入门/标准/豪华；主控档位「树莓派 5（无主板无 SD 卡）/ 2G / 4G / 8G / 16G」。

### 11.1 三个坑（下单前必须看清）

1. **¥2199 是「不含主控」的配置**。页面选中的是「树莓派 5（无主板无 SD 卡）」，树莓派 5（8G）另需约 ¥700 → **实际到手 ¥2900+**。这是低价锚点引流，不是成交价。
2. **换主控：物理可行、软件要移植**。幻尔扩展板是树莓派 40-pin HAT 形态；KunPeng Pro 自带标准 40-pin 扩展口（2×20，引脚布局兼容：1/2=3.3V/5V、SDA/SCL@3/5、UART0@8/10、SPI MOSI/MISO@19/21、PWM@32、27/28=I2C6），且有官方 wiringOP。但扩展板驱动与 ROS2 包是面向树莓派 OS 写的，openEuler 上需自行移植（wiringOP 接管 GPIO/PWM + 重配设备树），**不是插上即用**。
3. **相机配置分三档，宣传图 ≠ 买到的那台**：入门版 = 单目 RGB（无深度）；标准/高级版 = 1 颗 Aurora930 Pro 3D 深度相机（RGB-D 一体），官方装在机械臂末端（eye-in-hand）。宣传图里的「3D 抓取 / 点云」是标准/高级版能力，**下单前必须点「参数」核对档位**。

### 11.2 这个价划算吗（单纯算硬件）

树莓派 5 8G ≈¥700 + 2D 雷达 ≈¥300~400 + 深度相机 ≈¥300~950 + 6 轴总线舵机臂 ≈¥500~800 + 铝合金底盘/电机/轮 ≈¥300~500 + 电池 ≈¥150 → **自攒约 ¥2250~3500**。配置齐全时 ¥2900 属正常套件溢价，不算坑。

### 11.3 但对简历的价值：它是竞品，不是捷径

- **最大风险不是钱，是会动摇范围**。这套自带激光雷达 + 深度相机 + 三维建图，正是主动放弃的 B/C 档能力，买了大概率去跑 SLAM，A 档链路搁浅。
- **面试一问就露**：「这个 SLAM 是你写的吗？」——基于 nav2/cartographer/slam_toolbox 的集成，幻尔和你都一样，但套件党的代码不是自己搭的，讲不出误差预算与选参理由。自研路线能讲：自研 F407/ESP32 核心板 → 自研 PWM/总线舵机驱动 → DaBai DCW + 眼在手标定 → 鲲鹏云边端 IoT 栈 → 精度链误差分解。
- **想要 ROS2 经验，不必买它**：KunPeng 上装 ROS2 Humble + 跑 turtlebot3 仿真/真机，零成本获得同样技能项。

### 11.4 结论

## 12 诚实边界（必须写进方案的话）

1. **功能全部基于开源框架**（OpenCV / YOLOv8 / nav2 / slam_toolbox / RTAB-Map）。幻尔也是。区别是集成能力，不是算法原创——硬说「自研 SLAM」一问就崩。
2. **鲲鹏无 GPU/NPU**，深度学习只能「轻量 CPU 模型 + 云端重模型」，这是硬约束不是选择。
3. **深度相机的限制要照实说**：量化台阶 ∝ z²、2m 处 ±22mm、640×480 无 D2C 对齐、黑色/高反光无回波，抓取必须控制在 0.3~0.6m 且目标放中央。
4. **精度别吹**：重复性 ≤1.1mm 是「同姿态组内」，横向仍有约 1.4cm 系统偏差未解；不要说成「毫米级绝对精度」。
5. **工作量诚实估计**：剩余软件链（深度进抓取 + 总线舵机接入 + 语音 ASR）约 1~2 个月业余时间。
