# 手柄遥控：麦轮底盘 + 六轴总线舵机臂（v3.1 · 2.4G 远程 + Waveshare 转接板）

**一句话**：能用。手柄（2.4G 接收器或有线）在鲲鹏上就是标准 `/dev/input/jsN`，一条串口发
`$CAR,VEL` 驱动底盘，另一条串口经 **Waveshare Bus Servo Adapter (A)** 发幻尔 `55 55` 帧驱动六轴，
**STM32 固件一行不用改**。

代码：`gp_teleop.py`（单文件，标准库 + pyserial，不依赖 pygame / evdev）。

本机已验证（不接硬件）：语法编译、底盘帧校验和与固件文档逐字节一致、舵机帧、**读位置回包解析
（含回声/坏校验负例）**、扳机三种零点形态归一、配置冲突检查、满输入 12 s 不越限、
**输入整形参数化（底盘摇杆 / 扳机 / 机械臂各自独立死区与指数）**、**部分读回冻结未回轴**、
**越界目标慢速回收**、回 HOME 收敛、模式切换/急停/回 HOME/掉线 全流程模拟。
**未实机**：gp_teleop.py 在鲲鹏上的**整机链路**（六颗串联 + 真实回包 + 真实回声）还没跑过；
舵机 + 微雪板本身已在 PC 测试台实测通过（见第 8 节第 2 条）。

## 2. 键位表（两个模式，M1 背键或 BACK 切换）

### 2.1 驾驶模式（DRIVE，默认；底盘动、臂静止）

| 输入 | 功能 |
|---|---|
| 左摇杆 Y / X | 前进后退 / 左右横移（麦轮全向） |
| 右摇杆 X | 原地自转（左推逆时针） |
| **LT（模拟扳机）** | **油门 + 使能**：松开 = 0 速，压得越深越快（0 → 0.30 m/s） |
| RT（模拟扳机） | 精细档：压得越深越慢（1.0 → 0.5 连续） |

### 2.2 机械臂模式（ARM；底盘自动刹停并锁死）

| 输入 | 关节 | 实际动作（位置值变化 + 2026-11-26 标定语义） |
|---|---|---|
| 左摇杆 X | J1 底座 | 右推 = 位置减小 = 俯视顺时针；左推 = 逆时针（零位 460 = 正前方；与驾驶模式「右推右转」一致） |
| 左摇杆 Y | J2 大臂 | 推上 = 位置减小 = 大臂后仰；推下 = 位置增大 = 前仰（零位 514 = 竖直） |
| 右摇杆 Y | J3 肘 | 推上 = 位置增大 = 小臂相对大臂后折；推下 = 位置减小 = 前伸（零位 516 = 大臂小臂成直线） |
| 右摇杆 X | J4 腕 | 右推 = 位置增大 = 夹爪前仰；左推 = 后仰（零位 502 = 与臂成直线） |
| 十字键 ←/→ | J5 腕滚 | 右 = 位置减小 = 从腕看逆时针；左 = 顺时针（零位 494 = 夹爪朝前） |
| LB / RB | J6 夹爪 | LB = 张开（→300）；RB = 闭合（→674） |
| LT / RT | 臂速 | LT 加速（1→2 倍）/ RT 减速（→0.5 倍） |

> 方向语义按 `kunpeng/robot/arm_params.json`（2026-11-26 装机标定）写，**不是猜的**。
> 若实机发现某个轴与上表相反，改 `ARM_MAP` 里那一行的 `gain` 符号即可（+1 ↔ −1），不要拆舵机。

> 十字键是**通断量**（0 / ±1），不是比例轴：J5 的增益已降到 0.75，按住才走、松手即停；
> 想更快就同时压 LT（×1→2）。这也是网上臂控用十字键管腕转的通行做法（Baby-Robot-Arm 同款思路）。

### 2.3 两个模式通用

| 输入 | 功能 |
|---|---|
| **M1 背键 / BACK** | 切换模式（切换瞬间底盘立即刹停；切回驾驶后 0.3 s 内不接受油门，防带杆窜车） |
| A | 急停（锁存）：底盘 STOP + 六轴暂停；再按解除（要求先松开 LT） |
| B | 一键回 HOME：六轴约 3~4 s 慢速回零位（J6 会一并闭合到 674），任何摇杆动作立即中止 |
| START | 打印状态：里程计 + 六轴目标/限位/读回 |

未绑定（预留）：X、Y、M2、十字键 ↑/↓。

## 3. 双模式还是单模式？—— 结论：双模式

你问的这个问题，答案由硬件决定，不是口味问题：**一副手柄只有 4 根模拟轴（左 X/Y、右 X/Y）+ 2 个扳机，
而底盘要 3 个连续量、机械臂要 6 个连续量。**

- 单模式意味着底盘和臂共用同一批摇杆，必须二选一；把臂的关节挪到数字键上，就是「一点一点挪」，
  没有比例速度、没有微调，接一杯水都费劲。v1 就是这么写的，被我自己的复查否掉了。
- 网上没有一款六轴方案是「所有关节都上数字键」的：[PiPER 官方手柄](https://github.com/kehuanjack/Gamepad_PiPER)
  左摇杆管 J1/J2、右摇杆管 J3+腕转；[Baby-Robot-Arm](https://github.com/qnx/Baby-Robot-Arm-with-Gamepad-Control)
  左摇杆 base/shoulder、右摇杆 elbow/tilt、十字键腕转；[PS5 六轴 demo](https://www.aomway.com/post/1453.html)
  摇杆管 4 个关节、L1/R1 管底座。[ROS `teleop_twist_joy`](https://collaborativeroboticslab.github.io/wiki/gamepad-ros-teleoperation/)
  这个移动机器人事实标准干脆只管底盘（左摇杆线速度、右摇杆角速度、LB 使能）。
- 「同一个摇杆按模式复用」是工业通行做法：[RoboMaster 遥控器](https://rm-static.djicdn.com/tem/17348/RoboMaster%20AI%E6%9C%BA%E5%99%A8%E4%BA%BA%202020%E6%A0%87%E5%87%86%E7%89%88%20%E7%94%A8%E6%88%B7%E6%89%8B%E5%86%8Cv2.pdf)
  的 S1 拨杆就是切「底盘跟随/云台跟随」。所以切模式不是妥协，是标准解。
- 切换成本已经压到最低：M1 在握持时无名指可及，按一下即切且底盘同时刹停；M1 若不被上报还有 BACK。

**刻意没抄的**：PiPER 的「位姿模式」（要逆解，当前固件没有可靠 IK，旧 IK 已删，做了就是假功能）、
用扳机控夹爪（两个扳机已被油门/精调占用，且夹爪要双向）、三档 turbo（没必要多一层状态）。

## 4. 2.4G 远程（你要的连接方式）

1. **必须有那颗 USB 接收器（dongle）**。启明星2 的 2.4G 是「接收器另购」，机身本身不带 2.4G 主机。
   没有 dongle 就只能 Type-C 有线或蓝牙；蓝牙在 openEuler 上要配 BlueZ，最折腾，不推荐。
2. 配对：手柄关机 → 把 dongle 插鲲鹏 USB → 按手柄的 2.4G 组合键（一般为 `HOME+X` 长按，指示灯快闪后常亮即配对成功）。
3. 识别：dongle 会被 `xpad` 当成 XInput 手柄，出现 `/dev/input/jsN`。**编号会随插拔/有线无线切换变化**，
   所以脚本默认**自动挑**：先按设备名认（Xbox / GameSir / XInput / Controller），认不出才取编号最小的 js。
   也可显式指定 `--js /dev/input/js3`。
4. 距离：2.4G 私有协议一般 8~10 m 视线内；**鲲鹏的 ESP32 热点也是 2.4GHz**，同频会互相让路。
   掉包先拉开距离/换信道；**如果你是经这个热点 SSH 登录鲲鹏，千万别直接关热点**（会把自己的 SSH 一起断掉），
   改从本地键鼠/串口启动，或临时用有线网络。
5. **掉线保护**（远程最关键）：手柄关机/接收器被拔 → 内核注销输入设备 → js 节点消失 →
   脚本 `pad.gone` 立刻发 `$CAR,STOP` + 六轴 `MOVE_STOP` 并退出。**这一条必须实测验收**（第 9 节第 6 条）：
   关手柄电源，1 s 内必须打印「手柄设备消失」并停车。若你的 dongle 掉线后节点不消失（个别固件会这样），
   回来告诉我，我再加一条「无事件超时」兜底——默认不加，因为匀速直行本来就不产生事件，加了会误停。
6. 底盘固件还有第二道：500 ms 收不到 `$CAR,VEL` 自动刹停。但脚本只要活着就会持续喂狗，
   所以**第一道（节点消失检测）才是真正的远程失控保护**。

## 5. 接线（三条线，物理位置说清楚）

| # | 从 | 到 | 线 | 注意 |
|---|---|---|---|---|
| ① 手柄 | 2.4G dongle（或手柄 Type-C 口） | **鲲鹏 USB3.0 口** | dongle 直插 / 手柄自带 Type-C 线 | teleop 时不用相机，可拔相机腾口；别和舵机大电流共一个无源 hub |
| ② 底盘 | CH341 模块 TXD / RXD / GND | STM32 **PA10(RX1) / PA9(TX1) / GND** | 3 根杜邦线 | 🔴 CH341 的 **5V 与 3.3V 针都不接**（VBUS 倒灌会关掉 host 口）；有 3.3V 跳线就拨 3.3V；GND 必须共地 |
| ③ 机械臂 | 转接板 **USB Type-C** | 鲲鹏另一个 USB 口 | Type-C 数据线（能传数据的，不是纯充电线） | 见下面 5.1，四件事必须对上 |

### 5.1 Waveshare Bus Servo Adapter (A) 专章（你手上这块）

这是微雪 SKU 25514，官方定位是 ST/SC 系列（ST3215 等）总线舵机的驱动板，**9~12.6V 输入、DC5521 +
绿色接线端子双供电、UART 与 USB 二选一（跳线切换）**。它本身不做协议翻译，只是「USB/串口 ↔ 单线总线」
的电平桥 + 舵机供电通路，所以上位机发什么帧，舵机上就收到什么帧 —— 幻尔的 `55 55` 帧可以直接用。
**这条「微雪板 × 幻尔舵机」链路已在 PC 测试台实测通过**：`../../工具/servo_acceptance/验收记录.csv`
里 J1~J6 六颗都是经微雪板逐颗跑完全套验货（到点误差 2~9、背隙 0.9~3.3，J5 替换件 HTS-20H
背隙 13.6/15.3 单位超门槛 8 判 FAIL，但已装车用固件单侧逼近补偿兜底，见第 7 节表后注）。
因此协议与板子都不需要再怀疑；但**整机第一次上电仍先单颗 J1**——鲲鹏 USB 口、跳线 B、DVG 转接线
都是这条链路上还没验证过的新环节，逐步放量是工程常识，不是不信任协议。

| 项 | 怎么设 | 说明 |
|---|---|---|
| 跳线 | **B 位（USB–SERVO）** | A 位是 UART。工程 docx《移动操作机器人-硬件引脚使用总表》表 10 写的「A 位 + USART6 同名相接」是**另一条 STM32 路径**——现已启用，但串口是 **USART3（PB10/PB11）不是 USART6**；接鲲鹏要走 B 位，别照那张表拨 A 位 |
| 供电 | **11.2V 母线 → 绿色接线端子**（DC5521 备用） | 与 J1/J2/J3~J6 的 9~12.6V 同域，正好匹配现有电压树；母线 470µF 低 ESR 电容照旧并在端子上 |
| 电流 | 峰值 3A+3A+4×2A ≈ **14A** | DC5521 座子接触面小、易发热，**优先走绿色端子**；20A 降压那一路要能扛住，先单颗试再加 |
| 线序 | 板子丝印 **D V G** = Data / VCC / GND；幻尔舵机是 **GND / VIN / SIG**（官方手册针序，**顺序相反**） | **绝对不能直插**：做 3P 转接线逐针对——SIG↔D、VIN↔V、GND↔G，接反 VIN/GND 秒烧 |
| 插头 | 微雪板 DVG 口是 **5264-3P（2.54mm）**；幻尔这批是 **PH2.0-3P（2.0mm）** | **实测插不进**，必须 PH2.0↔5264 转接线或退针转接（只接 D/V/G 三根），别硬掰 |
| 波特率 | 115200 8N1 | 板子要求「与舵机一致」；幻尔出厂 115200。若舵机被改过，改 `ARM_BAUD` |
| 串口名 | `/dev/ttyUSB0` 或 `/dev/ttyACM0` | 板载 USB 转串口芯片，插上后用 `--list` 看，**不需要再外挂 CH340** |

> 这条同时也把工程文档里「驱动板是 USB 转总线还是 TTL 收发器」的悬念关掉了：**是 USB 转总线（B 位）**，
> 顺带还能当 UART 电平桥（A 位），现已给 STM32 USART3（PB10/PB11）作机械臂总线舵机驱动用。

上电顺序：**降压调到 11.2V → STM32 → 舵机转接板（跳线 B，本模块鲲鹏直连路径；STM32 控制路径拨 A 位）→ 鲲鹏 → 手柄**。

> ⚠️ 底盘 CH341 和舵机板都是 USB 转串口，`/dev/serial/by-id` 的名字不一定一眼分得清（同芯片时甚至可能撞名）。
> **拔一个插一个**、用 `--list` 核对实际路径，必要时显式给 `--car-port /dev/ttyUSB0 --arm-port /dev/ttyUSB1`。

## 6. 上线七步

**第 0 步 · 上传**（本机 PowerShell，工程根目录用相对路径）

```powershell
Set-Location "D:\简历\STM32项目\4.ESP32-S3项目\RoboticArm_Kunpeng"
ssh root@192.168.77.100 "mkdir -p ~/kunpeng_vision"      # 目录不存在时 scp 会直接失败
scp "kunpeng\gamepad\gp_teleop.py" root@192.168.77.100:~/kunpeng_vision/
```

> 板 IP 以 `hostname -I` 为准（现行口径：ESP32 热点 `192.168.77.1` + 鲲鹏静态 `192.168.77.100`；旧网段 `192.168.4.100`）。

**第 1 步 · 离线自检**（不接任何硬件）

```bash
ssh root@192.168.77.100
cd ~/kunpeng_vision
python3 gp_teleop.py --selftest
```

应打印 `[配置] 通过` / 两条底盘帧 `OK` / 舵机帧 `OK` / 回包解析 `OK` / `[限位] … 无` /
`[HOME] 从最远端回位 … OK` / `自检通过`。最后一项是回零收敛检查（从最远端起回，约 3~4 s、拍数有限）。

**第 2 步 · 认设备**

```bash
python3 gp_teleop.py --list
```

会连设备名一起列出来（`Xbox Wireless Controller` 之类），并列出 `/dev/serial/by-id` 与 `ttyUSB*/ttyACM*`。

**第 3 步 · 认键（30 秒，不用改代码）**

```bash
python3 gp_teleop.py --probe          # 不带 --js 就是自动挑
```

推摇杆、按背键、按十字键，屏幕会报**原始编号**：

- 背键若报 `键 10 / 11` → 默认就对了；若是别的编号 → `--btn m1:8,m2:9` 覆盖，或直接用 BACK 切模式。
- 十字键若报 `轴 6 / 7` → 默认就对了；若报成按键 → 见第 8 节第 4 条改绑 J5。
- 扳机：脚本自己认零点（松手 ≈ −32767 / ≈0 / 反相高位），**不用你告诉它**；只要求启动时别碰扳机（要采零点）。

**第 4 步 · 空跑摘要（不碰串口）**

```bash
python3 gp_teleop.py --dry-run      # 只打印 5 Hz 的 VEL 摘要，不打开任何串口
```

`--dry-run` 只打印摘要，**不会打印舵机帧、也不会读回**；帧是否合法看第 1 步 `--selftest`。
按 M1 应看到 `[模式] 机械臂（底盘锁定）` 且 VEL 全 0；按 BACK 切回；按 A 出现急停提示。

**第 5 步 · 只开底盘**

```bash
sudo pkill -f web_control.py     # 5000 的 Flask 占着 CH341，必须先停
python3 gp_teleop.py
```

判据：压 LT + 推上 = 前进；右摇杆右 = 顺时针；**松 LT 后 0.5 s 内停住**。

**第 6 步 · 接臂（先单颗、先单轴）**

```bash
python3 gp_teleop.py --arm-port /dev/ttyUSB0      # 端口名以第 2 步 --list 的实际结果为准
```

先只接 **J1** 一颗舵机试链路：应打印 `[臂] 读回成功 1/6，起点已对齐实测位置`。
若只回了一部分，会打印 `[臂] 未读回：Jx … → 本次禁用这些轴`，其余轴照常，不会硬拽。
读回全失败 → 查跳线是否在 B、波特率、线序、ID；这时**不要加 `--arm-home` 硬跑**。
链路通了再逐颗接上，每次只动一个关节、只动一点点；方向不对改 `ARM_MAP` 里该行的 `gain` 符号（+1 ↔ −1），不要改 `dir`（`dir` 是标定方向，改了会和 arm_params 语义打架）。

**第 7 步 · 标定收紧**：home/dir 已按 arm_params.json 回填；按第 7 节把 `lo/hi` 收紧到结构极限前 40 单位，再放开跑。

## 7. 标定表（home/dir 已按 arm_params.json 回填；lo/hi 仅 J6 实测，其余待收紧）

单位：0~1000 ↔ 0~240°，1 单位 = 0.24°；`lo/hi` 是安全软限位（结构极限前留 ≥40 单位余量）。

## 8. 安全机制与已知边界

**已实现**

- 切模式即刹停底盘，切回驾驶后 0.3 s 内油门无效；臂模式下每拍继续发 0 速度，底盘被真正锁死。
- 松开 LT 立即发 0 速度（DRIVE），不是「保持上次速度」；臂模式松开 LT 即回 1.0 倍速。
- 底盘固件 500 ms 收不到 VEL 自动刹停（脚本被杀/掉线的兜底）。
- 退出（Ctrl-C / 异常 / SIGTERM）先发 `$CAR,STOP` + 六颗 `MOVE_STOP` 再关串口。
- 手柄掉线（节点消失 / 读失败）立即停车退出；急停锁存，解除要求先松 LT；急停自动取消回 HOME。
- 关节目标只在 `[lo,hi]` 内按 `spd` 逐拍推进（永不跳变）；启动**先读回位置再允许发帧**，
  默认读回失败的轴**本次运行完全不发帧**（绝不按默认 HOME 硬拽）；部分读回就只控读回的那几轴。
  唯一例外：全部读回失败且显式给了 `--arm-home`（等于人工确认「臂确实在 HOME」）才按 HOME 起点发帧。
  实测位置落在软限位之外时，按 `spd` **慢速收回限位**，不会一步跳进去；读数 >1000（越程段）则直接禁用该轴。
- 舵机 `MOVE_STOP`(12) 之后新 `MOVE` 会被忽略，所以启动和解除急停都先发 `MOVE_START`(11)。
- 同一个键 250 ms 防连击（防背键宏连发把模式来回切）；切模式时显式补一条 `$CAR,STOP`。

**已知边界（别当已验收）**

1. **整机链路没上电跑过**：舵机 + 微雪板在 PC 测试台已实测通（`../../工具/servo_acceptance/验收记录.csv`），
   但 gp_teleop.py 在鲲鹏上（六颗串联、真实回包、真实回声）还没跑过。回包格式与验收工具一致
   （LEN=5、CMD=0x1C、位置在第 6/7 字节），gp 的解析器用同一格式 + 合成帧验过
   （含「转接板回声」「坏校验」两个负例），且同时兼容「有回声 / 无回声」两种板子。
2. **跨品牌组合已实测通**：无需再担心「微雪只保证 ST/SC」。若整机单颗都读不回，按第 6 节查
   跳线 B、波特率、DVG 转接线序，最后再考虑给转接板 TTL 侧加示波器/逻辑分析仪看波形。
3. **背键 M1/M2 编号未确认**：M1=10、M2=11 是 XInput 常见值，不对就 `--btn` 覆盖或改用 BACK。
   若背键被设成「宏键」，按一下会连发一串事件，最好在官方 App 里设成普通按键或无功能。
4. **十字键形态**：Linux 上一般是轴 6/7（脚本默认）。若 `--probe` 显示它报的是按键，
   把 `ARM_MAP["J5"]` 改成 `[("bt", "X", -0.75), ("bt", "Y", +0.75)]`（与轴版同增益），X/Y 就从「预留」变成「腕滚」。
5. **USB 口不够**：手柄 dongle 一个、底盘 CH341 一个、舵机板一个，正好三个；鲲鹏只有 4 个 USB，
   相机要拔。长期用**带独立供电**的 hub，别和舵机大电流共用一路。
6. **独占串口**：`web_control.py`（Flask 网页）会占着底盘 CH341，跑之前先停（`pkill` 或 `POST /api/close`）；
   `voice_gateway.py` 走 TCP，不占串口。
7. **没做**：笛卡尔/位姿模式（要 IK）、录制示教回放、YOLO/语音联动、无事件超时兜底（理由见第 4 节第 5 条）。
8. **B 回 HOME 是六轴同时回**，没有碰撞规避：姿态很怪（比如夹爪缠在臂内侧）时先手动摆到安全区再按 B，
   或直接用 A 急停中止。真要做「分段回零」得先有各关节的几何模型，现阶段不做假功能。

## 9. 验收判据（够不够「能用」看这七条）

1. `--selftest` 全绿（含回包解析三项与 `[HOME]` 收敛）。
2. 压 LT + 推上 = 前进；松 LT 后 0.5 s 内停；不窜车。
3. 右摇杆右 = 顺时针自转；左摇杆横推 = 横移（麦轮）。
4. 按 M1 进臂模式，底盘立刻停、推摇杆不动车；再按回驾驶，底盘恢复。
5. 六个关节方向与键位表一致，走到限位前停住、不顶结构；**轻推摇杆能一格一格挪**（不是一推就冲到底）；
   B 键能慢速回零位。
6. **关手柄电源（模拟 2.4G 失联）**：1 s 内打印「手柄设备消失」并停车；Ctrl-C：立刻停、串口释放、能马上再跑一次。
7. 单颗舵机读回值 = 你用手推到的那个位置（±10 单位），证明回包解析在真板子上成立。
