# esp32/ —— ESP32-S3 端（语音入口，P2 阶段）

> 当前状态：**占位目录**。ESP32-S3 核心板与扩展板已到货/已下单，尚未焊接调试。
> 语音属于本项目 **P2 优先级**，等 STM32 + 鲲鹏链路跑通后再进。

---

## 一、这块板在系统里的位置

```
[你说话] → ESP32-S3（唤醒 + 语音转文字）→ 鲲鹏（理解意图 + 算目标点）
         → 串口发 $JOINT → STM32（驱动 6 路舵机抓取）
```

ESP32-S3 只做**最前端的一件事：把人说的话变成一句文本指令**，然后通过 Wi-Fi/串口交给鲲鹏。
它不参与运动学解算，也不直接驱动舵机——这样分工的原因是 ESP32 算力有限（双核 240MHz、无 FPU 大算力），
但它的 Wi-Fi/BLE 和麦克风接口最方便。

## 二、硬件清单（已定）

| 部件 | 型号 | 接到哪 | 用途 |
|---|---|---|---|
| 主控 | ESP32-S3-WROOM-1 **N16R8**（16MB Flash / 8MB PSRAM） | — | 语音 + 联网 |
| 核心板 | 自画 35.56×63mm（参照官方 DevKitC-1） | — | H1/H2 排针按 J1/J3 顺序 1×22 |
| USB 转串口 | **CH343G** + 双 Type-C | — | 一键下载 + 串口调试 |
| 麦克风 | **INMP441**（I2S 数字麦） | I2S0 | 采集语音（数字接口，抗干扰比模拟麦强） |
| 功放 | **MAX98357A**（I2S 功放） | I2S1 | 播放提示音/回复 |
| 显示屏 | **ST7789**（SPI） | SPI | 显示识别结果、状态 |
| 存储 | **microSD**（SDIO/SPI） | — | 存唤醒词模型、音频 |
| 灯效 | **WS2812** | RMT | 状态指示 |
| 总线 | **CAN**（需外接收发器如 TJA1050） | TWAI | 预留，将来接底盘电机 |

## 三、软件路线（待实施）

| 步骤 | 做什么 | 关键点 |
|---|---|---|
| 1 | 烧官方 `esp-idf`，跑通串口打印 + Wi-Fi 连接 | 先确认 CH343G 下载电路正常 |
| 2 | INMP441 采音，I2S 读原始 PCM，串口打印波形 | 先验证麦克风有数据，再谈识别 |
| 3 | 接 **ESP-SR / WakeNet** 离线唤醒词（如"小智小智"） | 唤醒词模型放 Flash/PSRAM |
| 4 | 唤醒后录音 → 送在线 ASR（或本地离线命令词） | 在线需 Wi-Fi + API Key |
| 5 | 识别文本 → 按协议封成 `$CMD*CK\r\n` → 发鲲鹏/STM32 | 直接复用项目已有 XOR 协议 |
| 6 | MAX98357A 回 TTS 提示音 | "好的，去抓水杯" |

## 四、和现有代码的对接点

- 语音识别出的文本 → 套用项目统一协议帧：`$<CMD>[,ARGS]*<CK>\r\n`（XOR 校验，2 位大写 HEX）。
- 校验算法直接照抄 `Core/Src/uart_protocol.c` 的 `xor_checksum`，或 Python 的 `arm_host.py`。
- 通信方式二选一：
  - **串口**：ESP32-S3 UART ↔ 鲲鹏 USB-TTL（和现在 STM32↔鲲鹏 同一条思路，最简）；
  - **Wi-Fi TCP**：ESP32 建 TCP 客户端连鲲鹏，鲲鹏转发给 STM32（省一根线，但多一层）。

## 五、为什么这个目录现在是空的

因为**先做能做的**：STM32 固件已经跑通、鲲鹏识别已经跑通、网页遥控已经能控舵机，
这三块不依赖 ESP32 就能演示完整闭环（用手点网页代替说话）。
等这条链路稳定，再把"手点"换成"嘴说"，风险最低——语音识别本身（尤其离线唤醒 + 中文 ASR）
是独立的坑，混在一起调会分不清是识别错了还是机械臂错了。

> 什么时候往这个目录放代码：官方 ESP-IDF 工程建立后，把 `main/` 下的 `voice.c`、`i2s_mic.c`、
> `protocol.c` 放进来即可。
