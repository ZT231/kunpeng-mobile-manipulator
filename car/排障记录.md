## 第 1 条 · `cp` 报「target ... is not a directory」，但目录明明存在

- **现象**：把 `1.Smart car` 的源码拷进 4 号项目时，
  `cp "$SRC"/*.c "$DST"/`（`DST` 是含中文的绝对路径 `/d/简历/.../car/`）报
  `target ... is not a directory`；同一条命令里 `stat car` 又明确显示它是目录。
- **排查过程**：先用 `ls -la` + `stat` 确认目标目录真的建出来了、权限正常；
  再试把目标换成**相对路径**（先 `cd` 进工程根，用 `../../1.Smart car` 作源、`car/` 作目标），
  拷成功。⇒ 问题不在目录，在「参数里带中文绝对路径」。
- **根因**：本机是 Git Bash（MSYS），外部命令的参数经过 Windows 路径转换层时，
  含中文的 POSIX 绝对路径会被转换坏；而 `cd` 是 shell 内建命令、不受这层影响。
  这与项目既有记录「Git Bash 中文参数会坏」是同一类坑，这次是 `cp` 而非 `g++ -I`。
- **解决**：所有文件操作改成「先用内建 `cd` 进到工程根（绝对路径 OK），后续一律相对路径」；
  中文只出现在 `cd` 的参数里，不出现在 `cp` / `gcc` 的参数里。
  另外发现 Bash 工具的 cwd **不保证跨调用持久**，所以每条命令都显式 `cd` 一次。
- **一句话面试说辞**：「Windows 下 Git Bash 的外部命令参数遇中文路径会转换失败，
  我改成 shell 内建 `cd` 进目录 + 相对路径操作，并且每条命令都重新 `cd`，不依赖工作目录持久。」

## 第 2 条 · 帧里的 `F` 会被老的单字符协议误当成「前进」

- **现象**（设计阶段推演，🔴 预判非实机）：原 `main.c` 是读一个字符 `switch` 一个字符，
  `F` = 前进、`B` = 后退、`S` = 停。新帧 `$CAR,FWD,800*3D` 里恰好有 `F`、`,`、`8`…
  如果无脑把每个字节都喂给老逻辑，解析一帧的过程中车会被反复启停好几次。
- **排查过程**：逐字节走一遍 `main.c` 的 while 循环，确认 `BT_Read()` 不区分来源，
  两种协议共用一条字节流。
- **根因**：**两套协议复用同一物理通道但没有分用判据**。单字符协议没有任何帧头，
  无法自证「我是独立命令」。
- **解决**：主循环加 `s_in_frame` 标志 —— 见到 `$` 置 1、见到 `\n` 清 0；
  帧模式内的字节只喂 `car_frame.c`，帧模式外的单字节才走 `Legacy_OneChar()`。
  再加 200ms 帧间超时，防止上位机只发半帧导致永远卡在帧模式。老协议一行没删。
- **一句话面试说辞**：「新老两套协议共用一个串口，我用帧头标志位做分用，
  保留老蓝牙 APP 的演示能力不动，这是典型的向后兼容改造。」

## 第 3 条 · `delay_ms(800)` 会让急停喊不住

- **现象**（设计阶段推演，🔴 预判非实机）：A 项验收判据是「发 `$CAR,FWD,800`，车前进 0.8s 停」。
  最直觉的写法是 `Car_Forward(); delay_ms(800); Car_Stop();`。
- **排查过程**：看原 `delay.c` 是 DWT 循环忙等；在这 800ms 里 `BT_Read()` 一次都不会被调到，
  上位机中途发 `$CAR,STOP` 只能干等，自动模式（避障 / 循迹）也会被卡住 800ms。
- **根因**：**阻塞式延时把「定时」和「收命令」耦合在一个执行流里**，
  裸机单线程下没有任何抢占或回调机会（规范说法：缺少非阻塞状态机 / 时间片轮询）。
- **解决**：改成记一个到期时间戳 `s_stop_at_ms = millis() + 800`，主循环每圈比一次，
  到点才 `Car_Stop()`；新命令或 `STOP` 随时能把它清零。
  `mode 切换` 时也清零，防止切模式半路突然停车。
- **一句话面试说辞**：「裸机里我没用 `delay_ms` 做动作时长，改成 `millis()` 时间戳轮询，
  这样急停和新命令随时能打断，避障循迹也不会被卡住。」

## 第 4 条 · 校验和与超长帧：为什么必须自己闸住

- **现象**（设计阶段推演，🔴 预判非实机）：上位机 / LLM 可能发出
  `$CAR,FWD,99999`（跑 100 秒）、`$CAR,SPD,5000`（PWM 越界）、
  或者线上干扰导致校验和不符、甚至一口气灌几百字节。
- **排查过程**：对照机械臂 `uart_protocol.c` 的错误码表（`1` 帧错 / `2` 未知命令 /
  `3` 参数错 / `4` 状态禁止），确认底盘要沿用同一套语义，否则上位机要写两套解析。
- **根因**：**串口是信任边界**。没有量程仲裁，一个错帧就能让车一直跑；
  没有定长缓冲上限，裸机没有 OS 内存保护，越界就是跑飞。
- **解决**：`CAR_FRAME_MAX_LEN=64` 超长立刻 `$ERR,1` 并复位状态机；
  本地仲裁闸门 `时长 ≤ 5000ms` / `PWM ≤ 999` / `MODE ≤ 2`，越界 `$ERR,3` 且**不执行动作**；
  CK 用 `$` 与 `*` 之间逐字节 XOR，对不上 `$ERR,1`。
  14 项 host 单元测试里有 6 项专门验这些拦截。
- **一句话面试说辞**：「我把量程仲裁放在固件侧而不是上位机 —— LLM 只能提议动作，
  本地仲裁器才授权，这样就算云端给了离谱参数，车也不会真跑起来。」
